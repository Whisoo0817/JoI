# E1 구체화: 표현 범위와 행동 의미 비교

2026-09-10. 사용자 질문에 대한 **제안**이며 확정 protocol/실험 결과가 아니다.
현재 전제: 올바르게 확정한 Timeline에서 연구를 시작한다. NL 생성 정확도와 사용자 이해도는 평가하지 않는다.
상위 계획: `confirmed_ir_evaluation_2026-09-10.md`의 E1.

## 평가 질문

확정된 스마트홈 자동화 행동을 지원 시간·상태·제어 연산의 조합으로 얼마나 담을 수 있는가?
기존 표현과 비교할 때 같은 행동을 결정하기 위해 무엇을 명시하고 어떤 실행 의미에 의존하는가?
결정성은 의미론의 논증 대상이며 실험 성공률이나 독점적 신규 성질로 취급하지 않는다.

## E1a: 독립 사례의 지원 범위 — 필수 제안

1. 기존 388개 개발 corpus와 별도로 출처·선정 규칙을 먼저 고정한다. 외부 자동화 사례 30개 정도로 시작하는 규모를 제안하되, 수량·출처는 미확정이다. 성공/실패를 보고 사례를 교체하지 않는다.
2. 원래 요구를 보존한 행동 계약을 Timeline 작성 전에 기술적으로 확정한다. 초기 상태, 평가 시점, 타이머 취소/재시작, 저장값, 반복/재진입, 호출 시각·인자·중복·순서를 기록한다. 모호한 사항에 대한 추가 가정은 따로 표시한다. 해소 불가능한 자료는 데이터 불충분으로 보고한다.
3. 기술적 작성자가 IR를 작성하고 다른 검토자가 요구 보존을 검토한다. 이는 사용자 이해도 연구가 아니다. 범용 외부 스크립트에 핵심 행동을 숨겨 완전 지원으로 계산하지 않는다.
4. 완전 표현/일부 표현/현재 지원 밖을 분리한다. 작성 실패만으로 언어적 불가능을 판정하지 말고 미지원 문법·의미 근거 또는 미해결로 표시한다. 시간·재진입 의미를 바꾸거나 요구를 삭제한 것은 완전 표현이 아니다.
5. IR 문법·의미상 표현 가능, 참조 실행기 구현 지원, Explorer 판정 지원을 별도 열로 남긴다. 검증 거절이나 timeout은 곧 표현 불가능이 아니다.
6. 독립적으로 작성한 경계 입력과 예상 ACTION으로 encoding을 점검한다. 예시 실행 일치만으로 전 입력에서의 의미 보존을 증명했다고 쓰지 않는다. 일반적 대응 근거는 연산 의미와 구성별 검토에 둔다.

포함 범위에는 `Service.Method`당 서로 다른 selector 하나라는 binding 계약을 적용한다.
한 selector의 `all(...)`이 여러 기기에 fan-out하는 것은 완전 지원 후보지만, 동일 service에
서로 다른 selector가 둘 이상 필요한 사례는 현재 binding/lowering 지원 밖으로 기록한다.
이를 Timeline 언어 자체의 표현 불가능성으로 집계하지 않고 frontend/binding boundary로 분리한다.

보고: 전체 분모와 자료 불충분 수, 완전 표현 비율, 행동 구성/조합별 실패 사유, 대표 의미 전개 2개. 의도적으로 균형화한 corpus의 비율을 실제 가정에서의 사용 빈도나 전체 스마트홈 coverage로 해석하지 않는다.
병렬·중첩 스케줄 등 경계 요구도 남긴다. 현 period는 회차 종료 후 대기이므로 정각마다의 cadence와 자동 동일시하지 않는다. cycle count를 조건 만족 횟수 누적 counter로 취급하지 않는다.

## E1b: 같은 행동의 표현 비교 — 권장 소규모 분석

복합 행동 6개 정도를 기술적으로 수작업 encoding하는 pilot을 제안한다. 사례 수는 미확정.
일반명 TAP 대신 특정 논문의 문법·실행 의미·버전을 고정한다. AutoTap 또는 Trace2TAP 중 하나를 우선 후보로 하며, FSM 대안이 핵심이면 timed state-machine 표현 하나를 추가한다. LTL은 property 층과 operational model 층을 분리해서 비교한다.

각 사례의 평가 시각/입력/서비스 호출 관찰 계약을 통일하고 다음을 기록한다.

- 같은 행동의 완전 encoding 여부와 근거.
- 시간 연산에 내장된 정책, 사용자가 추가 작성한 보조 변수/상태/전이, 도구가 자동 생성한 구조를 구별.
- timer reset, snapshot 보존, 재진입, 동시 입력 처리의 의미가 정의되는 위치.
- 고정 초기 상태·입력에 대해 관측 ACTION이 유일한지. 의도적인 비결정성은 잘못된 시스템으로 분류하지 않는다.
- 핵심 요구를 표현하려면 새로운 외부 실행 코드를 도입해야 하는지.

보조 상태 수는 표현 방식 설명 자료다. 언어 간 LOC/AST/상태 수의 단순 비교를 사용성·추론 난도·성능 우위로 해석하지 않는다. 가능한 기존 내장 시간 기능과 라이브러리를 baseline에도 허용한다.
기존 표현이 같은 계약을 자연스럽게 지원하면 그대로 긍정 결과로 보고한다. 이 경우 우위 주장을 줄이고 공통 IR–JoI 검증 기준이라는 역할을 강조한다.

## 결정성의 정확한 위치

고정 프로그램·실행 모델·초기 상태·입력 이력에서 정상 실행의 timed ACTION trace가 유일하다는 성질이다. 도메인 연산의 결정성과 조합/상태 전달/동시 사건/진행 규칙을 함께 논증해야 한다. 각 primitive의 결정성만으로 임의 조합의 결정성이 따라온다고 쓰지 않는다.
TAP/FSM도 실행 의미에 따라 결정적일 수 있고 충분히 제약한 논리 명세도 출력 행동을 유일하게 정할 수 있다. Timeline의 제안 가치는 시간·제어·상태 정책을 정의된 연산 의미로 조합하고 이를 생성 전 행동 기준과 생성 후 timed ACTION 검증 기준으로 공유한다는 점이다.

## 경계 예시

one-shot 연속 부재 5분 후 off: absent@0, present@4m, absent@4.5m.
이후 계속 absent면 예상 off@9.5m; off@5m은 잘못된 sustain encoding.
LTL 측이 타이머 모델과 충분한 조건을 제공하여 같은 결과를 정하면 동일 행동 지원으로 인정한다.
AutoTap에도 지속 조건 timer 모델이 있으므로 sustain 하나를 Timeline 고유 기능으로 쓰지 않는다.

## 후속 사용자 결정 및 실패 유형 후보

사용자는 표현 간 비교를 일단 제외하고, 여러 자동화 사례의 요구 추출과 Timeline의 요구 보존 평가에 집중하기로 했다. 따라서 위 E1b는 보류한다.

병렬 실행 외 조사할 후보: 실행 중 즉시 취소/재시작, 다른 대기 중 발생한 이벤트의 누적·재생, 이동 시간창의 횟수/집계, 독립 반복 일정 및 인스턴스 중첩 정책. 이는 조사 후보이며 전부 표현 불가능하다는 판정이 아니다.
현재 확실한 의미 경계는 단일 제어 흐름, wait 평가 시점에만 edge 관찰, cycle.until의 회차 시작 검사, 회차 종료 후 period 대기다. 구현/문법 경계와 임의 encoding 불가능을 구별한다.

- 병렬: 두 호출을 연이어 내는 fanout과 독립적으로 대기·진행하는 두 흐름을 구별한다.
- 취소: delay 도중 즉시 취소하고 대체 ACTION을 내야 하는 요구를 경계 사례로 삼는다. 단순히 delay 뒤 조건을 검사하면 원요구를 만족하지 않는다. clock/상태/분기 조합으로 정확히 구현되는지는 먼저 점검한다.
- 이벤트 기억: 다른 delay 중 문이 열렸다 닫힌 사실을 나중에 처리하라는 요구. 현재 edge latch는 배경 이벤트 기록기가 아니다.
- 집계: 최근 10분 안에 문이 세 번 열렸는지, 최근 1시간 평균 등을 후보로 한다. 단순 count 부재만으로 불가능 판정하지 말고 필요한 이력/상태를 지원 조합으로 보존할 수 있는지 확인한다. cycle.count는 회차 인덱스이며 조건 만족 누적 횟수가 아니다. GV 서비스 우회는 의미·관측과 환경 의존을 공개하고 검증한다.
- 중첩/스케줄: frontend는 nested loop를 거절하지만 고정 반복은 펼칠 수 있다. 모든 nested 요구를 실패로 계산하지 않는다. 단일 cron의 표현 가능성과 여러 실행 인스턴스의 정책·검증 지원을 구별한다.

논문 설명의 단위: 원래 요구 → 필요한 실행 기능 → 현행 의미/조합으로 가능한지 → 정확히 빠지는 행동. 문법상의 키워드 부재만으로 실패를 선언하지 않는다.
보고 범위 문장 후보: 현재 Timeline은 단일 자동화 실행의 순차·분기·반복 및 명시적 대기와 상태 전달을 대상으로 한다. 독립 실행 흐름의 조정, 일반적인 선점/이벤트 버퍼링/시간창 집계의 지원 범위는 별도로 평가한다. 미지원의 이유를 결정성과 동일시하지 않는다.
