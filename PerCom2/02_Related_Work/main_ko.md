# Related Work and Positioning — 한글 검토본

> 같은 폴더의 [main.md](main.md)와 `overleaf-paper/main.tex`의 해당 절을 번역했다. SenSys의 검증 기준에 따른 논리 순서를 유지하면서 중복 설명을 줄이고, 주요 연구의 비교를 표로 정리했다. 추가 피드백을 반영하고 영문과 LaTeX에 동기화했다.

기존 자동화 검증은 규칙이 명시된 안전·활성 속성을 만족하는지 검사해 왔으며, 코드 생성 평가에서는 테스트 사례나 정답 실행 결과가 기준으로 사용되어 왔다. 자연어 요청으로부터 자동화를 생성할 때에는, 이러한 속성의 만족과 함께 코드가 요청된 구체적인 동작을 구현하는지도 확인해야 한다. 그러나 요청 자체는 바로 실행해 대조할 수 있는 기준이 아니므로, 각 시스템이 요청된 동작을 어떻게 표현하고 무엇을 기준으로 검사하는지가 중요해진다. 이 관점에서 기존 연구를 정리한다. Table 1은 대표 시스템의 검사 대상, 기준, 방법을 비교한다.

**검증 기준이 이미 존재하는 경우.** TAP 규칙을 형식 기법으로 검증하는 연구는 폭넓게 이루어져 왔다. AutoTap~\cite{autotap}은 사용자 지정 LTL 안전 속성을 만족하도록 TAP 규칙을 합성하거나 수정한다. TAPInspector~\cite{tapinspector}는 시간 정보를 고려한 규칙 집합의 안전·활성 속성 위반을 모델 검사하고, TAPFixer~\cite{tapfixer}는 이러한 위반을 수정한다. 관련 분석은 규칙 간 취약점과 보안 취약점을 찾아내며~\cite{iruler,soteria}, HAWatcher~\cite{hawatcher}는 추출한 불변식을 기준으로 배포된 자동화를 모니터링한다. 이들 시스템은 시간적 동작과 규칙 상호작용을 포함한 자동화 동작의 속성을 검사한다.

대상 도메인이 실행 가능한 오라클을 제공하는 코드 생성에서도 기준을 사용할 수 있다. GPIoT~\cite{gpiot}는 자연어 요구사항으로부터 신호 처리 및 ML 알고리즘 코드를 생성하고, 실행 테스트로 생성 코드를 평가한다. IoT 밖에서는 text-to-SQL이 정답 쿼리의 실행 결과를 기준으로 생성 쿼리를 평가한다~\cite{spider}. 이러한 평가에서는 테스트 사례나 정답 결과가 기준을 제공한다.

**LLM이 생성하는 반응형 자동화.** 자연어 요청으로부터 자동화를 생성하는 시스템들은 생성 결과를 확인하기 위해 서로 다른 검사 기준과 절차를 사용한다. AutoIoT~\cite{autoiot_maude}는 Maude 재작성 논리를 사용하여 생성 규칙의 네 가지 규칙 간 충돌 유형을 검사한다. ChatIoT~\cite{chatiot}는 자연어를 Home Assistant 자동화로 변환하고, LLM Evaluator로 형식 준수와 요청 충족 여부를 평가한다.

AwareAuto~\cite{awareauto}는 사용자가 검토·수정할 수 있는 자동화 규칙을 구성하고, 이를 기기 인터페이스에 연결된 TA-pair JSON으로 변환하여 실행 관리자에 전달한다. 이 규칙 표현에는 이벤트·상태 모드와 시간 조건이 포함된다. VETS의 최종 산출물은 에지 감지나 조건의 지속 같은 시간적 동작을 변수와 조건문으로 구현하는 JOI 스크립트다. 따라서 VETS는 생성된 구현의 상태 갱신과 동작 시점이 확정된 Timeline IR의 행동을 보존하는지 검사한다.

자동화 밖에서도 생성 결과를 원래 요청과 대조하는 접근이 제안되었다. LACE~\cite{lace}는 생성된 접근 제어 정책을 자연어로 역변환하고 NLI 모델로 원래 요청과의 의미적 동등성을 판단하며, 정책 간 충돌은 SMT 솔버로 별도 검사한다. 따라서 요청 부합성 판단은 정책의 의미를 다루고, 형식 검사는 정책 간 충돌을 다룬다.

이러한 연구를 바탕으로 본 연구가 다루는 질문은, 명시된 자동화 동작이 별도로 생성된 반응형·시간 기반 코드에서도 보존되는가이다. VETS는 자연어 요청으로부터 Timeline IR을 구성하고, 확정된 IR을 코드 생성의 기준이자 실행 가능한 검증 기준으로 사용한다. Behavioral Explorer는 정해진 입력값 범위와 실행 규칙 안에서, 허용된 모든 초기 상태와 입력 시퀀스에 대해 생성 코드가 IR과 동일한 timed action trace를 만드는지 검사한다. 이 보장은 확정된 IR이 사용자가 의도한 자동화를 담고 있다는 가정에 의존한다.
