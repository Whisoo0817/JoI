# 시스템 개요

![VETS 시스템 개요](system.pdf)

*VETS 시스템 개요. Authoring 단계에서는 사용자 확인을 거친 Timeline IR을 바탕으로 JOI 코드를 생성하고, Verification 단계에서는 생성 코드의 행동을 확정된 IR과 비교한다. 점선은 사용자 요청에 따른 IR 수정과 선택적인 반례 기반 코드 수정을 나타낸다.*

VETS는 앞서 설명한 설계를 두 단계의 파이프라인으로 구현한다. Authoring 단계에서는 사용자 요청으로부터 Timeline IR을 구성하고, 사용자가 그 동작을 검토·확정하면 이를 실행 가능한 JOI 코드로 변환한다. Verification 단계에서는 배포 전에 Behavioral Explorer가 생성 코드를 확정된 IR과 대조한다.

**실행 대상.** VETS는 상용 IoT 플랫폼의 엣지 허브에서 구동되는 JOI 코드를 생성·검증 대상으로 삼는다. JOI 자동화는 시작 스케줄(`cron`), 재실행 간격(`period`), 스크립트 본문(`code`)으로 구성된다. 에지 감지, 조건의 지속, 횟수 세기 등의 시간적 동작은 영속 변수와 일반 조건문을 사용하여 반복 실행되는 스크립트 안에서 구현해야 한다.

**Phase 1: Authoring.** VETS는 먼저 사용자의 자연어 요청을 분석한다. 이 분석은 시작 시각, 반복 주기, 트리거 또는 조건, 지연 또는 지속 시간, 대상 액션 등 자동화에 필요한 시간적·행동적 항목을 식별한다. 또한 요청에 등장하는 기기를 연결된 기기 목록과 대응시켜 기기 바인딩을 구성한다. 로컬 LLM은 이 분석을 바탕으로 자동화의 시간적 제어 흐름을 명시하는 Timeline IR을 생성한다. Timeline IR의 구조와 제시 방식은 §5에서 설명한다.

사용자는 IR이 나타내는 동작과 기기 바인딩을 검토하고, 확정 전에 수정을 요청할 수 있다. 확인이 끝나면 IR을 행동 기준으로 확정하고, 로컬 LLM이 확정된 IR과 바인딩을 바탕으로 JOI 코드를 생성한다.

**Phase 2: Verification.** Behavioral Explorer는 확정된 Timeline IR과 생성된 JOI 코드를 입력으로 받는다. 행동 검사 전에 코드를 파싱한다. Explorer는 기기 바인딩, 시작 시각, 입력값 범위와 실행 규칙으로 검증 환경을 설정한다. 이어서 이 환경에서 허용되는 초기 상태들을 출발점으로 두 실행의 탐색을 시작한다. IR 인터프리터와 JOI 인터프리터는 같은 외부 입력값과 논리 시계를 사용하면서, 각자의 변수와 타이머, 실행이 어디까지 진행되었는지를 별도로 유지한다. Explorer는 다음 입력 선택, 양쪽 실행 진행, timed action 비교, 아직 검사 범위에 포함되지 않은 후속 상태 추가를 반복하며 가능한 실행을 함께 탐색한다.

허용된 모든 초기 상태와 입력 시퀀스에서 timed action trace가 일치함을 확인하는 탐색이 완료된 경우에만 배포를 승인한다. 불일치는 재생으로 차이를 확인한 경우에만 보고하며, 지원하지 않는 연산, 실행 오류, 검사 예산 소진은 미인증으로 남아 배포를 승인하지 않는다. 검증은 LLM 호출 없이 로컬에서 수행한다. 보장 범위는 정해진 입력값 범위와 실행 규칙 안에서 생성 코드가 확정된 IR에 부합하는지에 있다. 공동 탐색 절차와 판정 기준은 §6에서 자세히 설명한다.

**반례 피드백.** 반례에는 초기 환경, 입력 시퀀스, 기대 액션과 실제 액션이 기록된다. 이 반례를 LLM에 전달하여 JOI 코드 수정을 안내할 수 있다. 확정된 IR과 바인딩은 유지하며, 수정된 코드는 배포 전에 다시 검사해야 한다.
