# 행동 검증: 실행 규칙과 건전성

> 부록을 포함한 9페이지 분량을 고려하여 논문에서 제외했다. 이 파일은 로컬 기술 참고자료로 보존한다.

6절의 실행 규칙, 지원하는 탐색 방법, 건전성 논증을 정리한 부록이다. 여기서 반응(reaction)은 고정된 논리 시각에 프로그램을 실행하여 대기하거나 종료할 때까지 진행하고, 그 시각에 발생한 액션을 모으는 단위다.

## 실행 계약

모델 \(M\)은 바인딩, 서비스 catalog와 반환 정책, 시작 시각 \(t_0\), 입력 도메인, 허용되는 초기 전역 변수 환경 \(G_0\), 그리고 다음 실행 규칙을 고정한다. hour와 timestamp 같은 시간 필드는 논리적 시각을 따르며, 휴일 여부는 외부 불리언 입력이다. 두 인터프리터는 같은 외부 입력과 논리적 시각을 사용하되, 제어 위치와 저장소는 각각 유지한다.

| 구성 요소 | 선언된 모델 |
| --- | --- |
| 외부 입력 | \(t_0+n\Delta\)마다 각 입력은 선언된 도메인의 어떤 값으로든 바뀔 수 있고, 다음 갱신까지 유지된다. 기본 \(\Delta\)는 100 ms다. 한 갱신 구간 안에서 같은 기기·member·조회 인자 키를 읽으면 같은 값을 얻는다. |
| 값과 초기화 | 입력은 catalog의 타입·범위를 따른다. INTEGER는 수학적 정수이며, DOUBLE 입력은 선언된 0.1 격자와 숫자 표현 정책을 따른다. 명시적으로 도메인의 부분집합을 지정하면 보장도 그 범위로 제한된다. 프로그램이 쓰는 전역 변수는 \(G_0\)에서 시작해 각 실행에서 별도로 변화하며, 지역 변수는 각 프로그램의 초기화 규칙을 따른다. |
| 시간 | 내부 만료 시각은 1 ms 해상도를 따르며 입력 갱신 시각으로 반올림하지 않는다. 입력 갱신과 만료가 겹치면 새 입력을 먼저 적용한다. 반복의 period는 이전 회차가 끝난 뒤 시작된다. |
| 실행 인스턴스 | 준비 단계에서 `cron`을 포함한 시작 앵커가 같은지 검사한다. 검증 대상은 하나의 시나리오 인스턴스이며, 예약 실행 인스턴스의 중첩이나 여러 시나리오의 동시 실행은 모델 밖이다. |

**관찰하는 행동.** 각 비교 시각에 Explorer는 액션의 대상, 메서드, 인자, 발생 횟수와 순서를 비교한다. 하나의 fanout 호출에 속한 독립 기기들 사이에서만 순서 차이를 허용한다. 숫자 인자는 값으로 비교하며, 불리언과 문자열은 별개의 타입으로 구분한다. 이 트레이스 비교는 불필요하게 추가된 액션과 누락된 액션을 모두 찾아낸다. 한쪽이 액션을 내고 다른 쪽은 조용하다면, 나중에 기기 상태가 같아지더라도 불일치다. 한쪽이 종료되면 이후 영구적으로 액션을 내지 않는 것으로 처리하고, 다른 쪽은 계속 검사한다.

## 공동 입력과 저장값

지원되는 단일 값 술어에만 쓰이는 입력은 두 프로그램의 술어를 함께 수집한다. 대입을 거쳐 사용되는 경우도 포함한다. 수집한 모든 술어의 참·거짓이 같을 때만 두 값을 같은 셀로 묶는다. 그러면 비어 있지 않은 셀마다 대표값 하나를 검사하여 해당 조건 결과를 모두 포함할 수 있다. 예를 들어 IR의 조건이 \(T>22\), 코드의 조건이 \(T>25\)이면 선언된 숫자 도메인 안에서 \(T\le22\), \(22<T\le25\), \(T>25\)를 구분해야 한다. 가운데 셀이 두 조건의 불일치를 드러낸다. Explorer는 각 프로그램에서 따로 고른 대표값 목록을 합치는 대신, 술어를 먼저 합쳐 입력을 분할한다.

이 축소를 적용하려면 값의 이후 사용도 검사해야 한다. `saved = T` 이후 `saved`를 인자로 전달하는 액션이 있다면, 23과 24가 현재 같은 조건들을 만족하더라도 하나로 합칠 수 없다. 분석은 모든 정의, 분기와 복사를 따라가며 출력, 변환 또는 분할로 보존되지 않는 계산에 사용되는 값을 식별한다. 이런 입력은 전체 값을 열거하거나 지원되는 기호 방법으로 다뤄야 한다. 저장값은 타입과 원래 읽은 입력 구간의 의미를 유지하며, 과거에 저장한 입력을 최신 입력으로 바꾸지 않는다. 예를 들어 액션의 숫자 인자 `1`과 `1.0`이 같다고 해서 저장소까지 합칠 수는 없다. 이후 문자열 변환에서 둘이 구분될 수 있기 때문이다.

구체 탐색~\cite{modelchecking}은 양쪽 제어 상태, 관련 저장소, 활성 타이머, edge·종료 플래그와 필요한 현재 입력을 유지한다. 다음 입력 갱신, 만료, 관련 시계 경계 중 가장 이른 시각으로 진행한다. 두 프로그램 모두 중단된 상태에서 중간 입력을 관찰하거나 관련 상태를 바꾸지 않을 때만 그 갱신을 생략할 수 있다. 재개할 때는 가능한 최신 입력을 모두 포함하고, 이전에 저장한 값도 보존한다.

## 타이머 관계와 탐색

Explorer는 지원되는 프로그램 형태에 따라 서로 다른 검사 방법을 사용한다. 각 방법은 별도의 적용 조건과 완료 의무를 가지며, 한 방법이 지원한다고 해서 다른 방법도 지원하는 것은 아니다.

| 방법 | 지원 형태와 인증 조건 |
| --- | --- |
| 구체 탐색 | 공동 술어 셀 또는 전체 입력값과 정확한 상태 또는 정당화된 상대 시간 키를 사용한다. 모든 후속이 포함될 때만 인증한다. |
| 기호 값 흐름 | 순차적인 일회 실행의 읽기·복사·문자열·고정 지연을 다룬다. 타입을 가진 읽기 기호를 보존하고, 종료까지 관찰이 일치하면 인증한다. |
| SMT 산술 | catalog 범위와 선형 산술(덧셈·뺄셈·상수 곱셈/나눗셈)을 사용하는, 순환 없는 숫자 일회 실행을 다룬다. 일반 loop·전역 변수·시계 읽기는 제외한다. 관찰 식이 같거나 경로·입력 제약 아래의 액션 차이 질의가 UNSAT이어야 하며, 모든 경로가 종료해야 한다. |
| 정수 관계 | 제한된 최상위 카운터 반복을 다룬다. 실제 초기화, 출력·갱신 순서와 정수 관계 보존을 검사하고 그래프가 닫혀야 한다. |
| 타이머 관계 | 만료가 입력 격자에 맞고 카운터 사용이 제한된 동기 프로그램을 다룬다. 타이머·카운터 집합을 탐색하며 확대된 집합을 모두 재검사해 폐쇄에 도달해야 한다. |

**서로 다른 시간 표현의 연결.** IR의 지속 조건 대기는 JOI의 틱 카운터에 대응할 수 있다. 기본 타이머 방법은 JOI 반복 주기가 \(\Delta\)이고, IR의 period·delay·지속 조건 길이·timeout이 \(\Delta\)의 정수배일 것을 요구한다. 선택한 카운터에는 정수 상수 초기화·리셋, 1씩 증가, 정수 상수와의 직접 비교를 허용한다. 일반 변수나 액션·조회 인자로 복사하는 경우는 거절한다. 이 제한은 해당 카운터의 대입과 사용처 전체를 검사하여 확인한다. 이 기본 경우는 JOI loop·전역 변수·조회·시계 읽기를 제외하며, Hour와 timestamp snapshot 확장에는 추가 사용처 검사가 필요하다. 다른 시간 표현에는 별도로 지원되는 분석이나 구체 탐색이 필요하다.

노드 \((q,Z)\)의 \(q\)는 양쪽 제어 위치, 관련 일반 저장소, 활성 타이머의 구성, edge·종료 플래그를 유지한다. 집합 \(Z\)는 정수 차이 제약 행렬(difference-bound matrix, DBM) [@bengtsson2004timed]로 표현하며, \(x_i-x_j\le c\) 형태의 제약을 나타내며, 영 좌표는 \(x_0=0\)이다. 카운터 좌표는 원래 정수값이고, 타이머 좌표는 저장된 시작 또는 만료 시각 \(r\)에 대한 \((t-r)/\Delta\)다. 따라서 미래 만료 시각의 좌표는 음수다. 예를 들어 초기화와 이후 반응이 뒷받침하면 IR 경과 시간 좌표 \(a\)와 JOI 카운터 \(k\) 사이의 \(a-k=0\) 관계를 유지할 수 있다. 이 관계 아래에서는 \(a\ge d\)와 \(k\ge d+1\)이 \(a=k=d\)에서 달라져 한 틱의 시간 오류를 드러낸다.

각 공동 입력에 대해 두 인터프리터는 같은 관계 제약 아래에서 실행된다. 비교는 반대 경우까지 포함한 가능한 분기들로 집합을 나누며, 모순된 분기는 제외한다. 각 분기에서 액션 일치를 검사한다. \(x'=y+c\) 형태의 갱신이나 정수 상수 대입은 치환과 투영으로 정확한 후속 DBM을 만든다. 카운터 증가와 타이머 리셋은 원래 문장 순서를 따른다. 이 기본 방법의 관련 사건은 모두 격자 위에 있으므로 한 입력 간격씩 진행해도 중간 액션을 빠뜨리지 않는다.

**포함, 확대와 재검사.** \(q\)가 다른 후속은 별도로 유지한다. 기존 \(Z\)가 새 후속 집합을 포함하면 추가 작업이 필요 없다. 포함하지 않으면 widening~\cite{cousot1977}으로 두 집합을 모두 포함하도록 확대한다. 불안정한 경계는 프로그램의 비교 상수와 타이머 길이에서 얻은 임계값 또는 무한대로 늘리며, 안정적인 차이 제약은 유지한다. 확대된 노드는 현재 처리 중인 노드여도 작업 목록에 다시 넣는다. 확대된 집합에서 모든 입력과 가능한 분기를 재검사한다. 이 집합에는 실제로 도달할 수 없는 상태가 포함될 수 있으며, 인증하려면 그 집합 전체에서 액션 일치와 후속 포함이 성립해야 한다. 구체 대표 하나의 실행만으로는 이 의무를 충족할 수 없다.

**알고리즘 1. 타이머 관계 탐색.**

```text
공통 모델과 타이머 방법의 제한을 검사한다. 만족하지 않으면 UNCERTIFIED를 반환한다.
공동 입력 셀을 구성하고, 전체 값이 필요한 입력은 그대로 보존한다.
D := 첫 반응 전 초기 노드들; Q := 모든 초기 노드의 키
Q가 비어 있지 않은 동안:
    자원이 소진되면 UNCERTIFIED를 반환한다.
    q := Q에서 꺼낸 키; Z := 현재 D[q]
    (q, Z)에서 모든 공동 입력과 가능한 관계 분기에 대해:
        처음에는 t0, 이후에는 한 격자 간격 뒤에서 양쪽 반응을 실행한다.
        해당 시각의 액션을 비교한다.
        불일치 가능성이 있으면:
            초기화부터 구체 재생하여 확인되면 DIVERGENT를 반환한다.
            그렇지 않으면 이 시도에서 UNCERTIFIED를 반환한다.
        후속 (q', Z')를 계산한다. 양쪽 모두 종료된 후속만 생략한다.
        q'가 새 키이면:
            D[q'] := Z'; q'를 Q에 추가한다.
        그렇지 않고 Z'가 D[q']에 포함되지 않으면:
            D[q'] := Widen(D[q'], Z'); 대기 중이 아니면 q'를 Q에 추가한다.
EQUIVALENT를 반환한다.
```

알고리즘 1은 타이머 방법을 설명하며, 초기 노드에서 첫 반응과 이후 재개를 구분한다. 지원하지 않는 연산이 나오면 그 시도는 인증 없이 중단한다. 타이머 시도가 미확정이면 자원 한도 안에서 구체 탐색을 이어서 시도할 수 있다. 추상 불일치 자체는 반례가 아니다. 원래 초기화, 입력과 시계 규칙을 따른 재생에서 실제 차이를 확인해야 한다.

## 검사 완료와 건전성

완료된 관계 그래프가 나타내는 구체 상태 쌍들의 집합을 \(R\)이라고 하자. 상대 시각은 \(M\) 아래에서 해석하며, 양쪽 모두 종료된 상태는 이후 조용한 흡수 상태로 포함한다. 인증은 다음을 확보한다.

\[
\operatorname{Init}_M\subseteq R,\qquad
\operatorname{Post}_M(R)\subseteq R,
\]

또한 모든 허용 입력에 대해 표현된 모든 반응의 시간 포함 관찰이 일치해야 한다. \(\operatorname{Post}_M\)은 공통 실행 규칙 아래의 모든 후속을 포함한다. 작업 목록 소진으로 이 조건들이 성립하는 이유는 모든 초기 경우, 입력과 가능한 분기를 포함하고 확대된 노드를 재검사하기 때문이다. 일회 실행 기호 방법은 대신 가능한 모든 경로에서 관찰 일치와 종료를 확인하여 완료한다. 자원 한도 도달이나 유한 실행 구간의 검사만으로는 무제한 동등성이 성립하지 않는다.

\(I,C\)는 준비된 IR과 코드이며, \(\mathcal U_M\)은 앞의 계약에서 허용하는 입력 이력이다. 지원되는 방법이 자신의 의무를 완료하고 실행 시간의 상한 없이 EQUIVALENT를 반환하면 이를 \(\operatorname{Accept}_{\infty}(I,C,M)\)으로 표기한다.

**명제 S — 건전성.** 지원 범위에 속하며 준비를 마친 IR–코드 쌍에 대해, 선언된 실행 및 관찰 규칙 아래에서 다음이 성립한다.

\[
\begin{aligned}
&\operatorname{Accept}_{\infty}(I,C,M)\\
&\quad\Longrightarrow\ \forall g_0\in G_0,\ \forall u\in\mathcal U_M:\\
&\qquad\operatorname{Tr}_M(I;g_0,u)
 =_O \operatorname{Tr}_M(C;g_0,u).
\end{aligned}
\]

여기서 \(=_O\)는 앞의 관찰 규칙에 따라 액션과 발생 시각이 같다는 뜻이다. 연산자 규칙이 결정적이고, 각 논리 시각의 실행이 유한하며, 유한 시간 구간에 실행 재개가 유한 번만 발생한다고 가정한다. 오류와 실행 한도 도달은 정상 종료가 아니다.

**증명 개요.** 공동 술어 셀은 모든 허용 입력값 조합을 포함한다. 사용처 분석은 술어와 이후 관찰이 보존되는 곳에서만 대표값 치환을 허용하고, 관찰 가능한 저장 데이터는 전체 값이나 타입을 가진 기호로 보존한다. 따라서 입력 갱신을 넘어 저장된 읽기까지 포함해 모든 구체 입력 이력이 포괄된다. 타이머 관계에서는 가능한 분기를 나누어 표현된 모든 값을 포함하며, 정확한 후속 투영과 그 뒤의 확대가 모든 후속을 포함한다. 확대된 노드를 재검사하므로 추가된 도달 불가능 상태까지 포함한 최종 집합 전체에서 관찰 일치와 폐쇄가 성립한다.

구체 방법은 미래 행동을 보존하는 상태 키를 사용하고, 기호 방법은 모든 가능한 경로에서 관찰 식의 일치 또는 차이 질의의 해소를 요구한다. 정수 관계 방법에서는 실제 초기화가 관계를 수립하고 각 반응의 출력·갱신 검사가 이를 보존한다. 지원되는 시간 생략 구간에는 관찰이 없고, 재개 시 가능한 모든 입력을 유지한다. 따라서 초기 포함과 후속 포함에 대한 귀납으로 모든 유한 트레이스 접두부에서 일치가 이어진다. 종료된 기호 경로는 이후 조용하다. 정상 실행과 시간 진행 가정에 따라 접두부의 일치가 전체 트레이스로 확장되며, 결정적인 IR 실행이 유일한 기준 트레이스를 제공한다.

이 보장은 파싱, 의미 해석과 솔버 결과가 올바르다는 가정에 의존한다. 확정된 IR이 사용자의 의도와 일치하거나 실제 기기가 모델대로 동작함을 입증하지 않으며, 모든 동등한 쌍에 대해 판정이 완료된다고 보장하지 않는다.

건전성 논증은 수작업 증명 개요이며, 구현을 기계적으로 검증한 것은 아니다.
