# §5 Timeline IR 집필 계획

작성일: 2026-09-19. 사용자 요청에 따른 비판적 검토와 제안이며, 본문·그림·구현의 수정 완료나 저자 확정을 뜻하지 않는다. 이번 단계에서는 집필 계획만 작성한다.

## 1. 절의 중심과 주장 범위

**Timeline IR은 자동화의 시간적 제어 흐름을 명시하며, 주어진 입력에서 기대 동작과 발생 시각을 정하는 실행 가능한 행동 명세다.**

- 시간적 연산은 실행이 언제 진행되는지를, 순서·분기·반복·종료는 어떻게 진행되는지를 정한다. 이 두 요소의 결합을 설명한다.
- “time axis”를 모든 액션의 절대 시각이 미리 배치된 스케줄로 설명하지 않는다. 분기 결과와 대기 완료 시각은 입력에 따라 달라진다. IR은 가능한 흐름을 정의하고, 특정 초기 상태와 입력 시퀀스에서 실행하면 하나의 timed action trace가 나온다.
- `executable`은 IR 인터프리터가 실행 의미에 따라 기대 액션을 산출한다는 뜻으로 구체화한다. IR을 기기 배포 코드라고 소개하지 않는다.
- 순서·분기·반복 자체의 신규성을 주장하지 않는다. 시간 조건과 제어 흐름을 명시한 IR을 authoring에서 확정하고 생성 코드의 행동 기준으로 사용하는 역할에 초점을 둔다.
- 새로운 실증 주장을 추가하지 않는다. 표현 범위는 Evaluation, 사용자 이해도·오류 식별 효과는 미평가 사항으로 남긴다.

## 3. 권장 본문 구성

소절을 많이 나누지 않고 네 문단 묶음으로 구성한다. 초안 목표는 영문 약 450–550단어와 그림 하나이며, 이는 편집 목표이지 확정된 지면 규정이 아니다.

1. **Explicit temporal control flow.** 도입에서 중심 주장을 제시한다. JSON의 순차 step과 중첩된 branch/cycle body가 구조를 나타내며, start/wait/delay/period가 시간 진행을 정함을 설명한다. 같은 동작이 JOI에서는 상태 변수·조건문·주기적 실행에 나뉠 수 있다는 연결은 한 문장으로 제한한다.
2. **One worked example.** 그림의 습도 예시로 if의 선택, On → delay → Off의 순서, 회차 완료 후 period 대기와 재진입을 설명한다. 그림에서 쓰지 않은 wait의 조건·edge·지속시간, read의 저장, break의 종료 역할은 짧게 덧붙인다. 한 Timeline의 병렬 branch는 주장하지 않는다.
3. **Executable reference.** 현재 실행 위치·저장값·타이머를 유지하며 대기 또는 종료까지 진행하고, 기기 명령과 시각을 기록한다는 실행 설명을 둔다. 필요한 결정성 조건을 평문으로 적고 §6의 IR–코드 비교로 연결한다. 탐색 알고리즘은 반복 설명하지 않는다.
4. **Presenting the IR.** JSON 직접 제시, 규칙 기반 자연어 설명, 선택한 입력에서의 시간 축 시각화를 예로 든다. 향후 입력을 바꿔 보는 상호작용형 재생이나 LLM 설명으로 확장할 수 있으나, 설명 방식과 관계없이 확정 IR이 명세라는 점을 유지한다. 이해도 개선은 주장하지 않는다.

## 4. 그림 계획: 하나의 예시, 세 가지 관점

기존 SenSys Figure 4(b)의 습도 예시를 수정해 사용한다. 단순 sustain 예시는 짧지만 분기·반복을 보여주지 못하므로 이번 절의 중심에는 습도 예시가 더 적합하다. 모든 operator를 넣으려 예시를 복잡하게 만들지 않는다.

**예시 의미:** 지금 시작한다. 회차 시작 시 습도가 70을 초과하면 스위치를 켜고 5분 기다린 뒤 끈다. 조건이 거짓이면 동작하지 않는다. 어느 경우든 회차가 끝난 뒤 10분 기다리고 다음 회차를 시작한다.

- 기존 `cron`은 그림에서 `start_at: now`로 단순화하고 상대 시각을 쓴다. 스케줄 기능은 본문에서 언급한다. 여러 일일 인스턴스의 중첩까지 이 그림으로 설명하지 않는다.
- **(a) Timeline IR:** 실제 JSON의 start_at → cycle → if → call/delay/call 중첩을 보인다. 작은 글씨로 모든 필드를 나열하지 않는다. 축약하면 축약임을 명시하고 실행용 원본을 별도로 둔다.
- **(b) Plain-language view:** 위 의미를 간결하게 제시한다. “매 10분마다 검사”가 아니라 “회차 완료 후 10분 대기”를 명시한다. 현재 renderer 출력으로 소개하려면 먼저 해당 구현을 고치고 확인해야 한다. 그 전의 수동 문안은 제시 방식의 예시로 구분한다.
- **(c) Execution under one timed input sequence:** 가로 시간 축에 입력 습도, 실행 위치/대기 구간, 발생한 명령을 정렬한다. 명령은 On/Off 지점으로 표시한다. 지속된 기기 상태를 실측한 것처럼 막대로 표시하지 않는다.
- (a), (b)는 IR의 구조와 설명이며, (c)는 특정 입력에서의 실행이다. 세 패널을 모두 IR 전체와 동등한 표현이라고 부르지 않는다. 특히 한 trace가 모든 분기를 설명하거나 검증한 것은 아니다.
- 배치는 위쪽 IR·설명 두 패널, 아래쪽 공통 시간 축을 권장한다. 색 없이도 따라갈 수 있도록 같은 단계명과 괄호/구간 표기를 사용한다. 별도 시스템 그림이나 코드 비교를 추가하지 않는다.

시간 축의 구체 내용:

| 상대 시각(분) | 입력 / 실행 사건 | 기기 명령 |
| --- | --- | --- |
| 0 | 습도 75, 첫 회차 조건 참; 5분 delay 진입 | On |
| 2 | 습도가 65로 바뀜; 진행 중인 무조건 delay 유지 | 없음 |
| 5 | delay 완료; 회차 종료; 10분 period 대기 시작 | Off |
| 15 | 다음 회차 조건 거짓; 즉시 회차 종료; 다시 10분 대기 | 없음 |
| 20 | 습도가 75로 바뀜; period 대기 유지 | 없음 |
| 25 | 다음 회차 조건 참; 5분 delay 진입 | On |
| 30 | delay 완료; 회차 종료; 10분 period 대기 시작 | Off |

이 예시는 외부 입력 변화와 내부 타이머 만료를 구분하고, 입력 변화가 항상 즉시 액션이나 분기 재평가를 일으키는 것은 아니라는 점을 보여준다. 표의 사건 사이에서도 입력은 유지되며, 모든 입력 갱신 tick을 그림에 그릴 필요는 없다.

**확인 범위:** 2026-09-19 `IrRunner`에 위 IR(`start_at: now`)과 입력을 주어 0–35분을 1초 간격으로 실행했다. 명령 trace는 On@0, Off@5, On@25, Off@30이었다. 이는 그림용 한 실행의 확인이며 전체 의미론의 증명, catalog/binding 준비 검사의 확인, 사용자 평가가 아니다.

## 5. Input-determinism의 최소 설명

권장 문안의 핵심은 다음과 같다. 최종 본문에서는 앞의 실행 설명과 합쳐 중복을 줄인다.

> Timeline IR 인터프리터는 현재 실행 위치, 저장값과 타이머를 유지하며, 순서·조건·시간 규칙에 따라 다음 단계를 결정한다. 입력 갱신과 타이머 만료가 겹치면 새 입력을 먼저 반영한다. 따라서 IR, 바인딩과 실행 규칙을 고정하면, 같은 초기 상태와 timed input sequence는 같은 순서와 시각의 기기 명령을 정한다. 이는 오류 없이 각 시각의 처리가 유한하게 끝나고 유한 시간 안에 무한히 많은 처리가 일어나지 않는 실행을 전제로 한다. §6은 이 기대 timed action trace를 생성 코드의 행동과 비교한다.

- 명제 D라는 이름, 수식, 귀납 증명은 넣지 않는다. `input-determinism` 용어 자체도 지면상 필요하면 생략할 수 있다.
- 내용 전체를 빼는 것은 권장하지 않는다. 다만 도입과 실행 설명에 같은 초기 상태·입력·실행 규칙에서 명령과 시각이 정해진다는 내용이 이미 들어가면 별도 결정성 문단은 없앨 수 있다.
- 서로 다른 입력도 같은 trace를 만든다는 뜻이 아니다. IR에 분기가 없다는 뜻도 아니며, 임의 IR의 종료나 전체 구현의 기계 검증을 보장하지 않는다.
- 기존 증명 자료는 로컬 기술 참고로 보존한다. 사용자와 앞서 정한 지면 방침에 따라 논문 부록을 자동으로 추가하지 않는다.

## 6. 구현·원고 정합성 및 집필 순서

1. 위 예시와 시간 축으로 한글 초안을 작성한다. 실행 의미가 필요한 부분만 SenSys 문장을 바꾸며, 옛 §5의 rendering 중심 논리는 재구성한다.
2. 그림을 제작할 때 실행용 JSON과 시간 축 데이터의 대응을 보존한다. 현재 `ir_renderer.py`는 이 예시에 “Every 10 minutes, check the humidity.”를 출력함을 확인했다. 결정론적 렌더링 결과로 싣기 전 수정·확인이 필요하며, 이번 계획 단계에서는 구현을 변경하지 않는다.
3. 본문이 확정되면 PerCom2 영문·한글과 Overleaf §5를 동기화한다. 이전 SenSys·PerCom 자료는 보존한다.
4. Overleaf의 기존 `Timeline IR Grammar` 부록에도 feasibility gate, nested-cycle 금지, period cadence, bounded horizon 설명이 남아 있다. §5 수정 시 이 절에 종속된 부록과 참조도 함께 정리해야 한다. 기본안은 논문에서 해당 부록을 제외하고 로컬 참고로 보존하는 것이다.
5. 시스템 그림과 Limitations·Conclusion에도 옛 gate/rendering/bounded-checking 설명이 남아 있다. §5 수정만으로 전체 정합성이 해결되었다고 보고하지 않으며, 해당 절 후속 정리 항목으로 둔다.
6. 문장 검토 단계에서는 PDF 빌드나 푸시를 하지 않는다.
