# Timeline IR

Timeline IR은 자동화의 시간적 제어 흐름을 시간 축 위에 명시적으로 드러낸다. 스케줄, 대기, 지연은 실행이 언제 진행되는지를 정하고, 순서, 분기, 반복은 실행이 어떻게 진행되는지를 정한다. 사용자가 확정한 IR은 코드 생성을 안내하며, 생성된 JOI 코드를 검사하기 위한 실행 가능한 행동 기준을 제공한다.

**연산자와 구조.** IR은 각 단계가 `op` 필드로 식별되는 JSON 트리다. `timeline`은 `start_at`으로 시작 시점을 정하고 각 단계를 순서대로 실행한다. `if`의 분기와 `cycle`의 본문에는 다시 단계들의 시퀀스가 들어간다. 기본 연산자에는 조건, 관찰된 에지 또는 조건의 지속을 기다리는 `wait`, 일정 시간 기다리는 `delay`, 값을 저장하는 `read`, 기기 서비스를 호출하는 `call`도 있다. 조건의 지속을 기다리는 `wait`는 조건이 거짓이 되면 타이머를 초기화한다. `cycle`은 각 회차가 끝난 뒤 `period`만큼 기다리며, 횟수나 `until` 조건으로 반복을 끝낼 수 있다. `break`는 자신을 감싸는 반복을 종료한다. 하나의 timeline 안에는 병렬 분기가 없다. IR이 참조하는 실제 기기는 확정된 바인딩이 지정한다.

그림 4의 예시는 문이 닫힌 초기 상태에서 시작하며, `Contact`의 참은 닫힘을, `Switch`는 현관 조명을 나타낸다. 그림 4(a)의 IR은 문 열림 이벤트를 기다린 뒤 조명을 켜고 반복에 진입한다. 반복 본문은 “문을 닫아 주세요”라는 안내를 내보내고, 문이 닫히거나 30초가 지날 때까지 기다린다. 문이 열린 상태로 30초가 지나면 다음 회차에서 다시 안내한다. 문이 닫히면 대기가 해제되고 `until` 조건에 따라 반복을 종료한다. 이어서 `cycle` 다음에 놓인 `call`(15행)이 조명을 끈다. 이처럼 반복은 전체 제어 흐름의 중간 단계이며, 종료 후에는 그 뒤의 단계로 실행이 이어진다. 그림 4(b)는 이 제어 흐름을 자연어로 표현한다.

그림 4(c)는 문 상태의 변화에 따라 이 제어 흐름이 시간 축에서 어떻게 진행되는지 보여준다. 10초에 문이 열리면 조명을 켠 뒤 첫 안내를 내보낸다. 문이 계속 열려 있어 40초와 70초에 안내를 반복한다. 85초에 문이 닫히면 100초의 대기 만료 시점까지 기다리지 않고 반복을 종료한 뒤 조명을 끈다. 시간 경과는 다음 회차로, 문 닫힘은 반복 이후 단계로 실행을 진행시킨다.

**실행 가능한 행동 기준.** IR 인터프리터는 실행 위치, 저장값과 타이머를 유지한다. 실행에 영향을 주는 각 시각에 대기하거나 종료할 때까지 단계를 실행하고, 발생한 기기 명령과 시각을 timed action trace로 기록한다. 입력 갱신과 타이머 만료가 겹치면 새 입력을 먼저 반영한다. IR, 바인딩과 실행 규칙을 고정하면, 같은 초기 상태와 입력 시퀀스(timed input sequence)는 같은 순서와 시각의 기기 명령을 정한다. 이러한 input-determinism은 오류 없이 실행되고, 유한한 시간 구간에서 유한한 수의 단계가 실행된다는 전제를 둔다. §6은 허용된 입력들에 걸쳐 이 기대 trace를 기준으로 생성 코드를 검사한다.

**IR의 제시 방식.** 사용자는 JSON을 직접 살펴보거나 그림 4(b)와 같은 자연어 렌더링을 검토할 수 있다. 그림 4(c)와 같은 시간 축 표현은 선택한 입력에서의 동작을 보여준다. 이 구조는 사용자가 입력값이나 변화 시점을 바꾸고 그에 따른 동작을 확인하는 기능이나, LLM을 통한 설명 생성으로 확장할 수 있다. 이러한 확장과 사용자 이해에 미치는 효과는 본 연구에서 평가하지 않는다. 어떤 방식으로 제시하더라도 확정된 IR이 명세이며, 우리는 이 IR이 사용자가 의도한 동작을 담는다고 가정한다.
