# E1 데이터셋의 구성과 구조 복잡도: 분석 및 본문 문안

> **정정:** 기존 R 태그 51건을 “두 가지 이상 행동 요소를 가진 요청”으로 해석한 부분은 철회한다. 태그가 복합 동작을 충분히 반영하지 못한다. 원문과 확정 해석을 다시 검토한 92건 전수 분석은 `E1_BEHAVIOR_REVIEW_KO.md`에 있다. 아래 IR 연산자·중첩 통계는 그대로 유효하다.

2026-09-19. `count_e1_operators.py`와 `e1_operator_counts.json`에 근거한 작성안. 현재 논문 본문에 적용하지 않았으며, 새 평가 실험은 실행하지 않았다.

## 1. 설명의 순서

**외부 출처에서 100건 수집 → 범위와 해석 가능성 검토로 92건 확정 → Timeline IR로 변환 → 변환된 구조의 특성 분석 → 예상 행동 재현 여부 평가.**

수집 당시의 선정 근거와 변환 후 관찰한 구조를 구분한다. 원고의 “목적 표집”은 출처와 연구 목적을 고려한 수집을 뜻한다. “무작위”, “사용 빈도가 높은”, “대표적인”, “1–10 난이도를 고르게 포함하도록 선정한”이라는 설명을 뒷받침하는 기록은 없다. 초기 12건은 행동 요소를 고려해 구성한 기록도 있으므로, 반대로 “아무 특성도 고려하지 않고 수집했다”고 단정하지도 않는다. 본문에는 “네 출처 유형에서 자동화 요청 100건을 수집했다”는 확인된 절차를 쓰면 된다.

92건은 IR 변환에 성공한 사례만 뽑은 수가 아니다. 연구 범위와 동작 해석의 명확성을 검토한 결과이며, 나머지는 모호함 6건과 범위 밖 2건이다. 구조 통계와 실행 결과는 이 92건에 대해 보고한다.

## 2. 원래 요청의 행동 특성

`corpus_100.csv`의 기존 저자 확정 `rb_adjudicated` 분류를 사용했다. 아래 수치는 IR 연산자 수로부터 추정한 것이 아니다. 한 요청에 여러 유형을 부여할 수 있다.

| 행동 특성 | 포함 요청 수 / 92 |
| --- | ---: |
| 즉시 반응 | 65 |
| 시계 시각·시간대 조건 | 28 |
| 순차·분기 | 23 |
| 지연 후 동작 | 14 |
| 일정 시간의 조건 지속과 중단 시 재계수 | 13 |
| 저장한 값을 이후 동작에 사용 | 8 |
| 조건을 만족할 때까지 주기적 반복 | 5 |
| 정해진 횟수 반복 | 3 |
| 사건에 한 번 반응하고 다시 무장 | 3 |
| 정해진 시각과 사건 발생의 경쟁 | 2 |

- 기존 R 태그는 요청당 1–5개이며, **51건에 두 개 이상 붙어 있다**. 이를 실제 행동 요소 수라고 해석하지 않는다.
- 즉시 반응만으로 분류된 요청은 26건이다.
- 취소·재시작, 독립 흐름, 사건 이력, 중첩 반복 같은 경계 요소는 **13건**에 나타난다. 유형별 중복을 허용하면 각각 6, 5, 2, 1건이다.
- 이 수치는 표집된 요청들의 구성이다. 실제 이용 빈도나 인구집단의 분포를 뜻하지 않는다.

이 태그 집계만으로 여러 행동 요소를 결합한 요청의 비율을 주장할 수 없다. 수집 의도는 이번에 저자가 설명한 “복잡한 요청 우선 탐색”을 반영하며, 실제 구성은 새 전수 검토안으로 확인한다.

## 3. 최종 Timeline IR의 구조 특성

92개 요청을 구현한 독립 Timeline은 98개다. 네 요청이 각각 2·3·2·3개 Timeline으로 분리되었다. 통계 단위는 계속 요청 92건으로 유지한다.

| 측정 축 | 결과 | 해석 |
| --- | --- | --- |
| 전체 연산자 종류 수 | 요청당 3–8종 | 하나의 종류를 여러 번 사용해도 종류 수는 한 번만 센다. |
| 공통 `start_at`·`call`을 제외한 종류 수 | 요청당 1–6종, 중앙값 3종 | 제어·대기·시간·값 처리 연산자의 조합 폭 |
| 공통 두 연산자 외 3종 이상 포함 | 77/92건(83.7%) | 여러 기능을 조합한 최종 인코딩이 다수 |
| 공통 두 연산자를 제외한 서로 다른 종류 조합 | 18개 | 연산자 종류의 집합만 비교한 값으로, 전체 제어 흐름 모양의 개수는 아님 |
| `if`/`cycle` 최대 중첩 깊이 | 0–4단계 | 외부 감시 반복도 포함한 구문 구조 |
| 중첩 깊이 2 이상 | 65/92건(70.7%) | 한 제어 구조 안에 다른 제어 구조가 들어가는 인코딩 |
| 중첩 깊이 3 이상 | 14/92건(15.2%) | 상대적으로 깊은 제어 구조 |
| 반복 자체의 최대 중첩 깊이 | 0–3단계 | 반복 중첩 2 이상은 10건 |
| `wait`와 `cycle` 함께 포함 | 65건 | 두 연산자가 같은 요청에 존재 |
| `wait`, `if`, `cycle` 함께 포함 | 47건 | 대기·조건 분기·반복이 같은 요청에 존재 |
| `read`와 `if` 함께 포함 | 53건 | 값을 저장하는 단계와 분기가 같은 요청에 존재 |
| 지속 조건을 가진 `wait` 포함 | 9건 | `for` 속성 사용 |
| 시간 제한을 가진 `wait` 포함 | 8건 | `timeout` 속성 사용 |

중첩 깊이별 요청 수: **0단계 2건, 1단계 25건, 2단계 51건, 3단계 10건, 4단계 4건**.

공통 두 연산자를 제외한 종류 수별 요청 수: **1종 2건, 2종 13건, 3종 38건, 4종 33건, 5종 5건, 6종 1건**.

`cycle`이 들어간 요청 88건을 “88건이 반복 행동을 요구한다”고 쓰면 안 된다. 단순 사건 감시·재무장을 구현하기 위한 반복도 포함되기 때문이다. `read` 역시 센서 값 저장과 내부 제어를 위한 이전 값·시각 저장을 모두 포함한다. 이러한 수치는 **선택한 최종 IR의 구조적 특성**이다.

## 4. 크기와 인코딩 방식

정적 연산자 노드 수는 `start_at`을 포함해 요청당 **3–7,803개, 중앙값 7개, 평균 110개**다. 반복문의 실행 횟수는 곱하지 않고, JSON에 작성된 각 노드를 한 번씩 센다. 단, 이미 JSON에 펼쳐진 반복은 펼쳐진 모습 그대로 센다.

| 사례 | 연산자 수 | 큰 이유 |
| --- | ---: | --- |
| E1-024: 스프링클러의 직전 48시간 급수 제한 | 7,803 | 600개의 1초 사용 이력 슬롯을 명시적으로 펼친 최종 구현 |
| E1-066: 일산화탄소 감지 후 점멸 | 905 | 두 조명에 대한 150회 점멸을 펼친 구현 |
| E1-070: 초인종 후 점멸 | 606 | 조명의 150회 점멸을 펼친 구현 |
| 나머지 89건 | 3–27, 중앙값 7, 평균 9.06 | 위 세 사례를 제외한 보조 분포 |

크기를 보고할 때 세 큰 사례를 숨기거나, 3–27을 전체 범위로 적지 않는다. 반대로 평균 110개만 강조하면 다수 사례의 구조를 잘못 전달하게 된다. **본문은 연산자 조합·중첩 깊이를 중심으로, 크기와 큰 사례는 부록에서 함께 설명**하는 구성이 적절하다.

짧은 예제도 여러 시간 조건을 결합할 수 있다. E1-099의 조명 유지·연장·종료 사례는 연산자 12개와 중첩 깊이 4를 가진다. “많은 노드 = 어려운 요청”이라는 단일 순위가 적절하지 않은 이유다.

## 5. 본문용 문안

### 데이터셋 문단: 수집과 선별

기존 출처 인용을 유지하고 아래 흐름으로 정리한다. 특징 목록을 먼저 제시하여 선정 조건으로 오해하게 만들지 않는다.

> Google Home과 Home Assistant의 공식 예제, 선행 연구의 과제와 예제, AutoTap의 공개 참가자 응답, Home Assistant Community 게시물에서 자동화 요청 100건을 수집했다. 저자 한 명이 반응형·시간 기반 자동화라는 연구 범위, 동작 해석의 명확성, 의미상 중복 여부를 검토하여 92건을 평가 대상으로 확정했다. 나머지는 해석이 모호한 여섯 건과 범위 밖의 두 건이다.

영문:

> We collected 100 automation requests from official Google Home and Home Assistant examples, published research tasks and examples, released AutoTap participant responses, and Home Assistant Community posts. One author reviewed their reactive-temporal scope, clarity of the requested behavior, and semantic duplication, identifying 92 requests for evaluation. The remaining six requests were ambiguous and two were outside the study scope.

### E1 문단: 변환 후 특성 — 권장 축약안

E1의 첫 문단을 아래로 대체하는 방식이다. 기존 해석·예상 트레이스 작성 절차, 예시, E1 표와 실행 결과는 유지한다. 98개 Timeline과 세부 크기는 부록에 둬도 된다.

> E1은 외부 요청 92건을 Timeline IR로 표현하고 실행해 표현 적합성을 평가한다. 최종 IR은 공통 연산자인 `start_at`과 `call` 외에 1–6종의 연산자를 사용했으며, 77건은 세 종류 이상을 조합했다. 분기와 반복의 최대 중첩 깊이는 0–4단계였고, 14건은 세 단계 이상이었다. 이 분포는 단순한 제어 구조부터 여러 연산자와 중첩 제어를 결합한 구조까지 평가했음을 보여준다.

영문:

> E1 evaluates Timeline IR adequacy by encoding and executing the 92 external requests. Beyond the common `start_at` and `call` operators, the final encodings used one to six operator types, with 77 requests combining at least three. Maximum nesting depth of conditionals and loops ranged from zero to four, with 14 requests reaching at least three levels. The evaluation thus covers simple control structures as well as combinations of multiple operators and nested control flow.

### 요청 자체의 특성 문안 정정

기존의 “51건이 두 가지 이상의 요소를 결합한다”는 한·영 문안은 철회한다. 이 문장 대신 `E1_BEHAVIOR_REVIEW_KO.md`의 전수 검토와 수집 의도 문안을 사용한다.

### 부록용 구조·크기 문안

> 외부 요청 92건의 최종 구현은 98개 Timeline으로 구성되며, 네 요청은 여러 독립 흐름으로 나뉜다. 요청별 통계는 이들 흐름을 합산하고 중첩 깊이는 최댓값을 취한다. 정적 연산자 수의 중앙값은 7개이며, 89건은 3–27개다. 나머지 세 건은 명시적으로 펼친 점멸 시퀀스 두 건과 600개 시간 슬롯으로 급수 이력을 기록하는 한 건으로, 각각 606개, 905개, 7,803개의 연산자를 사용한다. 분기·반복의 중첩 깊이 0·1·2·3·4에 해당하는 요청은 각각 2·25·51·10·4건이다. 이러한 값은 감시·재무장을 위한 제어 구조를 포함한 최종 인코딩의 특성이며, 요청의 고유 난이도를 나타내는 점수는 아니다.

## 6. 1–10 복잡도 점수 대신 쓸 수 있는 것

새 점수의 가중치와 경계값을 정할 근거가 없으므로 1–10 척도를 만들지 않는다. 요청별로 이미 측정 가능한 **(연산자 종류 수, 최대 중첩 깊이, 정적 노드 수)**를 제공하면 검토자가 복잡도의 다른 측면을 직접 확인할 수 있다. 비교가 필요하면 이 정의를 동일하게 E3에 적용할 수 있지만, 현재 인코딩 관례와 데이터 선정 목적이 다르므로 숫자 차이를 난이도 우열로 해석하지 않는다.
