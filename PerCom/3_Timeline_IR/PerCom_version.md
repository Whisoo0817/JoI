# Timeline IR — PerCom working draft

Timeline is an executable behavioral specification for a bounded class of reactive-temporal JoI automations. It does not attempt to standardize all smart-home behavior. Instead, it provides a closed, typed surface on which VETS can fix the behavior of one automation before generating platform code. A complete reference consists of the Timeline program, its binding plan, and the declared execution model.

Timeline combines temporal operators with structured control and explicit state propagation. `wait` observes a level, edge, sustained condition, or timeout according to defined evaluation and reset rules. `delay` advances unconditionally to a deadline. `read` stores the typed value observed at a specific point, allowing a later condition or ACTION to use that snapshot. `call` emits the observable service invocation. `if`, `cycle`, and `break` determine branch, repetition, and exit behavior, while `start_at` anchors execution when calendar time matters.

The operational state contains a control position, local values and relevant global variables, active timers, edge history, cycle state, and termination status. A reaction first applies the shared input snapshot at logical time `t`, then advances until the program blocks or terminates and emits an ordered sequence of ACTIONs. When an input update and a timer deadline coincide, the new input is applied first. A false sustained condition cancels its accumulated duration; an unconditional delay remains active. Period denotes a delay after an iteration completes rather than a fixed-rate start schedule.

For a fixed Timeline, model, initial state, and timed input history, supported execution yields one timed ACTION trace. This input-determinism is a property of the full operational semantics, including tie handling, state lifetime, and control composition; it is not an exclusive property of Timeline or a claim that every Timeline program is accepted. Unsupported combinations and executions that violate progress conditions are rejected or remain outside the certificate.

Binding grounds reference calls without embedding platform selectors into Timeline. In the current contract, each service-method pair has one distinct selector, which may denote several devices. The observable trace records action time, service, method, typed arguments, target, multiplicity, and explicit order. This contract allows Timeline to function as the reference for implementation validation rather than merely as an intermediate serialization format.
