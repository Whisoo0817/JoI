# Table 1 — judge verdict consistency on behavior-preserving rewrites

작성 2026-09-16, 같은 날 최종 설계로 갱신(맨 아래 8절 변경 이력). 이 실험은 **동기 실험**이며 E1–E4 밖이고
Introduction 의 Table 1 을 받친다(Figure 2 는 원고에서 뺐다). 보이려는 것 하나: *행동이 같은
프로그램을 표현만 바꿔 물으면 LLM judge 의 배포/거절 판정이 바뀌는가, 그리고 아무것도 바꾸지
않고 다시 물어도 바뀌는가.*

옛 SenSys 수치(9B 27.0% / GPT-5.1 10.6%, 유형별 최대 81%)는 **쓰지 않는다**. 이유:
identity 대조가 없었고, 씨앗이 확정 명세를 만족한다는 근거가 없었으며, 동등성 판정이 우리
시뮬레이터의 trace 한 줄이었고, 불확실성 추정이 없었다. 그 데이터셋(`equiv_stress_v2.json`,
251 groups / 643 variants)과 생성기는 남아 있지 않다(생성기는 `aa866bd^:paper/build_equiv_stress.py`
에서 복구 가능, v2 는 커밋된 적 없음). 따라서 재현이 아니라 새 실험이다.

## 1. 씨앗

E3 최종 실행(`explorer/eval/results/e3_single_binding_382_20260915_run/case_outcomes.jsonl`)의
**EQUIV-FIXPOINT 309건**. 후보 파일은 `explorer/candidates/qwen3_5-9b-fp8-e3-single-binding-v4/`.

이 씨앗을 쓰는 이유는 두 가지가 공짜로 따라오기 때문이다.
- **원본이 확정 명세를 만족한다**는 근거 — Explorer 가 확정 IR 과 EQUIV 라고 인증한 프로그램이다.
  (옛 실험에는 이 근거가 아예 없었다.)
- **변환본도 같은 잣대로 검증**할 수 있다 — 아래 2절.

파서가 거부하는 씨앗은 0건이었다. 변환이 하나도 만들어지지 않는 씨앗은 제외되어, 최소 하나의
검증된 변환을 가진 씨앗은 **217개**다(첫 설계 201개, 변환 추가로 16개 늘었다).

## 2. 변환 — 11 유형 3 띠

한 줄 예시로 "당연히 같다"가 읽히는 것부터, 시간 의미를 따라가야 같다는 걸 아는 것까지 배치했다.
옛 유형 중 드모르간·이중부정·덧셈 순서는 **뺐다** — 일반적인 코드 judge 편향이고
(Moon et al., *Don't Judge Code by Its Cover*, Findings of EACL 2026 이 이미 다룬다) 이 논문의 주장인
시간 행동과 거리가 멀다.

| 띠 | 유형 | 바꾸는 것 | 생성 | 증명 |
|---|---|---|---:|---:|
| Notation | `var_rename` | 변수 이름 하나를 전부 바꿈 | 50 | 50 |
| Notation | `comparator_flip` | `x >= 26` → `26 <= x` (첫 리터럴 비교) | 152 | 152 |
| Notation | `time_unit` | `delay(3 MIN)` → `delay(180 SEC)` | 27 | 27 |
| Notation | `exists_spelling` | `all(#X).a ==\| v` → `any(#X).a == v` | 39 | 39 |
| Logic | `branch_swap` | `if (C) {A} else {B}` → `if (not (C)) {B} else {A}` | 38 | 38 |
| Logic | `else_split` | `if (C) {A} else {B}` → `if (C) {A}` + `if (not (C)) {B}` | 38 | **27** |
| Temporal | `delay_split` | `delay(5 MIN)` → `delay(1 MIN)` + `delay(4 MIN)` | 25 | 25 |
| Temporal | `loop_unroll` | 횟수 반복 주기 실행 → 본문·delay 나열, `period` 0 | 15 | 15 |
| Temporal | `phase_flag` | `phase := 0` 정수 단계 → `started := false` + 공통 꼬리 | 11 | 11 |
| Temporal | `wait_precheck` | `wait until(C)` → `if (not (C)) { wait until(C) }` | 62 | 62 |
| Temporal | `period_halve` | `period P` → `period P/2`, 본문을 매 틱 뒤집히는 깃발로 한 번씩 거름 | 25 | 25 |

띠 이름은 원고 표와 같다. Notation 은 *어떻게 적느냐*만, Logic 은 조건·분기 구조를, Temporal 은 시간에
따라 실행되는 모양을 바꾼다.

- **`else_split` 은 무조건 동작 보존이 아니다.** then 절 A 가 조건 C 가 읽는 변수를 바꾸면 두 번째 검사
  값이 달라진다. 검사기가 11개를 `DIVERGE_CONFIRMED` 로 걸렀고 27개만 쓴다. 변환기는 후보를 내고
  **동등성은 검사기가 정한다**는 분업 그대로다.
- **`period_halve`** 는 `break`·`wait until`·`delay` 가 있는 본문(틱을 늦추거나 일찍 끝내 깃발이 안 뒤집힘)과
  본문 중간의 `:=` 를 제외한다. 맨 앞 `:=` 는 게이트 위로 올려 한 번만 돌게 한다.
- `else_split`·`wait_precheck`·`period_halve` 는 같은 날 뒤에 추가했다(8절). 셋 다 **모든 씨앗에 똑같이** 적용했다.

생성기 `build_rewrites.py`. 만들어진 변환은 전부 Explorer 파서를 통과했다(거부 0건).

## 3. 동등성 검증 — 여기가 옛 판과 결정적으로 다르다

변환본을 후보 파일로 써서 **E3 와 같은 동결 평가기**(`explorer/eval/frozen_contract.py`,
H=None, B5, 같은 caps, 같은 소스 snapshot)에 확정 IR 과 함께 태웠다. **EQUIV-FIXPOINT 가 나온
변환만 쌍으로 채택**한다. `verify_rewrites.py`.

결과: 생성 482개 중 **471개 EQUIV-FIXPOINT**, 11개 `DIVERGE_CONFIRMED`(전부 `else_split`), 미판정 0.
씨앗 217개, 쌍 471개.
기록은 `explorer/eval/results/fig2_rw_<유형>_20260916_{lineage,protocol,manifest}.json` 과 `_run/`.

즉 "행동이 같다"는 것이 judge 가 푸는 문제와 **독립된 절차**로 확인되어 있다. 옛 실험은 이걸
trace 한 줄 비교로 했다.

## 4. judge 호출

입력은 자연어 명령 + 프로그램({cron, period, script}) + JoI 언어 설명. 검증기 내부도, 확정 IR 도,
정답 코드도 주지 않는다. 출력은 마지막 줄의 `{"correct": true|false, "problem": "..."}`.
언어 설명 sha `ffa23b9b03a6bcc0`.

- **원본과 변환본은 각각 별개 호출**이다. 한 호출이 다른 호출을 보지 못한다.
- **identity**: 원본을 같은 프롬프트로 **3회** 부른다. 1회차가 판정, 2·3회차는 변환 없이 얼마나
  흔들리는지 재는 대조다. 유효 쌍 규칙은 변환 쌍과 동일하다.

| judge | 설정 |
|---|---|
| `Hyper-AI/Qwen3.5-9B-fp8` (로컬 vLLM) | thinking off, temperature 0, seed 0, 추론 예산 1500 + 답 300 |
| `gpt-5.4-mini-2026-03-17` (OpenAI) | reasoning_effort **low**, seed 42, max_completion_tokens 4096 |
| `claude-sonnet-5` (Anthropic) | adaptive thinking, effort **low**, max_tokens 4096 |

세 judge 는 서로 다른 급·다른 공급자다. 로컬 9B 는 temperature 0 이라 호출 간 변동이 거의 없고,
클라우드 두 개는 추론 모델이라 같은 입력에도 호출마다 달라질 수 있다. identity 열이 그 차이를 드러낸다.

**예산 강제(로컬 judge).** 9B 는 단계별 추론을 길게 써서 1500 토큰 안에 JSON 을 못 내는 일이 잦았다
(첫 시도에서 15% 가 `finish=length` 로 무판정). 상한을 올리는 대신 feedback 실험(`joi/self_feedback/repair_core.py`)
과 같은 방식을 쓴다: 예산을 다 쓰면 거기서 끊고, 끊긴 지점에 "예산을 다 썼으니 판정을 확정한다" 는
문장과 답의 시작(`{"correct":`)을 붙여 한 번 이어 부른다. 모델은 답만 완성하면 된다.
보고하는 출력 토큰은 **두 호출의 합**이며, 각 응답에 `forced` 와 예산·답 토큰을 따로 기록한다.
이 처리는 잘림을 무판정으로 버리지 않기 위한 것이고, 발동 비율은 결과에 함께 적는다.

한 행 안의 호출은 설정이 같아야 하므로, 설정을 바꾼 실행은 버리고 처음부터 다시 돌렸다.
버린 실행은 기록만 남긴다: `runs/gpt_medium_aborted/`(GPT `medium` 177건, 비용 때문에 `low` 로 전환),
`runs/qwen_1500_aborted/`(로컬 judge, 예산 강제 도입 전 313건).
`reasoning_effort` 최하값은 `none` 이지만 추론을 아예 끄면 judge 를 일부러 약하게 만든 것이 되어
`low` 를 썼다. Claude 도 같은 이유로 thinking 을 끄지 않고 effort 만 `low` 로 맞췄다.
세 judge 의 실제 추론 토큰 소비는 다르다(같은 `low` 라벨이 같은 추론량을 뜻하지 않는다). 실측치를
결과에 적는다.

## 5. 집계 — 3단계

1. **자기불일치.** 원본 217개 각각의 3회 판정이 **모두 같지 않으면** 1. 판정기별 비율. 조건이 없다.
2. **공통집합.** 세 판정기가 **모두** 3회 중 2회 이상 "맞다"고 한 원본만 남긴다 → **52개**
   (`aggregate.py` 의 `COMMON_MIN_ACCEPTS = 2`).
3. **재작성 뒤집힘.** 공통집합 원본의 재작성 **168쌍** 각각에 대해, 판정기가 "틀렸다"고 하면 1.
   원본을 안정적으로 통과시킨 뒤이므로 뒤집힘은 전부 통과→거부다. 띠별·유형별·전체 비율.

분모가 세 판정기에 공통이어서 표에 n 을 행마다 한 번만 적는다. 세 판정기가 함께 안정적으로 통과시킨
원본이라 "자연어가 애매해 거부했다"는 해석이 막힌다.

- 95% 구간은 **씨앗 프로그램 단위 bootstrap**(2,000 회 재표집). 같은 씨앗에서 나온 여러 변환을
  독립 표본으로 세지 않는다.
- 파싱 실패·오류는 공개하되(이번 실행은 세 판정기 모두 0건) 판정 수에서 뺀다.
- 보조 관점 두 개를 `results/RESULTS.md` 에 함께 남긴다: 판정기마다 자기 1회차 통과분을 분모로 삼는 관점,
  그리고 모든 쌍에서 방향 무관 뒤집힘. 원고 표는 공통집합 관점만 쓴다.

`aggregate.py` → `results/{summary.json, summary_common.json, RESULTS.md}`,
`render_table.py` → `results/{table1.tex, table1_preview.png}`. Figure 2 는 그리지 않는다
(`MOTIVATION_DRAW_FIG2=1` 일 때만, 옛 그림은 `results/superseded/`).

## 6. 결론의 한계 (원고에 그대로 반영할 것)

- 원본·재작성 모두 확정 IR 과 EQUIV 임이 따로 증명됐고 원본은 판정기가 안정적으로 통과시켰으므로,
  재작성 거부는 틀린 판정이다. 다만 버그 있는 프로그램을 잡아내는지는 재지 않았다.
- **공통집합은 217개 중 52개**다. 세 판정기가 함께 통과시킨, 자연어가 비교적 분명한 프로그램에 한정된다.
- 이 결과로 모든 LLM judge 가 원리적으로 배포 게이트에 못 쓴다고 주장하지 않는다. 검사한 judge·
  프로그램·변환·설정에 한정한다.
- 자기불일치가 있는 판정기(GPT·Claude)에서는 재작성 효과를 호출 변동과 분리할 수 없다. 그 경우 보고할 수
  있는 것은 "변환 없이도 판정이 재현되지 않는다"이다. Qwen 은 자기불일치 0 이라 분리가 필요 없다.
- 유형 칸은 3~39쌍이라 원고 표에는 띠만 싣는다.
- `period_halve` 는 표를 본 뒤 추가됐다(8절, 규칙 선커밋).
- 씨앗이 E3 와 같은 요청 집합에서 나온다. 본문에는 요청 집합만 밝히고 출처는 Evaluation 으로 링크한다.
