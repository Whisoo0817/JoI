# 코드 생성과 행동 검증

> 검토용 한글 번역. 같은 폴더의 `PerCom_version.md`를 기준으로 2026-09-17에 작성했다. 지금까지 수정한 표현을 반영했으며, 수식과 인용 표기는 유지했다.

그림 2처럼 LLM은 사용자가 확정한 Timeline IR과 기기 바인딩으로 후보 JoI 코드를 생성한다. 생성 코드가 조건이나 지연을 잘못 구현할 수 있으므로, Behavioral Explorer는 실행 모델에서 허용하는 모든 입력 이력에 대해 코드가 IR에 명시된 액션과 발생 시각을 보존하는지 검사한다. 아래에서는 두 실행을 비교하는 탐색 과정을 설명하고, 명제 S를 통해 동등성 검사를 완료했을 때 이 보장이 성립하는 이유를 제시한다.

## 두 실행을 함께 탐색하기

**공통 실행 모델.** Explorer는 각 인터프리터를 통해 IR과 생성 코드를 같은 입력값과 논리적 시각 아래에서 실행한다. 두 프로그램이 지원 범위에 속하는지 확인한 뒤, 읽는 값과 그 타입, 실행 규칙으로 공통 입력 모델을 구성한다. 허용되는 각 초기 설정에서 두 프로그램을 시작하고, 각자의 실행 상태를 따로 추적한다. 같은 행동을 구현하더라도 변수와 제어 흐름은 서로 다를 수 있기 때문이다.

**시간을 포함한 액션 비교.** Explorer는 각 실행 시각에 IR과 생성 코드가 내는 액션을 비교하며, 대상 기기, 호출 메서드, 인자, 발생 횟수와 순서가 같은지 확인한다. 하나의 호출이 여러 독립적인 기기에 액션을 전달하는 경우, 그 기기들 사이의 순서는 달라도 허용한다. 숫자 인자는 값으로 비교하며, 불리언과 문자열은 별개의 타입으로 구분한다. 이 트레이스 비교는 불필요하게 추가된 액션과 누락된 액션을 모두 찾아낸다. 한쪽에서 액션이 발생했는데 다른 쪽에서는 아무 액션도 발생하지 않았다면, 나중에 두 실행이 같은 기기 상태에 도달하더라도 불일치로 판단한다. 한쪽 프로그램이 종료되면 이후에는 액션을 내지 않는 것으로 처리하고, 다른 쪽의 실행은 계속 검사한다.

**입력과 시간.** 가능한 입력 이력을 빠짐없이 검사하기 위해, Explorer는 개별 값을 검사하거나 값들의 집합을 기호식으로 표현한다. 입력을 묶을 때는 나중에 계산에 쓰이는 저장값을 포함해 이후 액션과 발생 시각을 보존해야 한다. 5절의 시간 규칙에 따라, 구체적인 값을 사용하는 탐색은 다음 입력 변경 가능 시각, 타이머 만료 시각, 관련 시계 값의 변경 시각 중 가장 이른 시각으로 진행한다. 두 프로그램 모두 중간 입력 갱신을 관찰하거나 이후 행동에 영향을 주는 상태를 바꿀 수 없을 때만 그 갱신을 건너뛰며, 재개 시점에는 가능한 모든 입력값을 포함한다.

**알고리즘 1. 행동 탐색 개요.**

```text
IR–코드 쌍과 실행 모델을 준비한다. 지원하지 않으면 UNCERTIFIED를 반환한다.
자원 한도 안에서 적용 가능한 각 검사 방식에 대해:
    허용되는 모든 초기 설정으로 탐색할 상태를 초기화한다.
    탐색할 상태가 남아 있고 자원 한도가 허용하는 동안:
        상태와 가능한 입력을 선택한다.
        공통 입력 및 시간 규칙에 따라 두 프로그램을 진행시킨다.
        고려하는 모든 경우에서 액션과 발생 시각을 비교한다.
        불일치 가능성이 발견되면:
            구체적인 입력으로 재실행하여 확인되면 DIVERGENT(불일치)를 반환한다.
            확인되지 않으면 동등 판정 없이 해당 검사 방식을 중단한다.
        아직 검사해야 할 모든 후속 실행을 탐색 목록에 추가한다.
    검사 완료 조건을 충족한 경우에만 EQUIVALENT(동등)를 반환한다.
UNCERTIFIED(미확정)를 반환한다.
```

## 검사 완료와 건전성

Explorer를 배포 전 검사에 사용하는 근거로, 동등성 검사를 완료했을 때 무엇이 보장되는지 제시한다. 검사를 완료하려면 허용되는 모든 초기 설정과 입력을 포함하고, 액션의 일치를 확인하며, 탐색한 상태에서 이어지는 모든 후속 실행을 포함해야 한다. 지원되는 프로그램이 한 번 실행된 뒤 종료되는 경우에는 기호 기반 검사로 가능한 모든 실행 경로를 확인하여 검사를 완료할 수도 있다. 자원 한도에 도달했거나 일정 기간만 검사한 것으로는 충분하지 않다.

\(I,C\)는 5절의 실행 모델 \(M\) 아래에서 준비된 IR과 코드, \(G_0\)는 허용되는 전역 변수 초기 설정, \(\mathcal U_M\)은 허용되는 입력 이력의 집합이다. 적용 가능한 검사 방식이 위의 완료 조건을 충족하고, 실행 기간을 제한하지 않은 채 EQUIVALENT를 반환하면 이를 \(\operatorname{Accept}_{\infty}(I,C,M)\)으로 표기한다.

**명제 S — 건전성.** 지원 범위에 속하며 준비를 마친 IR–코드 쌍에 대해, 명시된 실행 및 관찰 규칙 아래에서 다음이 성립한다.

\[
\begin{aligned}
&\operatorname{Accept}_{\infty}(I,C,M)\\
&\quad\Longrightarrow\ \forall g_0\in G_0,\ \forall u\in\mathcal U_M:\\
&\qquad\operatorname{Tr}_M(I;g_0,u)
 =_O \operatorname{Tr}_M(C;g_0,u).
\end{aligned}
\]

여기서 \(=_O\)는 앞서 설명한 비교 규칙에 따라 액션과 발생 시각이 같다는 뜻이다. 이 보장은 5절의 정상 실행 및 시간 진행 조건을 따른다. 오류나 실행 한도 도달을 정상 종료로 처리하지 않는다.

**증명 개요.** 허용되는 초기 설정 \(g_0\)와 입력 이력 \(u\)를 고정하자. 탐색에는 그 초기 상태가 포함된다. 각 비교에서는 고려하는 모든 실행의 액션과 발생 시각을 검사한다. 입력을 묶거나 상태를 재사용하거나 시간을 건너뛰어도 가능한 모든 후속 실행과 관찰되는 행동이 보존된다. 검사가 완료되면 모든 후속 실행이 포함되어 있다. 따라서 시작부터 이후의 각 비교 시점까지 일치가 이어지며, 귀납법에 따라 트레이스의 모든 유한한 앞부분이 일치한다. 정상 실행 및 시간 진행 조건에 따라 이 일치는 전체 트레이스로 확장된다. 명제 D는 기준이 되는 IR 실행의 유일성을 보장한다.

이 보장은 명시된 실행 모델에 적용되며, 파싱과 의미 해석, 솔버 결과가 올바르다는 가정에 의존한다. 확정된 IR이 사용자의 의도와 일치하거나 실제 기기가 모델대로 동작함을 입증하는 것은 아니다.

**반례를 이용한 피드백.** 불일치가 확인되면 초기 환경, 시간 정보가 포함된 입력 이력, 기대 액션과 실제 액션을 반환한다. LLM은 이 정보를 사용해 코드를 수정할 수 있으며, 수정한 코드는 기존 IR과 기기 바인딩을 그대로 기준으로 삼아 다시 검사한다.

**구현.** VETS는 JoI를 대상으로 Python으로 구현했으며, 산술 추론에는 Z3를 사용한다. 검증에는 IR과 JoI 의미 실행기를 사용하고, LLM을 호출하거나 실제 기기를 작동시키지 않는다. 건전성 논증은 수작업 증명이며, 구현을 기계적으로 검증한 것은 아니다.
