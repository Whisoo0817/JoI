# 한계 및 향후 과제

VETS는 선언된 실행 모델 안에서 생성 코드가 확정된 Timeline IR의 행동과 발생 시각을 보존하는지 검사한다. IR이 사용자의 의도를 정확히 담았는지, 사용자가 IR을 올바르게 이해했는지는 보장하지 않는다. 실행 모델에 포함되지 않은 실제 기기의 동작과 네트워크 영향도 평가하지 않았다. 이 부분은 사용자 연구와 실제 배포 환경에서의 연구로 확인해야 한다.

현재 구현은 JoI를 지원하며 한 번에 하나의 자동화를 검사한다. Timeline IR로 표현할 수 있는 동작 중에도 Explorer가 지원하는 연산이나 탐색 자원 한도를 벗어나는 경우가 있다. 이런 경우는 미확정으로 남긴다. 다른 플랫폼을 지원하고 자동화 간 상호작용을 검사하는 것은 향후 과제다. Timeline IR을 JoI 코드로 직접 변환하는 컴파일러도 가능한 설계다. 현재의 LLM 기반 생성 방식과는 비교하지 않았으며, 두 방식을 비교하면 각각 어떤 상황에 유용한지 평가할 수 있다.

평가에도 한계가 있다. E1은 기록한 해석과 기대 트레이스에 의존하며, 모두가 독립적인 검토를 받은 것은 아니다. E2는 별도로 구현한 기준 실행기를 사용하지만, 유한한 입력 이력에서의 일치만으로 모든 입력에 대한 정확성을 입증하거나 두 구현이 따르는 언어 명세 자체의 오류를 배제할 수는 없다. E3는 우리가 JoI용으로 구성한 명령어를 사용했고, E4는 하나의 프로그램 틀을 변형했다. 따라서 이 결과만으로 다른 요청 집합이나 프로그램 구조에서의 성능을 보장할 수 없다. 독립적으로 검토한 요청, 다른 코드 생성기, 더 다양한 자동화 구조를 포함하는 평가가 필요하다.
