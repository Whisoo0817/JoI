# Limitations and Future Work

VETS checks whether generated code preserves the actions and timing of a confirmed Timeline IR under the declared execution model. It does not establish whether the IR captures the user's intent or whether the user understood it correctly. Physical device behavior and network effects outside that model are also untested. User studies and deployment studies are needed to assess these aspects.

The current implementation supports JoI and checks one automation at a time. Some behaviors expressible in Timeline IR remain beyond Explorer's supported operations or available search budget. Such cases remain undecided. Extending support to other platforms and checking interactions among automations are future directions. A compiler that translates Timeline IR directly into JoI code is another possible design. We have not compared it with the current LLM-based generation approach; that comparison would help assess when each approach is useful.

The evaluation also has limits. E1 depends on recorded interpretations and expected traces, not all of which received independent review. E2 uses separately implemented reference interpreters, but agreement on finite test histories cannot establish correctness for all inputs or rule out errors in the shared language specifications. E3 uses commands we constructed for JoI, and E4 varies one program template. These results therefore do not establish performance across other request populations or program structures. Broader evaluation should include independently reviewed requests, other code generators, and more varied automation structures.
