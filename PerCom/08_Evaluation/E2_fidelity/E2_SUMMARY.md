# E2 요약 — 검증 판정의 신뢰성 (2026-09-14)

E2 는 **"Explorer 가 내린 판정을 믿어도 되는가"** 를 독립 정답기로 확인한 실험이다.
이 문서는 개발 기록(동결판 → 보강 이력 → 바인딩 계약 → 탐색 최적화)과 최종 결과를 한곳에 모은다.
표 원본은 `RESULTS.md`(`make_e2_results.py` 생성), 쌍별 확인은 `INSPECTION_2026-09-14.md`, 원고 계획은 `E2_WRITING_PLAN.md` §0.
**모든 수치는 140쌍 모집단 기준이다.**

## 1. 설정

- **모집단 140쌍** (`handoff_timer/e2_population.json`, whisoo 결정 2026-09-14)
  - 동결 142쌍(`649cb9c`)에서 입력 오류 2쌍을 뺐다: `C03_008/llm`(ACTION 위치 `any(...)` = 구문 오류),
    `C20_011/llm`(TV 에 없는 Charger 를 읽는 잘못된 service mapping). 실행 파일의 142행은 그대로 둔다.
  - E1 요구 20개에서 직접 만든 쌍 102개: 올바른 쌍 21 + 오류 쌍 81 (12개 오류 계열).
  - 388 데이터셋에서 Explorer 판정과 무관하게 무작위로 뽑은 LLM 후보 40개 중 유효 입력 38개.
- **독립 정답기** (`reference/`): Explorer 코드를 본 적 없는 별도 에이전트가 명세 문서만 보고 작성한 IR·JoI 실행기.
  읽은 파일 기록(`READ_LOG.md`)과 import 검사(`test_independence.py`)가 있다. E1 기대 결과 41/41·12/12, JoI probe 15/15 일치.
- **이력** (140쌍 기준): 원래 이력 11,263개 + 보강 이력 37,727개(PROTOCOL §9, 정답기 실행 전에 규칙·이력 커밋) = 48,990개.
- **Explorer 예산**: 쌍당 120 초, 상태 400,000, 전이 2,000,000.
- **R14 미초기화 변수 산술** (whisoo 결정 2026-09-16, `RUNTIME_CONTRACT.md`): 한 번도 대입되지 않은 변수를
  산술에 쓰면 runtime error다. 인스턴스는 거기서 멈추고 그 멈춤 자체가 관찰 대상이다. 두 도구 모두 이 규칙으로
  고쳤다. 140쌍 중 이 규칙에 닿을 수 있는 코드는 C24_003 하나뿐이다(142쌍 전체 definite-assignment 검사).
- 판정 범주: EQUIV / DIVERGE(구체 재생으로 확인된 반례) / REFUSED / TIMEOUT. 거절·시간 초과는 분모에 남긴다.

- **바인딩 계약은 평가 계약 결정이다.** Explorer 개선 수치에 넣지 않는다(140쌍 기준 판정 수는 104 그대로).
- **Explorer 개선 = 탐색 최적화.** 같은 예산에서 판정 104 → 130(+26). 기존 104개 판정 변화 0, 남은 미판정 10.

### 2.1 확인 중 드러난 문제와 처리 (시간 순)
1. **정답기 이력의 약점**: 시작 상태가 사실상 하나, 선택형 입력(버튼·모드)을 바꾸지 않음.
   → 보강 이력(시작 상태 조합, 상한 없는 펄스)을 결과 보기 전에 규칙으로 고정해 추가. llm 5쌍을 정답기도 잡게 됐다.
   E1-086 f2·f4 는 유일한 시작 이력이 301 초에 끝나 이력으로는 닿지 않고 반례로만 확인된다.
2. **None 순서 비교**: 명세 공백. whisoo 결정으로 false. 동결판·현재판 두 판 모두 보고.
3. **바인딩·셀렉터 차이** (whisoo 결정, `BINDING_DECISION_2026-09-14.md`): E2 는 시간·상태·로직만 본다.
   - B1: JoI 셀렉터는 IR 바인딩 기기로. B2: 한 바인딩 자리 안에서 나뉜 같은 호출은 한 묶음(중복 호출은 여전히 다름).
   - B5: 한 서비스에 자리가 여럿이면 맞는 셀렉터 배정이 하나라도 있으면 같다.
   - IR 에 따로 적힌 호출의 순서는 지킨다. E1-086/fault3(다른 밸브 Close 순서 뒤집기)은 B5 로 EQUIV 가 되며 whisoo 가 받아들였다.
   - 기기 지목만 다른 오류 쌍 C16/fault1, E1-062/fault3, E1-086/fault3 은 두 도구 모두 EQUIV 이고, "관찰된 차이가 있는 오류" 에 들어가지 않는다.
   - 사전 측정: 22쌍의 모든 배정을 돌려 로직 오류 11쌍은 모든 배정에서 DIVERGE 임을 확인(E1-086 f2 는 1,024 배정).
4. **한도 초과 19쌍**: C20-O 로 원인을 좁혔다(JoI 틱 카운터 + IR 의 빈 동작 자리 `_noop` 시계 읽기). 탐색 최적화를 Codex 에 인계.
5. **부하 영향**: 동시 실행 중 C05 f2·f3 이 시간 초과. 조용할 때 다시 돌려 상태 한도 거절로 기록(부하 결과도 보존).
6. **C03_008**: `0e76584` 에서 바인딩된 서비스의 `any(...)` 동작 호출을 허용했으나, whisoo 결정(09-14)으로 되돌렸다.
   `any` 는 조건문 안에서만 쓸 수 있고 ACTION·대입·인자 위치는 구문 오류다. Explorer 파서와 정답기 모두 거절한다.
   모집단에서 제외(142쌍 JoI 전체를 새 파서로 검사해 이 규칙에 걸리는 쌍은 C03_008 하나뿐).

## 5. 정직하게 적을 한계

- **정답기 "같음" 은 증명이 아니다.** 만든 이력(원래 + 보강) 안에서 차이가 없다는 뜻이다. 8쌍은 반례로만 확인된다.
- **독립성은 코드·작성자 수준이다.** 같은 명세를 따르므로 명세 자체의 오류는 못 잡는다. 두 도구 모두 같은 모델 계열이 작성했다.
- **탐색 최적화는 E2 의 미판정 결과가 나온 뒤 적용했다.** 같은 예산이고, 기존 104개 판정은 바뀌지 않았으며, 새 판정 26개는
  모두 정답기와 일치한다(새 반례는 모두 정답기에 재생). 동결판 결과는 그대로 보존했다.
- **오류 쌍은 독립 표본이 아니다.** 한 요구에서 5쌍씩 나오므로 신뢰구간을 붙이지 않는다. LLM 표본은 38개다.
- **R14 는 이 쌍을 보고 정한 규칙이다.** C24_003 의 `n + 1`(미초기화 `n`)을 어떻게 볼지 명세에 없어서, 그 쌍을
  본 뒤 2026-09-16 에 계약으로 정했다. 0 으로 때우는 쪽 대신 오류를 택한 이유는 초기화 누락이 동치 판정에서
  사라지지 않게 하기 위해서다. 결과로 이 쌍은 "정답기가 실행 못 함"에서 "정답기가 확인한 DIVERGE"로 바뀌었고,
  Explorer 의 판정(DIVERGE)은 규칙 전후로 같다. 다른 쌍의 수치는 하나도 움직이지 않았다(정답기 A/B 재실행으로 확인).
- **바인딩은 별도 평가 계약이다.** 기기 지목만 다른 오류 3쌍은 판정에서 빠진 것이 아니라 계약에 따라 같다고 본 것이다.
