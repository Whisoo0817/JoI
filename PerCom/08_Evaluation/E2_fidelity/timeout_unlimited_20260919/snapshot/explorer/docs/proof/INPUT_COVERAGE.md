# 자동 입력 추론의 포괄성과 ACTION 보존

후속 승인된 [SMT 산술 경로](SMT_VERIFICATION.md)는 입력별 대표값 대신 전체 숫자
도메인의 기호를 사용한다. catalog bounds·0.1 격자·int/float·signed zero·None을
보존하고 읽은 epoch마다 독립 기호를 만든다. 아래 1차원 분할 논증을 결합식에
적용하지 않는다. 명시 유한 domain은 새 경로로 자동 확대하지 않는다.

최신 입력 계약 추가: `menu-string-return-v1`의 MenuProvider.GetMenu와
`chat-string-return-v1`의 CloudServiceProvider.ChatWithAI는 None 없는 STRING으로
선언한다(빈 문자열 허용). 아래 일반 비BOOL 결측 설명에는 이 예외가 적용된다.
ChatWithAI는 변형 없는 STRING identity 전달만 기호 인증하며 문자열 변환을
추가로 가정하지 않는다. 구체 대표값과 기호 도메인 모두 같은 반환 명세를 사용한다.

2026-09-07. 대상은 `input_coverage.py`와 이를 사용하는 `derive_axes`,
`compile_ir`, `merge_axes`, `timed_product`다. **아래에 정의한 입력 모델과
지원 AST에 대한 수학적 논증**이다. 기계 검증 증명이나 실세계 센서 타입의
추론 정확성, JoI 서버 구현의 적합성 증명은 아니다.
[탐색 정리](SEARCH_CORRECTNESS.md)의 입력 추상화 연결 의무를 다룬다.

**서비스 연결 후 갱신:** 기본 gate는 이제 [SERVICE_MODEL.md](../model/SERVICE_MODEL.md)의
실제 타입·범위·ENUM에서 공동 술어 대표값을 다시 만든다. 아래 모델 계열은
bare runner/명시 synthetic fixture 및 별도 GV 모델의 기초 논증으로 남는다.
actual-catalog 경로가 센서 타입을 후보 조건식에서 추정하는 것은 아니다.
현재 catalog BOOL/BOOLEAN 센서·조회 반환과 clock.isholiday의 도메인은
**{false,true}**다(`strict-two-valued-v1`). 아래 untyped/synthetic/GV 계열의
None을 실제 BOOL 입력의 허용값으로 읽지 않는다. 비BOOL nullable·0.1 정밀도는
정의한 모델 계약이고 초기 GV는 별도로 평가 모델에 선언한다.
실제 runtime 일치는 현재 모델 내 검증의 필수 전제가 아니다. 모델 밖의
실세계 입력까지 포괄한다는 주장과 구별한다. 최신 연결은 INTERNAL_SEMANTICS.md를 따른다.

추가 코드 검토 및 bounded 정리의 전제 대응은
[PROOF_OBLIGATIONS.md](PROOF_OBLIGATIONS.md)에 정리했다. catalog DOUBLE의
원값 전수 열거는 float와 signed zero뿐 아니라 허용 int 표현까지 포함한다.
조건 전용 분할에서는 같던 1/1.0도 관찰 문자열에서는 다를 수 있다.

**기호 경로 추가:** 큰 exact 도메인과 일반 STRING 때문에 자동 열거가 거절되는
순차 one-shot은 [SYMBOLIC_VALUE_FLOW.md](SYMBOLIC_VALUE_FLOW.md)의 보편 값 흐름
인증을 시도한다. `(입력 key, 입력 epoch)` 기호를 보존하므로 출력용 원값을 대표
숫자 하나로 바꾸지 않는다. 명시 유한 도메인·조건 분할·기존 BFS는 그대로다.

## 1. 입력 모델을 먼저 고정한다

IR에는 센서의 type/domain 선언이 없다. 따라서 `x > 10`을 읽었다고 실제
장치가 반드시 숫자를 반환한다는 사실이 증명되지는 않는다. 자동 추론은
다음 **제안된 모델**에서 대표값을 구성한다. 결과의 `input domain families`
기록과 평가 manifest에 이 전제를 남기고, 실제 도메인이 다르면 외부 선언을
사용한다. 후보 코드에 맞춰 실세계 타입을 확인했다고 주장하지 않는다.

| 자동 모델 계열 | 허용 원래 값 U | 선택 기준 |
| --- | --- | --- |
| `numeric` | None, bool, 모든 정수, 유한 float 중 십진 표기가 0.1의 배수인 값 | 숫자와의 순서 비교가 있음; 문자열 비교 상수는 없음 |
| `string` | None과 모든 유한 Python 문자열 | 문자열과의 순서 비교가 있음; 숫자/bool 비교 상수는 없음 |
| `scalar` | 위 두 계열의 합집합 | equality/inequality/truthiness만 사용 |
| `explicit` | 외부에서 선언한 유한 값 목록 전체 | 아래의 축소 불가능한 사용 또는 자동 경계 범위 초과 |

`None`은 결측을 나타낸다. 순서 비교의 None 결과는 양쪽 모델 실행기에서
false다. bool은 Python 수치 비교에서 0/1과 같게 비교되지만, 저장소/명시
도메인에서는 타입을 잃지 않는다. 문자열 정렬은 Python의 유한 문자열
사전식 순서다. 이를 실제 센서/서비스의 정렬·결측 정책으로 일반화하지 않는다.

숫자와 문자열의 순서 비교 혼합, 숫자 순서 비교와 문자열 equality 혼합 등은
**명시 도메인 요구**다. 예를 들어 기준의 `x == "on"`에 후보가 `x > 10`을
추가해 기준의 문자열 입력을 조용히 제외할 수 없다. 선언한 혼합 도메인에서
구체 실행이 타입 오류를 내면 성공 판정이 되지 않는다. IR과 JoI 실행기의
잘못된 타입에 대한 동작이 같다고 가정하지 않는다.

자동 수치 비교 상수의 절댓값은 10¹² 이하로 제한한다. 이는 센서 입력값의
범위 제한이 아니라 **현재 float 대표값 생성 구현의 증명 범위**다. 상수가
범위 밖이면 명시 입력 도메인을 요구하고, 그 경로에서는 큰 정수도 전량
열거한다. 입력값 자체가 이 범위 밖인 경우에는 해당 방향의 꼬리 구간에
속한다. ACTION/문자열/산술로 원래 값을 구별할 수 있으면 이 축소를 쓰지 않는다.

외부 입력은 합의한 기본 100ms 격자마다 모든 축의 Cartesian product에서
임의로 선택한다. 중간 시각은 입력 유지, timer는 정확한 1ms 해상도로
처리한다. binding/inventory는 고정이다. 초기 환경과 내부 GV도 전량 포함한다.

## 2. 출처와 사용 조건 수집

`Coverage.predicates[k]`는 입력 k에 적용될 수 있는 모든 단항 비교와
truthiness의 목록이다. `exact`는 대표값 치환 없이 명시 값 전체를 사용해야
하는 출처다. `writes`는 해당 프로그램이 쓸 수 있는 GV 이름이다.

JoI 변환은 리터럴, 외부 읽기, 변수, bool 결과 연산, 그 밖 계산으로 구분한다.
다음 정보를 제어 경로와 무관하게 모은다.

- `=`와 `:=`를 포함한 모든 변수 정의, 모든 if/else/loop 내부 정의.
- if/wait/loop의 조건과, 변수 대입 안에 저장된 bool 조건.
- ACTION 인자, 표현식 위치 GV set의 값까지 포함한 모든 GV 쓰기.
- 리터럴 인자의 query 결과. 인자별 키와 인자의 타입을 보존한다.
- 내부 GV 읽기의 가능한 초기값과 모든 쓰기 값의 출처.

IR 변환은 최종 명령열 전체의 READ/CALL 결과 정의를 합집합으로 모은다.
조건 앞뒤나 여러 분기에 있는 같은 이름의 정의를 빠뜨리지 않는다. CALL
인자와 템플릿에 들어가는 읽기도 포함한다. 현재 IR에는 일반 대입이나
병렬 분기가 없으며 새 문법을 가정하지 않는다.

변수의 출처는 정의 그래프를 순회해 얻는다. **깊이 4 같은 절단은 없다.**
이미 방문한 이름은 다시 확장하지 않는다. 어떤 외부 읽기에 도달하는 경로가
있다면 cycle을 제거한 단순 경로도 있으므로 이 방문 처리가 출처를 잃지
않는다. 실제 값의 유한한 대입 이력도 이 그래프의 경로이며, 미초기화 값은
None이다. 여러 정의를 모두 넣는 것은 가능한 출처를 늘리는 보수적 처리다.

`leaves`는 복사 경로의 각 가능한 읽기/상수를 보존하고, bool 결과는
{False, True}, 미초기화는 None으로 다룬다. 비교의 양쪽 가능한 잎의 곱을
검사한다. 읽기와 상수 사이 비교는 해당 입력의 술어로 추가한다. raw 읽기
사이 관계나 분할로 보존되지 않는 계산에 관여하는 출처는 `exact`로 보낸다.
모든 정의의 내부 식도 방문하므로 bool 변수로 감춘 조건이 누락되지 않는다.

### 출처 포괄성 보조정리

지원 AST의 구체 실행 중 외부 값을 읽어 변수/GV에 복사하거나 조건·계산·
ACTION에 사용했다면 그 읽기는 수집된 출처에 속한다.

증명: 직접 읽기는 변환의 잎 규칙으로 포함된다. 복사는 해당 정의의 출처를
따르고, 합성식은 자식 출처의 합집합을 따른다. 실행 중 선택된 분기와 정의는
정적 합집합 안에 있다. 대입 이력 길이에 대한 귀납으로 모든 보존 값의 출처가
포함된다. cycle의 경우에도 위의 단순 경로 논증으로 최초 외부 읽기나
초기값까지의 출처를 얻는다. IR은 정의가 READ와 결과 CALL뿐이므로 같은
논증의 더 작은 경우다. 검출하지 못하는 AST 종류는 오류를 기록해 거절한다.

### Query 경계

자동 수집이 인증하는 query는 리터럴 인자만 갖는다. `q(1)`과 `q(1.0)`은
런타임이 repr 기반 키를 사용하므로 다른 키다. IR에서 float 인자를 int로
바꾸던 처리를 제거했다. 인자 없는 query는 property 대응의 기본 키를 쓴다.
선언된 모델에는 해당 query 축이 있어야 하므로 미제공 답의 OpaqueToken에
의존해 포괄성을 주장하지 않는다.

변수 인자 query는 현재 추가 거절한다. 이전 `_loop_ranges`의 최솟값/상한
휴리스틱만으로 모든 실제 query 인자가 그 범위에 든다는 증명을 대신하지
않는다. 이것은 지원의 보수적 축소다. 리터럴로 grounding된 경우는 지원한다.
원래 D7의 joint/derived/observable-counter 거절도 계속 적용한다. `arith-arg`는
모든 출처가 exact이고 명시 또는 catalog 유한 domain의 모든 값이 실제 product에
주입되는 경우에만 해제한다. 따라서 action catalog 검증까지 모든 조합에서 실행되며,
일부 대표값만 일치해서 생기는 거짓 EQUIV는 없다. 조건을 하나라도 못 채우면 거절한다.
`:=` 초기화 안의 산술이 이 검사를 우회하지 못하도록 정의 요약도 보완했다.

## 3. 스칼라 입력의 분할

각 입력 k의 전체 술어 집합을 Pₖ라 하고, x의 진리벡터를
Vₖ(x)=(p(x))ₚ∈Pₖ라 한다. x∼ₖy iff Vₖ(x)=Vₖ(y)로 정의한다.
대표값 생성은 각 비어 있지 않은 동치류에서 하나를 남긴다.

### 수치값

각 비교 상수 c에서 실제 저장된 수치의 정확한 유리수 표현을 이용해
b=⌊10c⌋를 구하고 (b−1)/10, b/10, (b+1)/10을 후보에 넣는다. 0과 1도
포함한다. bool 상수와 truthiness의 0 경계도 보존된다.

실수선에서 단항 비교의 진리값은 상수에서만 변한다. 연속된 비교 상수 사이의
비어 있지 않은 0.1 격자 구간에는 경계에 가장 가까운 격자점이 있고, 위의
후보가 이를 포함한다. 상수 자신이 표현 가능한 격자점이면 equality 셀도
포함한다. 양쪽 무한 꼬리도 최외곽 상수의 인접점이 대표한다.

구현이 사용하는 float에서 c와 후보의 절댓값이 약 10¹² 이내이면 인접 float
간격은 0.1보다 작으며, 인접한 십진 0.1 값의 반올림은 순서를 보존하고 서로
겹치지 않는다. `Fraction(c)`로 경계를 계산하므로 문자열로 반올림한 c를
사용하는 가정도 없다. 경계가 반올림된 격자점과 정확히 같은 경우는 그 점이
후보에 포함된다. 이 범위 밖 입력은 모든 유한 경계의 같은 방향 꼬리이므로
추가 진리벡터를 만들지 않는다. 큰 비교 상수는 이 구현 논증에 포함하지 않고
명시 도메인을 요구한다.

### 문자열

유한 문자열 사전식 순서에서 최소 원소는 빈 문자열이다. 문자열 s의 바로
다음 원소는 `s + NUL`이다. 상수 문자열들과 각 상수의 바로 다음 원소,
빈 문자열과 NUL을 후보로 잡는다. 두 인접 상수 사이에 문자열이 있다면
작은 쪽의 바로 다음 원소가 그 구간 안에 있다. equality 점과 양쪽 비어 있지
않은 꼬리도 포함된다. 따라서 `"a" < x < "b"`의 `"a" + NUL` 같은 대표가
빠지지 않는다. `"__other__"`를 예약 센티널로 쓰지 않으므로 같은 이름의
실제 문자열 상수와 충돌하지 않는다.

### 결측·타입 혼합·합성

None은 별도 후보다. 모델이 허용하는 bool/숫자/문자열 후보를 모두 모은 뒤
**전체 술어의 진리벡터**로만 병합한다. 숫자 사전 뒤에 문자열 사전을
덮어쓰지 않는다. equality만 있는 scalar 모델에서도 bool 0/1, 나머지 숫자,
빈/비어 있지 않은 문자열, 문자열 상수, None에 대한 모든 벡터를 얻는다.

쌍 비교에서는 두 프로그램의 술어를 먼저 합친 뒤 대표값을 다시 생성한다.
따라서 각자 만든 대표값 집합을 단순히 합칠 때 누락될 수 있는 중간 영역도
포함한다. bool 합성은 원자의 진리값이 같으면 같은 결과를 낸다.

## 4. ACTION과 미래 상태의 보존

`exact`에 속하는 입력은 외부에서 선언한 유한 목록의 모든 원소를 그대로
사용한다. ACTION 인자에 이르는 출처는 계산·문자열 변환 전후를 가리지 않고
이 집합에 넣는다. 따라서 `speak(x)`와 `speak("" + x)`에 대해 guard의
진리벡터만 같은 값을 서로 치환하지 않는다. 1/1.0, bool/number, signed zero
구분도 명시 열거와 구체 저장소 키에 유지한다.

축소 가능한 입력 x는 같은 진리벡터의 대표 ρₖ(x)로 치환한다. 이 값이 복사된
변수/GV도 해당 출처의 관계로 연결하고, bool 계산 결과·상수·제어 위치·타이머는
정확히 같게 연결한다. raw 값끼리 비교하거나 그 값으로 계산하는 경우에는
관련 출처가 exact이므로 해당 값이 정확히 같다. raw 값과 상수/bool 결과를
비교하는 경우에는 수집된 술어의 진리값이 같아서 조건이 보존된다.

따라서 한 실행 문장을 처리하면 같은 분기를 선택하고, 같은 차단 위치와
타이머를 만들고, 같은 ACTION을 낸다. 대입은 위의 저장소 관계를 유지한다.
문장 실행에 대한 귀납, 차단 재개/반복 회차에 대한 귀납으로 모든 유한
입력 이력의 timed ACTION trace가 보존된다. 이 논증은 검색에서 raw 저장소를
강제로 병합하라는 뜻이 아니다. 검색은 대표 입력 실행의 구체 저장소를
계속 구분하며, 임의 원래 입력 실행과 대표 실행 사이의 관계를 증명한다.

## 5. 초기 GV와 프로그램 쌍

쌍 중 하나라도 쓰는 GV는 외부에서 매 입력 시각 덮어쓰는 축으로 취급하지
않는다. 양쪽이 공유하는 초기 선택 I의 축으로 이동한 뒤 각 프로그램의
내부 저장소에서 독립적으로 전개한다. 쓰기 없는 GV는 외부 입력 축이다.
실행 중 binding을 바꾸거나 두 시나리오의 상호작용을 추가한 것이 아니다.

초기 GV의 가능한 값도 같은 술어 분할로 대표하거나, ACTION으로 흐르면
명시 초기 도메인을 요구한다. 이제 초기값을 임의로 {None, False, True}로
고정하지 않는다. 명시 선언에 필요한 초기 키가 빠지면 거절한다. 내부 GV를
`@gv:name` 외부 축으로 다시 넣어 초기 상태 검사를 우회하는 것도 거절한다.

## 6. 입력 포괄성과 BFS 판정 연결 정리

전제: (a) 위의 입력 계열 또는 명시 유한 도메인이 검증 대상 모델로 고정되어
있다. (b) grounding된 AST/최종 IR 명령열이 입력 인증과 기존 지원 검사를
통과한다. (c) [SEARCH_CORRECTNESS.md](SEARCH_CORRECTNESS.md)의 반응 함수와
타이머/상태 키 전제를 만족한다.

이때 모델의 임의 초기 상태와 임의 입력 이력 u에 대해, 모든 초기/매 시각
입력의 성분을 ρ로 치환한 이력 ρ(u)가 존재한다. §3에서 모든 성분에 대표가
있고, §2·§4·§5에서 두 프로그램 각각의 원래/대표 timed ACTION이 같다.
탐색 정리의 BFS는 초기 곱과 매 입력 시각의 전체 곱을 검사하므로 ρ(u)를
포괄한다. 따라서 대표 탐색에서 동치가 성립하면 원래 U의 모든 허용 초기
상태와 입력 이력에서도 해당 시간 범위의 ACTION 동치가 성립한다.

대표는 모두 허용되는 구체 값이다. 따라서 대표 이력에서 발견한 DIVERGE도
실제 모델 안의 반례이며 저장된 초기값/시간/입력을 재생할 수 있다.
H가 있으면 닫힌 구간 [t₀,t₀+H]의 bounded 정리, 없고 몫 그래프가 닫히면
fixpoint 정리와 연결된다. cap/실행 오류/미인증 입력은 동치가 아니다.

## 7. 구현 검증과 남은 경계

`tests/test_input_coverage.py`는 독립 기대 ACTION과 직접 계산한 진리벡터로
검사한다. 숫자/문자열 연산자 쌍, 가까운 경계, None, 타입 혼합, 센티널 충돌,
40단계 복사, 다중/cyclic 정의, := 산술 거절, 숫자 GV, 초기 GV 소유권,
query 인자 타입/출처, 모델 범위 기록을 포함한다. 두 검색기의 일치만으로
입력 추론의 공통 오류를 배제하지 않는다.

기존 IR selfcheck의 flag 예제는 None에서 재무장하지 못했고, sustain 예제는
None에서 timer를 취소하지 못했다. 새 모델에서 올바른 예제가 되도록 각각
`not(t > 25)`와 `m != false`로 수정했다. 기존 오류 패턴의 반례는 별도 손
trace 회귀에 보존했다. 이는 결측을 넣었을 때 새로 검출한 행동 차이다.

남은 전제는 실제 센서/서비스 도메인의 근거, 파서/grounding이 사용자가
확정한 명세를 정확히 나타내는지, 구체 실행기의 전체 결정론성/실제 JoI
적합성이다. 입력 논증 자체로 이 의무가 완료되지는 않는다. 리터럴 밖 query
지원 확대, 더 큰 자동 수치 경계의 인증도 현재 범위에 포함하지 않는다.
