## 보장 범위

논문용 명제의 정의와 전제는 아래와 같이 확정한다. 경로별 세부 논증과 공통 귀납은
[통합 정리](../proof/PROOF_OBLIGATIONS.md#통합-정리의-도출)에 연결한다. 증명의 수준과 신뢰 기반은
그 문서에서 구별하고, 작업 완료 여부는 README를 따른다.

> 지원 검사와 해당 검증 경로의 작업을 완료해 H 없는 동등 인증을 받은
> 준비된 IR–코드 쌍은, 정한 실행 모델의 모든 허용 초기 상태와 입력 이력에서
> 시간 제한 없이 같은 timed ACTION trace를 낸다.

모든 임의 프로그램의 판정 완료를 보장하지 않는다. 자원 상한·지원 범위 밖은
동등 인증이 아니다. 유한 시간만 검사한 성공을 위 명제로 승격하지 않는다.
이는 확인된 IR 대비 코드 행동의 명제다. 자연어→IR의 정답성, 물리 기기 동작,
전체 Python 구현의 기계 검증, 모든 버그 부재를 함께 주장하지 않는다.

## 논문용 보장 명제

이 절은 논문에서 증명할 D/S의 기준 문구다. 운영상 성공 경로와 증명에 필요한
보조정리는 [구현 대응](../proof/PROOF_OBLIGATIONS.md#성공-조건과-증명-연결)에 연결한다.

| 기호 | 정의 |
| --- | --- |
| `I, C` | 준비 단계에서 검사·접지된 기준 IR과 후보 JoI 프로그램. 원문에서 이 표현으로의 의미 보존은 프런트엔드 대응 의무 |
| `M` | inventory/binding, catalog와 반환 정책, 시작 시각 `t₀`, 입력 간격 `Δ`, 입력/초기 GV 도메인, 아래 실행·관찰 규칙을 고정한 모델 |
| `W` | 양쪽 프로그램의 쓰기 대상 GV 이름의 합집합 `Writes(I) ∪ Writes(C)` |
| `Uₖ`, `G₀` | 외부 읽기 키별 **원래 허용 값**과 `W`에 속하는 관련 GV의 허용 초기 환경. 대표값 목록과 구별. 명시 subset이면 그 subset이 모델의 범위 |
| `u ∈ U_M` | `u: ℕ → ∏ₖ Uₖ`인 전체 입력 이력. `u(n)`은 `t₀+nΔ`의 공동 snapshot이고 다음 격자까지 유지. 초기 장치 상태는 `u(0)`에 포함 |
| `Init_P(g₀)` | 공통 초기 GV `g₀`, 빈 지역 저장소, 진입 제어 위치에서 시작하는 반응 전 상태. 실제 초기화 문장은 첫 반응에서 실행. 양쪽 지역 변수의 임의 곱집합이 아님 |
| `Tr_M(P; g₀,u)` | 공통 절대 시각 위의 `(시각, ACTION 관찰)` 열. 무행동은 열에서 생략하되 다음 ACTION 시각은 보존 |
| `V_K`, `Accept∞` | 고정 구현의 검증 절차와 작업량 상한 `K`. `H=None` 요청에서 아래 운영상 성공 조건으로 반환한 인증 |

`∏ₖ Uₖ`는 기기·조회 인자·반환 타입별 키를 구별한다. 같은 키/입력 시점의 읽기는
같은 값이며, 지역 변수에 저장한 이전 snapshot은 새 입력이 아니다. 입력 키는 다음처럼 나눈다.

- 일반 센서/조회, 양쪽 모두 읽기만 하는 GV의 `@gv:` 키, `clock.isholiday`는 `U_M`의 외부 축이다. 휴일 여부는 정확히 BOOL 두 값이다.
- `W`에 속하는 관련 GV는 `g₀ ∈ G₀`에서 초기값을 선택한 뒤 양쪽 저장소에서 각각 전개하며 외부 입력으로 덮어쓰지 않는다.
- 내장 `clock.hour`, `minute`, `weekday`, `timestamp`, IR의 파생 `clock.time`은 논리 시각의 함수이며 자유 입력 축이 아니다.

사용하는 도메인과 초기 집합은 비어 있지 않아야 한다. 해당 키가 전혀 없는 경우의
곱집합은 빈 환경 하나다. 외부 입력 이력에 변화 폭이나 최종 true 같은 추가 제약은 두지 않는다.

도메인은 타입을 가진 값의 집합이다. 자동 catalog 모델은 선언 타입·범위와 이 계약의
결측/정밀도 정책 전체를 뜻한다. catalog가 타입을 선언하지 않는 GV는
[기존 입력 논증의 모델 계열](../proof/INPUT_COVERAGE.md#1-입력-모델을-먼저-고정한다)에 따르거나
명시한 유한 도메인을 사용한다. 대표값은 이 집합의 계산용 표현이다.
초기 GV의 결측 `None`은 해당 이름이 없는 환경으로 구현되며, 지원 GV 읽기의 기본값도
`None`이다. 이름 존재 여부를 별도로 관찰하는 연산은 이 대응으로 지원하지 않는다.
`@gv:w` (`w∈W`)를 외부 입력으로 선언하는 중복 소유는 모델에 없으며
`check_supported_pair`가 거절한다. 쓰기만 하고 초기값을 읽지 않는 GV는 초기 자유 축을
추가할 필요가 없다. 첫 관찰 전에 프로그램의 쓰기로 값이 결정되기 때문이다.

구체 상태 `s`는 제어 위치·지역 저장소·GV·활성 타이머·edge 이력·종료 상태를 포함한다.
`R_P(s,u(n),t)=(s',A)`는 시각 `t`에 snapshot을 먼저 반영하고 차단/종료까지 실행하는
한 반응이다. `n=⌊(t−t₀)/Δ⌋`이며, 오류는 별도 결과 `err`다. `O(A)`는 아래 ACTION
정규형이다. `Tr`는 시각순으로 `(t,O(A))`를 이어 붙이고 `O(A)=()`인 항목만 생략한다.
지원 실행기는 고정된 준비 절차가 만드는 `IrRunner`, `OneShotRunner`, `PauseRunner`와
알려진 catalog/종료 wrapper다. 임의 runner 교체·상속 구현은 이 명제의 대상이 아니다.

**D — 모델 결정론성.** 지원 의미론에서 `P, M, g₀, u`를 고정하면 각 반응의
결과는 유일하다. 한 반응의 유한 실행·진행 조건까지 충족한 실행은 유일한 timed trace를 갖는다.
SMT 탐색 분기, 반례 선택 순서, wall-time timeout에 따른 도구 결과의 재현성은 이 명제가 아니다.

**S — H 없는 인증의 soundness.** 위 모델의 준비된 쌍에 대해 증명할 명제는 다음과 같다.
결론은 양화한 실행들이 오류 없이 정의된 trace를 갖는다는 것까지 포함한다.

\[
\operatorname{Accept}_{\infty}(V_K,I,C,M)
\ \Longrightarrow\
\forall g_0\in G_0\;\forall u\in\mathcal U_M\;\forall T\in\mathbb N:\quad
\operatorname{Tr}_M(I;g_0,u)_{\le t_0+T}
=_{O}
\operatorname{Tr}_M(C;g_0,u)_{\le t_0+T}.
\]

`T`는 결론에서 임의로 고르는 경과 ms다. 검증기에 넘기는 H나 실험 횟수가 아니다.
모든 유한 시각 prefix가 같으면 시간 제한 없는 관찰 열도 같다. 이 연결에는 한 시각의
반응이 유한하고, 무한 실행의 논리 시간이 진행하거나 종료 후 무행동으로 연장되는
조건이 필요하다. 오류·연료 소진을 종료한 빈 trace로 바꾸지 않는다.
종료 여부 자체는 관찰하지 않으므로 종료와 영원한 무행동은 ACTION 기준으로 같을 수 있다.

`Accept∞`는 trace 동등성을 전제로 정의하지 않는다. 고정된 준비 절차와
`timed_product`가 `H=None`에서 정상 반환한 `ProductResult`가 `verdict=EQUIV`,
`closed=true`, 두 bounded-horizon 필드 `None`인 경우다. `gate_pair`에서는 이에
대응하는 외부 `EQUIV`, 평가 worker에서는 `EQUIV-FIXPOINT` claim으로 기록한다.
명시 유한 도메인은 해당 값 목록으로 한정하고, 자동 입력의 대표값을 원래 도메인으로
해석하는 것은 O1/O2의 증명 의무다. 레거시 `product_runners`와 임의로 만든 결과
객체는 이 정의에 포함하지 않는다.

이 성공에 이르는 제어 흐름에서 SMT/관계 경로의 `complete=true`, 기호 값 흐름의
`both_terminated=true`가 따라옴을 구현 대응에 기록했다. 이들은 gate가 독립적으로
재검사하는 증명서가 아니다. 특히 `closed`의 기본값만으로 그래프 폐쇄를 증명하지
않는다. 경로의 작업 완료에서 모든 구체 실행의 관찰 보존을 도출하는 것이 S의 증명이다.

S는 인증에 성공한 쌍에 대한 함의다. 실제로 같은 모든 프로그램을 인증한다는 역방향,
모든 요청의 판정 완료, 모든 시작 시각·binding에 대한 동시 인증은 포함하지 않는다.
소스→모델 대응과 실행기 구현에 남는 신뢰 기반은 증명 문서에서 분리한다.

## 초기 상태·입력·서비스

- 모델에는 준비된 IR/코드, 고정 inventory/binding, 서비스 snapshot, 시작 시각,
  입력 도메인과 변화 시점, 초기 GV 모델이 포함된다. 실행 중 재바인딩하지 않는다.
- bare selector는 매번 무작위 선택하지 않는다. 유일한 Main이 있으면 Main,
  아니면 정해진 첫 후보를 선택한다. 동일한 선택을 재사용하며 any/all은 대응 집합 전체를 검사한다.
- 초기 장치 상태는 첫 입력 조합에 포함한다. 양쪽 중 하나가 쓰는 관련 GV는 선언한
  초기 도메인 또는 인증된 사용 술어로 추론한 모델에서 시작하며 이후 외부 입력으로
  덮어쓰지 않는다. 읽기 전용 GV는 매 입력 격자의 `@gv:` 외부 축이다.
  지역 변수는 각 프로그램의 실제 초기화 규칙으로 시작한다.
- 자동 입력은 양쪽 프로그램의 사용 위치를 합쳐 catalog 타입·범위에서 구성한다.
  명시 `input_domains`/초기 GV subset은 그 범위만 보장한다. 센서 범위를 임의로 만들지 않는다.
- BOOL은 정확히 false/true다. 누락·None·숫자 0/1을 BOOL 입력으로 인정하지 않는다.
- INTEGER는 수학적 정수다. DOUBLE 입력은 합의된 0.1 격자 및 허용 정수 표현을
  포함하며, 관찰에 필요한 signed zero/숫자 표현을 보존한다. 범위 밖 정밀도를 반올림해 수용하지 않는다.
- MenuProvider.GetMenu는 None 없는 STRING이다. 나머지 비BOOL의 결측은
  해당 모델에서 포함하며 derived clock 등 별도 정의된 비결측 값과 구별한다.
- 서비스 이름·capability·인자 순서/필수 인자·타입/범위를 검사한다. VOID 반환 대입은 거절한다.
  읽기 역할은 검토된 함수에만 허용한다. `query`는 Explorer의 읽기 모델 명칭이며 catalog의 별도 타입이 아니다.
- 읽기 입력 키는 구체 기기·member·타입을 보존한 리터럴 조회 인자를 포함한다.
  같은 snapshot의 같은 조회는 같은 값이며, 다른 입력 시점에 읽은 값은 별개다.
  동적 조회 인자, 효과와 반환값을 함께 모델링해야 하는 미지원 호출은 거절한다.
- Clock.Hour는 정수 0–23, Minute/Second의 선언 범위는 0–59다.
  IR `clock.time`은 hour×100+minute이며 catalog의 STRING Clock.Time과 다르다.
  Second 범위 정정이 새로운 clock.second 실행 지원을 뜻하지 않는다.

## 시간·반응

| 항목 | 계약 |
| --- | --- |
| 외부 입력 | 기본 `t₀+k×100ms`에서 각 입력이 자유롭게 변하고 사이에는 유지. 격자 사이 펄스는 모델 밖 |
| 내부 만료 | 정확한 1ms 단위 deadline. 150ms를 200ms로 올리지 않음. 타이머는 정확한 유리수 표현 |
| 같은 시각의 입력·만료 | 새 입력을 먼저 반영. 지속 조건이 깨지면 취소; 무조건 delay는 취소하지 않음 |
| delay | 진입 시각+duration에 기존 실행 위치에서 재개 |
| period | 회차 종료 뒤 period만큼 대기. 종료 1500ms+period 1000ms이면 다음 시작 2500ms |
| wait / edge | wait가 평가될 때 관찰. 초기 true edge는 발화하고 latch는 회차를 넘어 유지. 다른 대기 중 edge를 별도 누적하지 않음 |
| 종료 | 이후 무행동인 흡수 상태. 한쪽 종료만으로 불일치가 아니며 상대의 미래 ACTION은 계속 검사 |
| cron | 같은 시작 앵커인지 준비 단계에서 검사한 뒤 앵커를 소거. 여러 cron 인스턴스의 중첩 실행을 검증하지 않음 |
| 동시성 | 단일 시나리오 쌍. IR 내부 병렬 분기·여러 시나리오 간 병렬 수행은 지원하지 않음 |

입력 변화 주기와 내부 만료 정밀도는 서로 다른 개념이다. 긴 delay 동안 양쪽 모두
입력을 관찰하지 않으면 중간 입력을 생략할 수 있지만, 재개 시 가능한 최신 입력과
기존 저장값은 보존해야 한다. 정확한 생략 전제는 증명 의무에 연결한다.

## ACTION 관찰

관찰은 논리 시각별 호출의 대상·동작·인자·중복·명시적 순서다.
한 호출이 독립 기기들로 펼쳐진 fanout 안에서만 기기 나열 순서를 무시한다.
같은 시각이라는 이유로 별도 순차 호출을 섞거나 중복을 지우지 않는다.

구체 ACTION의 서명은 `(service, method, typed-args, target)`이다. `O(A)`는 실행 순서의
호출 그룹 열이며, 단일 호출은 원소 하나인 그룹이다. fanout 그룹에서는 같은 기기의
서명 열을 원래 순서대로 유지한 뒤 기기 ID 순으로 이어 붙인다. 따라서 독립 기기의
순열만 같은 정규형이 되고, 같은 기기의 순서·중복과 호출 그룹 경계는 유지된다.
수식의 `=_O`는 아래 숫자 규칙까지 적용한 이 정규형과 시각의 일치다.

숫자 ACTION 인자 `1`과 `1.0`은 같게 비교하지만 bool `true`와 숫자 `1`은 다르다.
문자열 `"1"`과 `"1.0"`도 다르다. 따라서 저장소 병합은 미래 문자열 변환을 위해
숫자의 타입·signed zero를 유지한다. 서비스 인자 타입 적합성 검사는 관찰 동치와 별개다.
내부 변수 대입·delay 시작·종료 플래그 자체를 새 제품 ACTION으로 추가하지 않는다.
서비스 `GlobalVariable.set...` 호출은 현재 실행기가 기록하는 쓰기 ACTION에 포함한다.
지역 변수 대입과 서비스 쓰기를 혼동해 관찰에서 제거하지 않는다.

## 지원하는 검증 경로

공통 계약 아래 서로 다른 충분조건을 검사한다. 한 경로의 지원을 다른 경로에 확대 적용하지 않는다.

| 경로 | 핵심 지원과 성공 조건 | 주요 제한 |
| --- | --- | --- |
| 구체 BFS | 공동 입력 분할/필요한 전체 값, 양쪽 저장소·타이머를 전개. 모든 후속을 검사한 그래프가 닫히면 H 없는 성공 | 임계값 분할로 원값 출력·결합 산술을 대신하지 않음. 그래프가 항상 닫히지는 않음 |
| 기호 값 흐름 | 순차 one-shot의 읽기·복사·문자열·고정 delay. 기기·조회 인자·입력 시점을 보존한 기호식 일치와 완료 | 일반 분기/주기/GV/산술을 이 경로에서 지원하지 않음 |
| SMT 산술 | 자격을 갖춘 catalog 숫자 one-shot. 분기 경로·입력 제약 아래 ACTION 차이 수식을 검사. H 없으면 모든 기호 경로 종료 필요 | 유한 catalog 숫자 bounds 등 사전조건. 일반 주기/loop/GV/clock·동적 query·비선형 산술 지원 아님 |
| 정수 관계 | 제한된 최상위 카운터 반복. 실제 초기화·출력/갱신 순서·후속 정수 관계와 그래프 폐쇄 | 임의 카운터/loop 추론 아님. 중첩/until cycle·관계 float·GV/clock·복잡한 snapshot 등 거절 |

SMT는 `+`, `-`, 상수 곱·상수 나눗셈 등을 지원하며 실제 typed 수치 의미를 보존한다.
`A+B>40`을 기존 단일 축 분할로 인증하지 않는다. 기호식이 다르다는 사실만으로
실제 ACTION 불일치라 판정하지 않는다. 구체 반례 재생 또는 더 보수적인 미결정이 필요하다.

시간 의존성이 없으면 내부 타이머의 정확한 상대값과 입력 위상을 사용한다.
모든 clock 읽기가 catalog 범위로 증명된 상수 비교 안에 있을 때만 같은 관계를
추가로 적용할 수 있다. 원래 AST와 실행은 유지한다. 실제 clock 경계나 저장 시각,
알 수 없는 래퍼는 이 최적화로 제거하지 않는다.

미인증 frontend 문법·floating/missing binding·capability/인자 오류·예약 내부 이름
충돌도 거절한다. 지원 검사의 세부 근거는 [증명 의무의 부록 연결](../proof/PROOF_OBLIGATIONS.md)에 있다.

## 판정 의미

| 결과 | 의미 |
| --- | --- |
| `EQUIV-FIXPOINT` / gate의 `EQUIV` | H 없는 성공 조건을 완료. 기호 one-shot의 종료도 이 공통 결과명으로 보고됨 |
| `EQUIV-BOUNDED` | 명시된 유한 H의 닫힌 구간까지만 동등. H 없는 성공과 구별 |
| `DIVERGE_CONFIRMED` / gate의 `DIVERGE` | 허용 초기 상태·입력 이력에서 재생된 실제 ACTION 차이 |
| `INCONCLUSIVE` / `UNKNOWN` / timeout | 자원 상한·미완료·증명 실패. 동등도 실제 불일치도 아님 |
| `REFUSED` | 지원/계약 밖. gate에서는 미결정도 REFUSED로 접으므로 평가에서 원인을 분리 |

자원 상한은 탐색 작업량의 제한이며 실행 시간 H가 아니다. 고정 입력의 빠른 실행은
반례 발견에만 사용하고, 그 이력에서 계속 같았다는 사실로 전칭 동등성을 인증하지 않는다.
