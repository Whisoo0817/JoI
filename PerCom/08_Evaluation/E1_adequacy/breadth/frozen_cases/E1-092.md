# E1-092 — independent parallel shutdown flows

Source: Home Assistant Community thread 955561, “Running groups of actions in Parallel.”

## Frozen interpretation

At a shutdown request, the Alexa announcement flow and the physical house-shutdown flow start together. An Alexa communication failure terminates only the Alexa flow; it must not stop or delay the house-shutdown flow. The source provides no completion deadline, so none is assumed.

## Binding plan

- `ShutdownRequested` is the trigger input.
- Alexa actions are abstract notification services: `Alexa.AnnounceTasks`, `Alexa.AnnounceNews`, and `Alexa.AnnounceAlarmSettings`.
- House actions are `Lights.Off(downstairs)`, `Locks.Lock(front, back)`, and `Alarm.Set(armed)`.

## Reference history and expected trace

| Time | Input / internal outcome | Expected action |
|---|---|---|
| t+0 s | `ShutdownRequested` | `Alexa.AnnounceTasks`; `Lights.Off(downstairs)` |
| t+1 s | Alexa tasks action completes | `Alexa.AnnounceNews`; `Locks.Lock(front, back)` |
| t+2 s | `Alexa.AnnounceNews` fails | `Alarm.Set(armed)` |
| t+3 s | no further input | -- |

The failed Alexa command is an execution outcome, not an additional expected ACTION. The physical branch completes its fixed sequential steps despite that failure.
