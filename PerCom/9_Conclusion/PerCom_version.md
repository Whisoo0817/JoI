# Conclusion — PerCom working draft

Generated smart-home code cannot be validated reliably from its syntax or nominal execution alone when reactive-temporal behavior is distributed across timers, persistent state, and control flow. VETS fixes the expected behavior before lowering as a user-confirmed Timeline and binding plan, then uses that executable specification as the reference for generated JoI code. Behavioral Explorer jointly explores the reference and implementation under a shared timed-input and ACTION contract, returning a certificate only when its declared horizon-free completion conditions hold and a replayable witness when their behaviors diverge. This design makes the preservation question explicit: whether an imperative implementation produces the same observable actions as the behavior the user confirmed. The final paper will delimit adequacy, interpreter fidelity, practical applicability, and scalability through E1–E4.
