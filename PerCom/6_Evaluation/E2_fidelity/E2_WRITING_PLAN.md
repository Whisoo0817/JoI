## 0. 최신 결정: 초기 미판정 쌍의 최적화 서술 (2026-09-14)

이 결정은 아래의 옛 142쌍/131판정 문구보다 우선한다. 최종 원고와 표를 동기화할 때 함께 고친다.

- `any(...)`가 ACTION에 붙은 `C03_008/llm`은 구문 오류로, 잘못된 service mapping인 `C20_011/llm`은 입력 오류로 E2 모집단에서 제외한다. 유효 모집단은 140쌍이다.
- 바인딩 평가 정의 변경은 Explorer 개선 수치에 포함하지 않는다. 바인딩은 독립적인 평가 계약 결정이다.
- 초기 유효 140쌍 중 Explorer가 판정한 쌍은 104개이고, 제한된 탐색 경로에서 판정을 완료하지 못한 쌍은 36개였다.
- 반복적인 시간·상태 탐색을 줄이는 의미 보존 최적화를 적용한 뒤, 동일한 시간·상태 예산에서 26쌍을 추가로 판정했다. 기존 104개 판정은 하나도 바뀌지 않았고 10쌍은 미판정으로 남았다.
- 본문에서는 `timer/state abstraction`, `fixed-cardinality aggregation unrolling` 같은 구현 기법을 열거하지 않는다. 필요하면 구현·artifact 문서에서만 설명한다.
- "같은 쌍을 보고 개선했다" 또는 "실패 사례에 맞춰 지원을 확장했다"고 요약하지 않는다. 핵심은 판정 결과의 수정이 아니라, 동일한 예산에서 반복 탐색을 줄인 것이다.

논문용 확정 문장:

> *Some pairs could not be decided within the original time and state budgets. We therefore applied semantics-preserving optimizations that reduce repetitive temporal and state exploration. Under the same budgets, the optimized Explorer issued verdicts for 26 additional pairs.*

## 1. 논문 안에서의 위치

- **Evaluation 의 두 번째 실험.** E1(요구 표현 적합성)이 "Timeline 으로 적을 수 있는가" 였다면, E2 는 **"Explorer 가 두 프로그램의
  같음/다름을 정확히 판정하는가"** 이다. E2 의 목적은 Explorer 의 능력(정확도)을 보여 주는 것.
- **뒤 실험의 전제.** E3(생성 결과 평가)는 Explorer 판정을 그대로 결과로 쓴다.
- **분량**: 약 0.6 쪽 (방법 한 문단, 표 1개, 결과 두 문단, 한계 반 줄).

## 2. 핵심 문장 (whisoo 09-14 확정, 수치는 140쌍 기준으로 갱신)

> Explorer 가 판정한 130쌍 중 독립 정답기와 어긋난 판정은 없었다(130쌍 모두 확인).
> LLM 생성 후보 38개는 전부 판정했고, 직접 만든 경계 요구 20개 중 18개를 판정했다.
> 남은 2개는 반복·타이머가 겹친 탐색의 시간 예산 초과와 사건 수에 따라 늘어나는 시한이라는 두 유형이다.

## 4. 절 구성 (원고 초안에 반영됨)

1. **질문과 방법 (한 문단)**
   - 독립 정답기: 명세만 보고 별도 작성자가 만든 IR·JoI 실행기. E1 기대 결과와 일치(41/41, 12/12, 15/15).
   - 쌍 140: E1 요구 20개의 올바른 쌍 21 + 오류 쌍 81(12 계열), 388 데이터셋 무작위 표본의 유효 LLM 후보 38.
   - 이력 약 49,000개(140쌍 기준). 비교: 정답기 입력 이력에서의 차이, Explorer 반례의 정답기 재생.
   - 거절·시간 초과는 분모에 남긴다. 끝에 §0 문장 3개(세 번째 문장 끝에 "and none of its earlier verdicts changed" 추가, Claude 판단)와 "아래 결과는 최적화된 Explorer" 한 문장.
   - 바인딩: 따로 설명하지 않는다.
2. **표 (Table E2, 하나)**
   - 윗부분 "Fidelity": 판정 130 / 정답기 확인 130 / 어긋남 0 / 실제 차이가 있는 오류 75 중 DIVERGE 69, 놓침 0, 미결정 6.
   - 아랫부분 "Coverage": LLM 38/38, 직접 만든 쌍 92/102, 요구 18/20, 미결정 원인 2유형(각 5쌍).
   - 오류 81 중 관찰된 차이가 없는 6쌍: C09/f4(구조상 관찰 불가), C16/f1·E1-062/f3·E1-086/f3(기기 지목만 다름, 두 도구 모두 EQUIV),
     E1-099/f2·f4(Explorer 미판정, 정답기 이력에서도 차이 없음). 표 각주 없이 "관찰 가능한 차이" 기준 75 로 설명.
3. **결과 문단 1 — 신뢰성**: 핵심 문장 1. 반례로만 확인된 8쌍은 "이력이 입력에 닿지 못함 5 + JoI 가 이력에 없는 기기 값을 읽음 3".
4. **결과 문단 2 — 판정 범위**: 핵심 문장 2·3. 두 유형을 C07·E1-099 예로 짧게. C07 은 시간 예산 초과(TIMEOUT), E1-099 는 거절.
5. **한계**
   - E2 안(반 줄): 정답기의 "같음" 은 입력 이력 범위 안의 증거다.
   - Limitations 절로: 정답기와 Explorer 는 같은 명세를 따른다(코드 수준 독립), 오류 쌍은 요구별로 묶여 독립 표본이 아니고 LLM 표본은 38.

## 5. 쓰지 않을 것

- "정확도 100%", "동등성을 증명", "명세가 옳음을 확인".
- 93%(130/140)를 정확도로 부르기. 판정 비율과 판정 신뢰성을 섞지 않는다.
- C07·E1-099 를 분모에서 빼기, LLM 38/38 을 388 전체로 일반화하기.
- C03_008·C20_011 사례, 40개에서 2개를 뺀 과정 (§0). 원고는 "38 valid LLM-generated candidates drawn at random" 으로만 쓴다.
- 구현 기법 이름, 104/36 같은 최적화 전 수치, 동결판·중간판 수치, 같은 쌍을 보고 개선했다는 경과 (§0).
- all/any, 셀렉터 나열, 바인딩 여러 개일 때의 비교 규칙, "범위 밖" 이라는 표현 (결정 3).
