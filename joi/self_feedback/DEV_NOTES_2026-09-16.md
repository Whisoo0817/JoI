# Repair prompt development notes — 2026-09-16

Purpose: choose the one-shot repair prompt (few-shot) for the E3 feedback run. Everything here
is prompt development on the fresh dev set `dev/cases.py` (14 cases, 7 error types × 2, disjoint
from the worked examples and from dataset.csv). No E3 case or E3 counterexample was used.
Not an experiment result; not for the manuscript.

## Result

Chosen: `prompts/repair.md` (= `repair_v5.md`): the reset-era repair instruction + a 7-row
"repair shape checklist" + worked examples A–G, run with **thinking off, temperature 0**
(greedy). Dev set 13/14 repaired to EQUIV-FIXPOINT, median 329 completion tokens per case.
Adding IR-derived timing facts to the payload (`--ir-facts`) makes the sampled (temperature 0.6)
setting equally robust across seeds (13/13/12) and is a harness option, not a prompt change.

Only unsolved dev case: D4a (pre-cycle action + cycle; the model drops the phase pattern).
D6a (sustain followed by a counted cycle) is solved only at temperature 0 or with IR facts.

## What moved the number

1. Worked examples (v1): 7→10 of 14 with thinking on; the remaining failures were three
   cases where the model reasoned past 8k tokens without answering and one where it kept
   `period` 1000 for a sustained condition. Raising the budget to 16k changed nothing.
2. Thinking off: fast (300–700 tokens) but rule-following is fragile; sustained conditions
   were 0/2 until the checklist stated the exact conversion table (v4/v5).
3. Checklist with a literal conversion table (`30 SEC → 300 → 301`, `1 MIN → 600 → 601`):
   sustained conditions 2/2 with greedy decoding. A formula (`D/100 + 1`) alone was misread
   as seconds + 1 (v3).
4. A self-check list at the end (v3) hurt: the model started adding waits the IR does not have.
5. Greedy decoding (temperature 0) removed most seed-to-seed variance: v5 at temperature 0.6
   scored 10/9/12 over seeds 0/1/2, at temperature 0 it scored 13.
6. Budget forcing (closing `</think>` on overflow) rescues sustained cases with thinking on,
   but costs the full 8k tokens per case and did not help edge or timing cases.

## Files

- `prompts/repair.md` — final prompt (identical to `repair_v5.md`).
- `prompts/repair_v0_noexamples.md` … `repair_v5.md` — versions in order; `repair_v1_examples.md` = examples only.
- `prompts/fewshot_check.py` — verifies every worked example (gold EQUIV-FIXPOINT, wrong DIVERGE).
- `dev/cases.py`, `dev/run_repair.py`, `dev/runs/<run-id>/` — dev set, one-shot runner, raw responses and verdicts.

Binding/selector errors are not in the dev set or the examples: under the B1/B5 binding
contract they verify EQUIV, so the verifier never produces a counterexample for them.
