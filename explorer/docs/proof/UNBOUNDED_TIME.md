# H 없는 시간 탐색 — silent-time-v1

2026-09-08 구현. [이전 계획](../archive/UNBOUNDED_TIME_HANDOFF.md)의 구체화다.
H를 기본 검증 경로에서 요구하지 않는다. 성공은 그래프 폐쇄 또는 모든 기호 경로의
종료로 결정하며, 자원 한도에서 멈추면 UNKNOWN이다. 모든 프로그램의 종료/동등성을
결정하는 알고리즘이나 실제 서버 적합성의 기계 증명을 주장하지 않는다.

## 구현과 선택한 시간 관계

- `time_events.suspension`: 실제 실행 위치를 읽어 고정 delay, 회차 완료 후 period,
  종료, 단순 wait를 구분한다. edge/지속/timeout wait와 알 수 없는 실행기는 보수적으로
  일반 이벤트 경로에 둔다. `delay`라는 단어가 프로그램에 있다는 이유로 생략하지 않는다.
- `timed.next_time`: 양쪽이 입력을 읽지 않는 고정 대기/종료 상태면 가장 이른 만료로
  이동한다. 한쪽이 입력에 반응하는 wait면 일반 입력 격자 탐색을 유지한다.
- `crossed_input_grid`: 만료가 격자에 정확히 놓였는지가 아니라, 이전 관찰 이후
  격자를 하나라도 지났는지 검사한다. 지났으면 모든 최신 입력 조합을 펼친다.
  150ms 만료는 100ms에 선택된 값을 읽으며, 50ms 만료는 초기 값을 유지한다.
- 시간 관계는 **정확한 내부 타이머 상대값 + 양쪽 실행 위치 + 입력 격자 위상**을
  사용한다. 기존 `internal_timers`/상태 키를 유지한다. 임의의 '만료 전' 구간으로
  서로 다른 남은 시간을 합치지 않는다. 시계값을 읽으면 절대 시각을 유지한다.
- `suspension`의 종류/정확한 만료는 내부 시간 관찰이다. 이것의 양쪽 일치를 별도
  필수 조건으로 강제하지 않는다. delay 100ms 두 번과 delay 200ms 한 번도 실제
  ACTION 시점이 같으면 인증할 수 있다. 외부 ACTION 정의는 변경하지 않았다.
- `relational_product`에도 동일한 생략과 최신 입력 분기를 연결했다. 무제한 auto
  경로는 엄격한 카운터 관계 자격 검사를 통과한 경우 기존 관계 엔진을 선택한다.
  bounded 요청은 자동으로 무제한 관계 인증으로 바꾸지 않는다.

이는 동기화된 긴 대기/반복을 처리하는 정확한 시간 관계 구현이다. 비동기 wait와
여러 타이머의 모든 상호작용을 유한한 timed-automata region/zone으로 바꾸는 일반
추상화는 구현하지 않았다. 그런 프로그램은 기존 정밀 탐색으로 닫히거나 UNKNOWN이다.

## 전이를 생략해도 되는 이유

두 실행기의 현재 중단 위치에서 다음 만료 전까지 명령을 실행하지 않으면, 그 사이
입력이 어떻게 바뀌어도 ACTION, 지역 변수, 저장된 snapshot, 프로그램이 쓴 GV,
실행 위치, 타이머의 시작값은 바뀌지 않는다. 중간 입력 이력은 재개 직전 최신값만
남긴다. 이 계약의 입력은 격자마다 독립적으로 모든 도메인 값을 취할 수 있으므로,
생략된 구간에 격자가 있으면 모든 최신 조합이 도달 가능하다. 없으면 이전 입력만
가능하다. 따라서 생략 전후의 재개 상태와 timed ACTION 집합이 정확히 일치한다.

만료가 격자와 같으면 새 입력을 먼저 적용한다. 만료 사이에 다른 실행기의 관찰이나
시간 사건이 있으면 그 사건이 우선하므로 생략하지 않는다. 과거에 저장한 센서값은
최신 입력과 별개로 기존 전체 상태 키에 보존한다. 이 논증은 입력 간 변화율/이력 제약이
없는 현재 계약에 대한 것이며, 그런 제약을 나중에 추가하면 다시 검토해야 한다.

## H 없는 폐쇄의 근거

시계값을 읽지 않는 프로그램에서, 같은 입력 위상을 유지하는 공통 시간 이동은
타이머 비교, 실행 위치, 다음 만료까지 거리, ACTION 인자/상대 발생 시각을 보존한다.
양쪽 내부 타이머를 같은 현재 시각에 대해 정규화하고 다른 값은 보존하면, 같은 키의
상태는 같은 미래 전이 문제다. 생략 전이의 모든 최신 입력 조합을 검사하고 BFS 큐가
비면, 모든 후속 전이에 대한 동등성은 귀납적으로 계속 유지된다. 같은 ACTION을 일정
횟수 봤다는 추정은 사용하지 않는다. 카운터는 별도의 기존 INTEGER 관계 불변식을 쓴다.

SMT 경로에서는 `H=None`일 때 모든 기호 분기가 종료해야 성공한다. 종료되지 않은
wait 경로를 시간 제한 없이 계속 펼치다가 자원을 소진하면 UNKNOWN이다. 정확한 상태
중복은 같은 절대 시각/제약/저장소에서만 제거한다. 각 분기는 기존 SMT 전체 입력
제약과 ACTION 차이 불만족 검사를 유지한다. 고정 delay 생략 후 입력 epoch는 실제
격자 번호를 사용하므로 과거 snapshot과 최신 입력의 출처가 섞이지 않는다.
새로운 일반 SMT 귀납 불변식 생성이나 반복 프로그램 지원을 주장하지 않는다.

## C08_011: 증명과 분리된 반례 가속

한쪽이 wait에서 멈추면 현재 입력을 계속 유지하는 **한 개의 구체 이력**을 필수 사건마다
실행해 본다. 시계 읽기에서는 이 가속을 하지 않는다. 지속/edge/timeout wait는 이미
현재 입력으로 한 번 반응한 상태에서, 유지되는 입력에 대한 다음 실제 만료를 사용한다.
입력이 고정이면 edge 메모리나 지속 시작값도 그 사이 바뀌지 않는다. 초기 입력 조합마다
최대2048개 사건(전체 상태/전이 예산도 적용), 이후 BFS 상태에서는1개 사건만 시도한다.
ACTION 차이가 나오면 반드시 별도의 구체 재생을 확인한다.
이 전이는 BFS의 방문 집합/큐에 넣지 않으며 동등 인증에는 사용하지 않는다.

C08_011의 Main 버튼=None, Hall 버튼=pushed 이력에서 코드만 1시간 뒤 조명 3대를 끈다.
새 결과는 재생된 DIVERGE다. 기존 H=None 진단의 UNKNOWN 원본은 보존한다.

`Divergence.input_step_ms`가 있는 새 반례는 `grid_history`로 입력 변경을 유효 격자에
놓고, replay에서 사이의 필수 사건을 다시 실행한다. 고정 입력에서도 조용하다고
확인된 중단 상태만 건너뛴다. 격자 밖에서 임의로 입력을 바꾸는 반례는 거절한다.
구형 반례 레코드와 그 재생 API는 유지한다.
