## 현재 증명 상태

계약의 D/S와 운영상 성공 조건에 대해 L1–L7의 세부 논증, 네 경로의 B0–B3 도출,
공통 귀납을 통합한 **수작업 증명을 완료**했다. 별도 검토의 Minor 두 건을 반영했다.
완료 범위는 선언한 모델과 고정 인증 알고리즘이며, 실행기/프런트엔드의 신뢰하는
구현 대응 및 전체 소스의 기계 검증과 구별한다.
과거 문서의 bounded 명제는 명시 H 요청의 근거로 유지하며 무제한 주정리와 구별한다.

논문에서 제시할 명제는 두 가지다.

- **모델 결정론성:** 같은 준비된 프로그램·초기 상태·시간별 입력을 고정하면 반응과 ACTION trace가 유일하다.
- **검증 soundness:** 각 경로의 성공 조건을 충족해 H 없이 EQUIV를 반환하면 모든 허용 초기 상태·입력 이력의 timed ACTION trace가 같다.

반응의 유일성은 모든 임의 프로그램이 종료하거나 Explorer가 반드시 판정을 완료한다는
명제가 아니다. 비지원·실행 연료/자원 초과는 인증하지 않는 조건과 함께 다뤄야 한다.

## 공통 증명 의무

기존 O1–O6 식별자는 유지한다. 아래는 핵심 논증과 구현 대응의 압축본이다.

| 의무 | 필요한 논증 | 구현·상세 근거 |
| --- | --- | --- |
| O1 입력 포괄 | 양쪽 사용 술어를 합친 분할에서 허용값마다 같은 진리벡터의 대표가 존재. 단순히 양쪽 대표 목록을 합치는 것으로 대체하지 않음 | `service_model.py`, `input_coverage.py`; [입력 포괄성](INPUT_COVERAGE.md) |
| O2 입력 치환 보존 | 복사/GV/모든 대입 경로의 출처를 보존. guard는 같은 bool, 원값 관찰은 전체 값 또는 별도 기호 증명을 요구하여 ACTION과 다음 상태를 보존 | `Collector`, `merged_coverage`, `initial_domains`; [입력 논증](INPUT_COVERAGE.md) |

| O4 미래를 보존하는 병합 | 제어 위치·양쪽 저장소/GV·현재 입력·edge/종료/활성 timer를 보존. 같아진 키에 같은 입력을 주면 같은 관찰과 관련된 후속 상태 | `state_key.py`, `timed.py`; [기존 탐색 정리](SEARCH_CORRECTNESS.md), [시간 관계](UNBOUNDED_TIME.md) |
| O5 모든 이력의 탐색 | 모든 초기 조합을 포함하고 각 입력 사건에서 모든 허용 다음 선택을 실행. 이미 검사한 동치 대표로만 병합 | `timed_product`의 initial/transition/queue/seen; [탐색 논증](SEARCH_CORRECTNESS.md) |
| O6 성공·반례·미결정 구별 | 전칭 의무 완료와 실제 폐쇄/종료를 성공 조건으로 요구. 자원 상한·예외를 성공으로 바꾸지 않으며 불일치는 허용 이력에서 재생 | `ProductResult.claim`, `gate.fold_verdict`, `replay_divergence`; [무제한 경로](UNBOUNDED_TIME.md) |

O1의 대표값은 guard 결과를 보존하는 도구다. 원값이 출력되면 타입·정수 표현·signed zero·
문자열 변환까지 고려해야 한다. 예를 들어 `speak(t)`와 `speak(9)`가 임계값 대표 하나에서
같아도 전체 도메인에서 같다고 할 수 없다. 산술은 O1의 1차원 분할 증명으로 덮지 않는다.

O3은 지원 문장 규칙의 유일성을 보이고, 한 반응의 내부 실행에 대한 귀납으로 연결한다.
결정적인 준비·실행이므로 동일 입력 prefix의 결과도 귀납적으로 유일해진다.
O4에서 ACTION의 숫자 동치와 저장소의 타입 보존을 구별해야 미래 문자열 차이를 놓치지 않는다.

예를 들어 매 회차 `count`를 출력하고 증가시키는 쌍은 몇 개의 count를 시험하는 대신,
두 값의 초기 일치와 임의 정수에서의 출력·갱신 관계 보존을 검사한다.
고정 입력 이력의 빠른 실행은 전칭 의무의 대체가 아니므로 위 성공 증명의 근거에서 제외한다.

## 주정리로 연결할 구조

1. 준비 단계에서 프로그램·서비스·binding·허용 초기/입력 모델과 관찰을 고정한다.
2. 입력 축소 또는 해당 기호 경로가 모든 구체 실행을 포함함을 보인다.
3. 각 반응에서 같은 관찰과 후속 관계를 보존한다. 시간 생략과 상태 병합도 그 관계의 보존으로 연결한다.
4. 초기 포함 및 전이 보존을 모든 유한 실행 prefix에 귀납 적용한다.
5. 실제로 닫힌 관계 그래프 또는 종료한 모든 기호 경로에서 임의 미래까지 같은 관찰을 얻는다.
   각 유한 시간 prefix의 일치에서 전체 timed trace 일치를 도출한다.

그래프가 유한하게 닫힐 것이라고 가정해 성공시키는 것이 아니라, 폐쇄 여부를 실행 중
확인해야 한다. 원시 단계의 progress/유한 반응 조건과 경로별 soundness 전제도 주정리에
명시한다. 아래 L1–L7과 네 경로의 B0–B3 표가 그 대응을 제공한다.

## 보장 명제의 기준

앞선 G1–G6에서 대상/양화, 결정론성/관찰, 운영상 성공, 공통 귀납, 경계 검토와 논문
배치를 확정했다. D/S의 문구는 [계약](../model/VERIFICATION_CONTRACT.md#논문용-보장-명제)에만
둔다. 그때의 조건부 연결을 아래 L1–L7과 통합 정리로 구체화한다.

## 성공 조건과 증명 연결

대상 진입점은 `gate.prepare_pair → timed.timed_product`다. catalog 정합성, 접지,
기간·cron 앵커 검사와 실행기 선택은 `prepare_pair`가 수행한다. 평가 worker도 같은
준비 절차를 거친다. 자동 도메인을 manifest에 대표 목록으로 저장했을 때 원래 집합과의
대응은 그 manifest의 도메인 근거와 O1/O2를 통해 복원하며, 목록 자체를 전체 실제 값이라
부르지 않는다. 명시 subset 요청은 그 subset을 넘어 확장하지 않는다.

`timed_product`의 auto 경로는 관계 분석 → 적용 가능한 SMT → catalog 도메인 구성 →
구체 BFS 순으로 진입한다. catalog 열거 거절 또는 입력 조합 상한에서는 지원 가능한
값 흐름 경로를 시도한다. SMT/값 흐름은 명시 외부/초기 도메인을 일반 catalog 기호로
바꾸지 않는다. 관계 경로는 명시 외부 도메인을 유지하고 GV는 거절한다.

| 경로 | 진입·정상 성공·조기 반환의 코드 대응 | 성공에서 필요한 의미론 의무 |
| --- | --- | --- |
| 구체 BFS | `check_supported_pair`, 도메인 검사 및 조합 상한 뒤 모든 초기 조합을 `transition`에 넣음. 양쪽 종료는 비교 후 큐에 넣지 않음. 나머지는 모든 입력 후속을 처리해 큐가 비어야 마지막 반환. `incomplete`는 UNKNOWN/closed=false, mismatch는 DIVERGE | O1–O5. 같은 키의 미래 관계, 생략 구간의 무행동, 초기 포함 |
| 기호 값 흐름 | `symbolic_specs`의 순차 READ/CALL/DELAY/END 및 JoI 대입/호출/delay 문법. 각 이벤트 관찰을 비교한 뒤 양쪽 종료 때 종료. cap은 UNKNOWN, 다른 식은 `_witness`의 재생 DIVERGE 또는 UNKNOWN | typed 식의 모든 대입에 대한 관찰 일치, source/epoch 및 호출 인자 적합성 보존 |
| SMT | `smt_specs`의 acyclic one-shot/수치 도메인 검사. `Fork`는 양 분기를 큐에 추가. mismatch UNSAT/동일 식 뒤 종료·동일 signature·후속 처리. 비종료 `nxt=None`은 H=None에서 Incomplete. 큐 소진 성공에 `complete=true` | typed 수치 해석, 도메인/경로 포함, signature 중복의 안전성, 종료 경로의 침묵 |
| 정수 관계 | `analyze`의 한 주기·양의 period·clock/GV 제외 검사. 실제 첫 반응 후 `normalize`; `NeedBranch` 양 분기와 모든 입력 조합을 처리. ACTION/순서 있는 갱신/post 관계 실패 또는 cap은 미인증. 큐 소진의 유일한 `finish(success=True)`가 EQUIV/closed/complete를 설정 | 초기 관계, 임의 INTEGER 및 분기 과대 근사, 살아 있는 과거 값 보존, 일반화와 시간 이동 |

다음 제어 흐름의 작은 논증은 문서상 가정으로 남기지 않고 실제 함수와 대조했다.

1. **후속 시각 없음:** `IrRunner`와 `OneShotRunner`는 종료 때만 wakeup=None이다.
   `PauseRunner`의 비종료는 delay/period deadline 또는 다음 입력 재검사를 반환한다.
   `TerminalRunner`/`DoneLatch`의 종료 래치는 영구 무행동이다. 따라서 알려진 준비
   실행기에서 양쪽 wakeup=None은 미래 ACTION 없음이다. `DoneLatch`가 삼키는
   terminated 플래그를 양쪽 종료 플래그와 혼동하지 않는다.
2. **값 흐름의 비종료 성공 분기:** 지원 IR은 유한 순차 명령열이고 JoI는 run/delay
   segment뿐이다. 정상 반응이 아직 종료하지 않았다면 양의 잔여 delay에서 멈춘다.
   이때 wakeup은 미래 정수 시각이므로 `nxt=None`일 수 없다. H=None에서는 horizon
   중단도 없다. 따라서 실제 성공은 `both_terminated=true`를 남긴다. 임의 wrapper나
   문법 확장을 이 논증에 자동 포함하지 않는다.
3. **SMT 중복 처리:** signature는 양쪽 typed 저장소·절대 시각·전체 path/known을
   보존한다. 동일 시각의 world는 공통 `world_at`에서 나온다. 중복 반응도 ACTION
   검사를 먼저 수행하고, 처음 방문은 후속을 큐에 넣거나 Incomplete를 발생시킨다.
   정상 successor는 시간을 엄격히 늘리므로 같은 signature로 시간 순환을 닫지 않는다.
   큐 소진 성공의 `complete`와 H=None의 `both_terminated`를 단독 flag 이상의
   전칭 보증으로 연결하는 기호 해석은 아래 L6에서 도출한다.
4. **오류·상한:** IR의 fuel 소진은 Unsupported이고 JoI의 실행 상한도 성공 종료로
   바꾸지 않는다. 엔진별 cap/solver unknown은 위 표대로 미인증이다. gate의 예외
   처리는 REFUSED, 평가 worker의 오류/메모리 초과는 별도 실패다. 정상 성공 반환
   없이 프로세스가 중단된 경우는 `Accept∞`가 아니다. `constant_witness`는 재생한
   반례 또는 cap만 반환하며 그 성공 경로에 기여하지 않는다.
5. **공통 결과 접기:** `ProductResult.closed`의 기본 true는 폐쇄 증명이 아니다.
   `fold_verdict`는 UNKNOWN·미폐쇄 성공·미재생 반례를 REFUSED로, 명시 H 성공은
   EQUIV-BOUNDED로 구별한다. 엔진별 인증서를 다시 검증하는 독립 proof kernel은 없다.
   GV 소유 충돌·누락/빈 입력 도메인은 `check_supported_pair`/`validate_domains`가
   거절한다. 추가 경로가 생기면 이 대응을 다시 확인해야 한다.

## 공통 귀납

**D의 논증.** 지원 식은 고정 저장소·snapshot·clock에서 lookup과 타입별 연산으로
유일한 값 또는 오류를 낸다. 조건은 유일한 분기를 고르며, 대입/호출은 정해진 순서로
저장소/관찰을 갱신한다. delay/period는 진입/회차 완료 시각에서 유일한 deadline을,
wait는 현재 값과 저장된 edge/지속 상태에서 유일한 반응을 정한다. 유한 내부 단계에
귀납하면 `R`이 부분 함수임을 얻는다. 같은 시각에는 입력을 먼저 적용하고 순차 반응을
한 번 소진한다. 0ms delay는 그 반응 안에서 진행하며 무한 내부 순환은 정상 반응이
아니다. 이후 사건은 양의 정수 ms만큼 전진하거나 영구 무행동이다. 반응열에 다시
귀납하면 각 정상 실행의 timed trace가 유일하다. 파서/실행기가 이 규칙을 구현한다는
전문 대응은 O3/프런트엔드 의무이며, 이 규칙 논증만으로 전체 소스를 증명하지 않는다.

각 탐색 노드 `q`의 구체화 `γ(q)`를 **그 노드가 대표하는 구체 상태 쌍들의 집합**으로 둔다.
이미 관찰이 같다는 조건을 이 집합의 정의에 넣지 않는다.

| 경로 | `γ(q)`의 정의에 들어갈 대응 |
| --- | --- |
| 구체 BFS | 지원 술어의 진리벡터가 같은 원래 입력/저장된 복사값, 또는 exact 축의 같은 typed 값. 같은 제어·GV 출처·edge·종료 상태. 상대 시간 모드에서는 양쪽에 공통 시간 이동, 정확한 활성 timer 상대값과 입력 위상을 보존 |
| 값 흐름 | `(기기/member/리터럴 조회 인자, epoch, 타입)` 기호에 원래 도메인 값을 대입한 양쪽 저장소. 같은 기호는 같은 값, 저장된 과거 기호는 해당 epoch 값을 유지 |
| SMT | typed 기호를 해석했을 때 누적 도메인 제약과 path/known을 만족하는 상태 쌍. float 문자열의 미해석 함수에는 실제 변환 함수를 대입한 경우가 포함되어야 함 |
| 정수 관계 | 공통 slot을 임의 수학적 INTEGER로 해석한 두 저장소, 보존된 typed 상수·제어·timer·외부 입력. 초기화는 실제 값에서 시작하며 `normalize` 뒤의 전체 정수 집합은 과대 근사 |

구체 BFS에서 저장된 복사값은 수집한 출처를 따라 대응해야 한다. 단순히 현재 입력의
진리벡터만 같은 것으로는 부족하다. 각 표 행의 구체 정의와 전이 보존은 아래 L1–L7에서 전개하고, B0–B3에 연결한다.

- **B0 초기 포함:** 모든 `g₀,u(0)`의 실제 첫 반응을 포함하는 초기 검사가 있다.
  그 반응은 오류 없이 양쪽에서 같은 `O(A)`를 내며, 후속 쌍은 검사할 노드의 `γ`에
  포함되거나 양쪽 영구 무행동이다. 초기화의 ACTION도 이 조건에 포함한다.
  근거: O1/O2 및 실제 초기 루프/관계 초기화.
- **B1 반응 포괄·보존:** `s∈γ(q)`와 임의 허용 다음 입력에 대해 검사한 후속 중 하나가
  실제 반응을 포함한다. 그 반응은 오류 없이 양쪽의 같은 경과 시각에서 같은 `O(A)`를
  내며 후속은 `γ(q')`에 속하거나 양쪽 영구 무행동이다. 오류를 무행동으로 치환하지
  않는다. 근거: O2/O3 및 경로별 기호 해석.
- **B2 무관찰 시간·병합:** 압축 구간 안의 양쪽 반응은 오류 없이 무관찰로 진행하며,
  재개 상태의 대응과 가능한 최신 입력 전부를 보존한다. 같은 키 또는 일반화된 관계로의
  이동은 이 포함을 보존한다.
  시간 이동은 **쌍의 양쪽에 같은 양**을 적용하고 실제 경과 시간을 유지한다.
  근거: O4, 시간 생략/catalog 보조정리 및 관계 일반화.
- **B3 작업 완료·진행:** 구체 BFS·정수 관계의 성공 그래프는 모든 도달 노드의 후속
  검사가 끝났거나 해당 노드가 영구 무행동이다. 값 흐름·SMT는 같은 시각 상태의
  중복 처리를 제외하면 모든 경로가 종료했다.
  한 반응은 유한하고 후속 시각은 정수 ms에서 엄격히 증가한다. 근거: O5/O6와 위 반환 대응.

**연결 보조정리(조건부 증명).** B0–B3가 해당 엔진에 성립하면 그 엔진의 `Accept∞`는
계약의 S를 함의한다. 임의의 `g₀,u`를 고정한다. B0로 첫 반응의 대표를 잡는다.
이미 같은 관찰 prefix와 대응 상태를 얻었다면 B1로 실제 다음 입력을 포함하는 후속과
같은 관찰을 얻는다. B2로 생략된 구간은 빈 관찰로 채우고, 병합한 경우에도 대응을
계속할 수 있다. B3 때문에 검사되지 않은 후속을 만나는 일이 없다. 따라서 반응 수에
대한 귀납으로 모든 유한 반응 prefix가 같다. 임의 유한 시각 `t₀+T` 안의 반응 수는
유한하므로 그 시각까지의 관찰도 같다. 전체 열이 다르다면 어느 유한 시각에 첫 차이가
있어야 하므로 모순이다. 종료 후는 무행동으로 연장한다. 영원히 false인 wait에는
공정성이나 최종 true를 가정하지 않는다. 이 증명 어디에도 검증 horizon H는 없다.

## 통합 증명 실행 계획

증명 단위를 다음처럼 고정한다. 새 계획 파일이나 과거 기술 부록을 수정하지 않고
이 문서에 산출물을 통합했다. P1–P5를 완료했으며, 각 행의 논증과 실제 진입·반환
조건의 연결 및 별도 검토 반영을 확인했다. 테스트 성공을 보조정리의 전제로 넣지 않는다.

| 단계 | 작업·산출물 | 완료 조건 |
| --- | --- | --- |
| P1 | L1 입력 표현·L2 저장값 치환 | 원래 도메인의 모든 값에 대표/기호 대입이 존재하고, 과거 복사값·초기 GV·오류 가능성까지 대응 |
| P2 | L3 반응 규칙·L4 시간/키 | 지원 반응의 모든 명령 종류를 분류하고, 중단/재개·시간 이동·무관찰 생략의 보존을 도출 |
| P3 | L5 값 흐름·L6 SMT·L7 정수 관계 | 각 typed 연산, 분기, 일반화가 구체 실행을 포함하는 이유와 미지원 처리 설명 |
| P4 | 네 경로의 B0–B3 및 S | 운영상 성공에서 개별 의무를 도출하고 공통 귀납 적용. 인증 알고리즘과 신뢰하는 실행 의미를 구별 |
| P5 | 독립 검토·문서 검사 | 논리 누락 지적 반영, 모델/주장 문서와 상태 정합화. 구조 검사와 증명을 구별 |

## 경로별 세부 논증

아래는 **정의한 실행 모델에 대한 수작업 증명**이다. 대상은 계약의 준비된 프로그램과
고정된 네 인증 알고리즘이다. Python 소스 전체를 proof assistant로 검증했다는 의미가
아니다. 마지막 신뢰 기반 절의 타입별 기본 연산·준비/실행 구현 대응을 사용한다.
각 알고리즘의 입력 포함·병합·분기·성공 의무는 아래에서 도출하며 신뢰 기반으로 넘기지 않는다.

### L1 — 원래 입력의 표현 포괄성

쌍의 공동 사용 술어를 `Pₖ`, exact 출처 집합을 `E`라 하자. 자동 입력에서
`k∉E`이면 `ρₖ(x)`는 `x`와 `Pₖ`의 모든 진리값이 같은 대표다. `k∈E` 또는
명시 도메인이면 `ρₖ`는 항등이다. 초기 GV에도 그 이름의 공동 사용에 같은 구성을 적용한다.

**대표의 존재.** BOOL은 두 값을 전량 사용한다. ENUM/선언 members는 모든 원소와
허용 결측을 후보로 넣는다. INTEGER/DOUBLE의 단항 비교는 비교 상수에서만 진리값이
변한다. 배율 `s=1,10`에서 `floor(s·c)` 주변 세 격자점과 허용 격자의 양 끝을
후보로 넣으면 모든 비어 있지 않은 점/구간/꼬리를 포함한다. truthiness의 0도 포함한다.
DOUBLE 경계는 실제 비교 상수의 정확한 유리수에서 구하며, 자동 경계 허용 범위 안에서는
인접 0.1 값이 float 반올림으로 합쳐지지 않는다. 경계 밖 꼬리의 값은 새로운 술어
벡터를 만들지 않는다. bounds `[l,r]`로 자른 셀은
허용 격자의 첫 값과 마지막 값(`ceil(s·l)/s`, `floor(s·r)/s`)이 대표한다. 예를 들어
DOUBLE `[0.15,0.35]`에서는 0.2/0.3이며, 격자 밖 선언 끝점을 대표로 쓰지 않는다. 조건 전용
int/float 표현 및 signed zero는 같은 벡터로 합칠 수 있으나 exact에서는 모든 허용
정수 표현과 양쪽 zero를 보존한다. 큰/무한 exact 집합을 임의 표본으로 대신하지 않는다.

STRING에서는 빈 문자열이 최소값이고 `s+NUL`이 유한 사전식 문자열의 바로 다음
값이다. 따라서 상수, 상수의 바로 다음 값, 최소값이 모든 비어 있지 않은 셀을 대표한다.
nullable인 경우 None 후보도 넣는다. 타입이 없는 GV 모델은 계약이 지정한 계열에 대해
같은 후보를 합친다. 서로 다른 타입의 순서 비교처럼 이 구성이 인증하지 못하는 경우는
거절/명시 도메인 요구다. 후보 생성 후 **전체 공동 진리벡터**로 묶으므로 각 셀에 대표가
남는다. 이는 [입력 부록 §3–5](INPUT_COVERAGE.md#3-스칼라-입력의-분할)의 catalog 타입별
인스턴스이며, 구현은 `ServiceModel.representatives`, `representatives`, `initial_domains`다.

임의 `g₀,u`의 각 성분에 ρ를 적용하면 공통 대표 초기값과 전체 대표 입력 이력을 얻는다.
각 도메인이 비어 있지 않고 입력 변화 제약이 없으므로 매 격자의 곱 선택이 가능하다.
`W`의 초기값을 선택한 뒤에는 외부에서 갱신하지 않는다. 읽기 전용 GV와 holiday는
매 격자의 선택에 남는다. 쓰기 전 초기값을 읽지 않는 이름은 최초 쓰기가 값을 결정한다.
이는 초기 지역 변수의 임의값을 추가하는 논증이 아니다.

기호 경로에서는 ρ 대신 `σ(k,n)=u(n)[k]`를 사용한다. 값 흐름 기호는 원래 도메인
값 자체를 해석으로 허용한다. SMT의 타입/격자 인코딩은 L6, 관계 경로의 공통 정수
slot은 L7에서 포괄성을 보인다. 유한한 기호 실행에서 읽지 않은 epoch는 아무 허용값으로
채울 수 있으므로 기호 표현이 전체 입력 이력의 일부를 누락하지 않는다.

### L2 — 과거 저장값을 포함한 입력 치환

증명을 위해 원시 입력값에 `(k,n)`이라는 **ghost 출처**를 붙인다. 초기 GV는 별도
`(initial,w)` 출처, 상수/미초기화는 typed 상수/None이다. 복사는 이 표식을 복사하고,
bool 연산 결과는 실제 bool, 그 밖 계산 결과는 사용한 피연산자로 계산한 값이다.
이 표식은 증명용이며 실행 코드나 상태 키에 추가하지 않는다.

저장소 관계 `Rρ`는 같은 제어/래치/종료/내부 타이머 아래, 원시 복사값 `x@(k,n)`을
`ρₖ(x)@(k,n)`에, 초기 GV를 해당 초기 대표에, typed 상수와 계산 결과를 정확한 값에
대응시킨다. 같은 원시 읽기 사건은 양쪽에서 같은 대표를 쓰고, 과거 값은 **과거 n**에
속한다. 관계에 ACTION 동등성을 정의로 넣지 않는다. `γ_BFS(q)`는 이러한 표식을 가질
수 있고 `Rρ`로 q의 양쪽 대표 저장소에 대응하는 구체 쌍들의 집합이다. L4의 공통 시간
이동도 허용한다. 여러 이력이 같은 q에 도달하면 그 구체화의 합집합을 허용한다.

`Collector`는 모든 대입·분기·GV 쓰기의 정의를 합친다. 실행에서 복사된 값의 출처는
실제 대입 이력 길이에 대한 귀납으로 이 정의 그래프에 포함된다. 그래프의 방문 이름
중복 제거는 외부 잎까지 가는 단순 경로를 보존한다. 그러므로 오래 저장된 값이나 다른
분기에서 대입된 값의 사용도 수집한 공동 술어/출처 안에 있다.

식의 구조에 귀납한다. 읽기·복사는 `Rρ`의 정의를 따른다. 원시값–리터럴 비교는 L1의
벡터로, 그 bool 합성은 동일한 bool로 보존된다. 읽기끼리의 비교, 산술·변환·함수의
피연산자, ACTION/GV 쓰기로 흐르는 원시값은 `Collector.compare/visit/run`이 exact으로
보낸다. 이 경우 피연산자가 typed 값까지 같으므로 결과 또는 실행 오류도 같다.
상수·내부 계산값은 동일 연산에서 정확히 전개한다. 초기 GV/복사값과 bool 결과의
비교도 가능한 잎의 곱을 수집하므로 빠지지 않는다. 미지원 식은 coverage 오류 또는
경로의 거절을 낸다. 따라서 **정상 대표 반응이 포괄하는 원래 반응도 정상**이며, 같은
분기·ACTION과 `Rρ`인 후속 저장소를 얻는다. 이를 문장과 회차에 반복 적용한다.

이 증명은 두 프로그램의 지역 변수 이름이나 저장소가 서로 같다고 요구하지 않는다.
각 프로그램의 원래 실행과 그 프로그램의 대표 실행을 먼저 연결한다. BFS가 두 대표
실행의 ACTION을 비교하므로 동등성의 추이성으로 두 원래 실행의 ACTION도 같아진다.

**입력 복사 상태와 exact 출처 guard의 사전조건 완화 (2026-09-11).** 위 논증은 복사값의
출처와 exact 출처를 이미 다루므로 두 사전 거절을 좁혔다. (i) `finiteness_check`는 모든
정의가 외부 읽기(clock 제외)·리터럴·bool 결과·그런 변수의 복사인 carried 변수를 유한으로
본다(`explore._input_copy`). 값은 출처 도메인 값·유한 상수·bool·None 중 하나이고 상태 키가
그 값을 그대로 담으므로 이 검사는 종료성 사전 점검일 뿐 새 치환 규칙이 아니다. 산술을 거친
복사는 계속 거절한다. (ii) joint/derived-guard(D7)는 1차원 대표값이 결합 경계를 놓칠 수
있어 거절한다. guard의 모든 출처 키가 `E`(exact)에 있고 주어진 도메인 키이면 L1에서 `ρₖ`가
항등이므로 놓칠 대표값이 없다. `features.exact_enumerated`는 이 경우만 finding을 제거하고,
출처를 이름으로 대응시키지 못한 guard는 그대로 거절한다. 이 긍정 판정은 주어진 유한
도메인에 대한 전수 검증이며 도메인이 실제 센서 값을 포괄한다는 전제는 남는다. 회귀는
`test_input_copy_state.py`(손 trace 증인 포함; 변경 전 코드에서 4/5 실패)다.

### L3 — 반응 규칙의 보존과 결정론성

표의 원시 규칙에 식 귀납(L2 또는 L5–L7)을 적용하고, 실행된 내부 문장 수에 귀납한다.
서로 다른 IR/JoI 명령열의 문장별 일치를 전제하지 않는다. 각자 자신의 구체/대표 또는
구체/기호 실행에 대응하며 **전체 반응의 ACTION**을 product에서 비교한다.

| 규칙군과 실제 분기 | 귀납 단계 |
| --- | --- |
| READ, 결과 CALL, 변수/GV 읽기 | 고정 key/리터럴 query args와 현재 epoch의 값을 읽는다. 변수는 저장된 값을 읽는다. 조회가 입력으로 허용되는지 준비 단계가 검사하고 누락 축은 거절. 조회 자체를 ACTION으로 만들지 않음 |
| 일반 대입, `:=`, GV set | RHS 대응을 저장소에 대입. `:=`는 runner의 첫 회차/일회 segment 활성 조건을 보존. GV set은 저장소와 해당 ACTION을 모두 갱신. 부분 식의 숨은 GV 쓰기는 거절 |
| CALL 및 fanout | 인자를 같은 순서로 평가하고 catalog 타입/범위를 검사한 뒤 같은 target/method/args를 관찰. 단일 호출의 독립 target 사슬만 정렬하므로 O의 동치는 순차 호출이나 중복을 지우지 않음 |
| IF, GOTO, bool 합성 | 동일 조건값 또는 해당 구체 대입을 포함하는 기호 분기를 택한다. AST가 정한 피연산자 평가와 분기 순서를 유지하며 단락 평가를 임의로 추가하지 않음 |
| DELAY | 최초 진입에 정확한 시작값을 저장. 만료 전에는 pc/continuation 보존, 만료에 다음 문장 진행. 0ms는 현재 유한 반응 안에서 진행 |
| WAIT level/edge/sustain/timeout | 동일 현재 조건과 p/s/t 레지스터에서 동일 fired/timeout을 얻는다. false sustain은 시작값 제거, edge는 현재 wait 평가 때만 p 갱신. fired 우선·그 뒤 timeout 검사 순서도 유지 |
| ENTER_CYCLE, TOP, END_ITER | 진입 count 초기화, count/until/period 검사, 완료 뒤 increment/period 시작을 각 규칙 그대로 수행. 중첩 진입/이탈의 pc와 레지스터도 보존 |
| JoI Loop/Break, block/segment/path | 유한 loop 내부 실행에 귀납. break의 가장 가까운 loop/프로그램 대상, 중첩 if continuation을 보존. pause 후 저장된 가지로 재개하며 진입 조건을 다시 고르지 않음 |
| 완료/종료 wrapper | 종료 래치 이후 ACTION 없음. `DoneLatch`는 flag를 삼켜도 `__fin`과 wakeup=None으로 영구 침묵. Catalog wrapper는 위 유효성 검사만 추가 |
| 오류/연료 | 정상값을 만들 수 없거나 IR fuel/JoI loop cap이 소진되면 정상 인증으로 연결되지 않음. 추상 실행의 미지원은 `Unsupported`이며 값/침묵으로 바꾸지 않음 |

구체 경로의 `check_finite`는 성공의 충분한 **탐색 종료 증명**으로 쓰지 않는다.
실제 `timed_product`는 저장된 사용자 값을 포화시키지 않고 typed 값을 유지한다.
컴파일 시 수행하는 named-counter 변환과 소스 접지는 준비 표현과 원문의 대응 영역이다.
여기서는 계약대로 준비된 프로그램의 실제 명령열을 실행한다. 그 단계에 대한 별도
수작업 대응을 전체 Python 구현의 기계 증명과 혼동하지 않는다.

고정된 구체 값에서 표의 각 규칙은 유일한 결과/오류를 가지므로 유한 반응에 대한
귀납으로 D의 반응 유일성을 얻는다. L4의 정수 시간 진행과 종료 확장을 적용하면 정상
전체 trace도 유일하다. 대표 성공의 정상성은 L2에서, 기호 성공의 정상성은 L5–L7의
연산/서비스 유효성에서 얻는다. 오류를 동등한 빈 ACTION으로 간주하지 않는다.

### L4 — 시간 생략과 상태 키의 미래 보존

**사건 포괄.** 반응 직후 다음 외부 격자, 양쪽 runner의 미래 deadline, 필요한 clock
초 경계 중 최솟값을 선택한다. 그 사이에는 snapshot이 같고 조건에 영향을 주는 clock
값과 활성 타이머 만료 여부가 변하지 않는다. wait를 같은 조건으로 재평가해도 edge/
sustain/timeout의 반응 후 레지스터가 변하지 않는다. 양쪽이 input-blind delay/period
또는 종료이면 더 강하게, 중간 입력이 무엇이든 다음 필수 만료 전에는 명령을 실행하지
않는다. 이는 `suspension`이 인식하는 정확한 실행기·wrapper의 해당 차단 분기에서
직접 따른다. 그 구간에는 새 인자 평가나 오류도 없다.

따라서 `silent_deadline`의 최솟값으로 이동해도 중간 관찰은 빈 열이고 continuation과
과거 저장값은 그대로다. 하나 이상의 격자를 넘었으면 재개 시 가능한 **최신 전체 입력
곱**을 선택한다. 넘지 않았으면 held 입력을 유지한다. 중간 입력과 최신 입력 사이에
변화율/공정성 제약이 없으므로 임의 실제 이력의 재개 snapshot이 반드시 포함된다.
한쪽만 wait 중이면 이 생략을 쓰지 않는다. `constant_witness(held_waits=True)`는
반례 진단 전용이며 이 보조정리의 전칭 생략 규칙이 아니다.

**키 병합.** 절대 시간 모드는 전체 typed 저장소·GV·held 입력·현재 절대 시각을
키에 넣는다. `freeze_state`는 타입, signed zero, 구조, pc/continuation, edge와 종료
래치를 구별하므로 키가 같으면 같은 다음 입력에 대한 반응과 후속 키가 같다.
알 수 없는 저장 타입은 문자열 repr로 병합하지 않고 거절한다.

상대 모드에서는 사용자가 관찰할 수 없는 **컴파일러 소유 timer**만 `now−start`
(예약된 다음 시작값이면 부호 있는 상대값)으로 바꾼다. 두 노드의 시간 차이를 h라 하면
그 timer와 현재 시각 모두 h만큼 이동하고, `(now−t₀) mod Δ`가 같으므로 미래 격자의
상대 위치도 같다. 모든 deadline 비교는 동일한 정수 차이로, 다음 입력은 동일한 상대
시점으로 대응한다. 새 timer를 만들 때에도 이동 관계를 유지한다. ACTION timestamp는
삭제하는 것이 아니라 두 실행에 같은 h를 더해 운반한다. 사용자 clock/저장 timestamp는
이 규칙으로 지우지 않는다.

catalog 상수 비교가 있는 경우에는 각 직접 clock 읽기의 실제 범위가 선언 구간에
포함된다. `interval_comparison`의 부등식은 가장 불리한 끝점으로 전 구간의 참/거짓을
결정한다. equality는 구간 분리 또는 같은 singleton일 때만 결정한다. 따라서 **비교
전체의 결과**가 시간 이동 전후 같으며 읽기 자체에 부작용도 없다. 모든 clock 사용이
그런 식 내부에 있을 때만 위 상대 관계를 적용한다. `hour==12`, 저장된 clock, 모르는
wrapper는 이 근거를 얻지 못한다. 원래 AST를 실행하므로 상수 분기를 삭제한 코드의
정답성을 추가 가정하지 않는다.

모든 정상 후속 시각은 정수 ms에서 엄격히 증가한다. 0ms 명령은 이미 유한 반응 안에서
처리한다. 따라서 유한 시간 구간에는 유한 횟수의 product 반응만 있고, 생략 구간의
복원도 유한하다. 양쪽 wakeup=None인 알려진 준비 runner는 미래에 영구 침묵한다.

### L5 — 값 흐름 경로의 보편 해석

값 흐름의 저장소는 typed 상수, `InputSymbol(k,n,type,nullable)`, 그리고 문자 조각과
기호의 열인 `TextTerm`으로 해석한다. `⟦InputSymbol(k,n)⟧σ=σ(k,n)`이며 TextTerm은
각 조각을 계약의 변환(None→빈 문자열 포함)으로 문자열화해 순서대로 연결한 값이다.
`γ_V(q)`는 q의 기호 저장소에 하나의 공통 σ를 대입한 모든 구체 쌍이다. pc/segment·
종료 래치와 정확한 timer/현재 절대 시각은 q와 같고, held 입력은 현재 epoch의
`σ(k,epoch)`다. 과거 저장 기호는 자신의 epoch를 그대로 해석한다. 타입/nullable은
그 기호의 허용 대입 집합을 제한한다. 입력 인코딩의 key에는 구체 기기와 typed 리터럴
조회 인자가 들어가므로 서로 다른 장치나 `q(1)`/`q(1.0)`를 같은 기호로 만들지 않는다.

L1에 의해 모든 실제 이력은 σ 하나를 준다. 읽기와 복사는 정의상 해석을 보존한다.
문자열 연결은 결합법칙, 빈 문자열 항등법칙, 인접 리터럴 연결만 정규화하므로 같은
TextTerm은 모든 σ에서 같은 문자열이다. `symbolic_add`는 실제 STRING 리터럴/이미
변환된 TextTerm이 한쪽에 있을 때만 이 규칙을 사용한다. nullable STRING 둘이 None일
때의 `None+None=0`을 문자열로 잘못 바꾸지 않는다. 그 밖 기호 산술/조건은 거절한다.
변환된 text의 unrestricted STRING 적합성, 또는 non-null raw STRING의 적합성만
인증하므로 두 프로그램이 함께 잘못된 호출을 하는 경우를 성공으로 만들지 않는다.
상수 호출은 일반 catalog 검사를 통과해야 한다.

지원 명령열에는 입력 의존 분기·반복이 없다. 식 귀납과 L3으로 각 반응이 모든 σ의
정상 구체 반응을 나타낸다. O의 구조적 동일성은 typed 기호의 해석과 교환하므로 모든
σ에서 ACTION이 같다. fixed delay와 epoch 유지에는 L4를 적용한다. 정상 비종료는
남은 양의 delay뿐이므로 H=None에서 successor 없이 성공할 수 없고, 실제 성공 시
양쪽 명령열이 끝났다. 이후 모든 입력은 무행동이다. 이것으로 B0–B3를 얻는다.
서로 다른 식은 이 충분조건의 실패일 뿐이며, 표본 반례 탐색의 실패는 인증이 아니다.

### L6 — SMT 경로의 포괄·typed 연산·UNSAT

`γ_S(q)`는 q의 typed 저장소를 공통 기호 대입 σ로 해석한 쌍 중 입력 도메인 D와
누적 분기 Φ를 만족하는 쌍이다. 제어/종료/정확한 timer와 현재 절대 시각은 q의 값이고,
held 입력은 `world_at(q.now)`를 같은 σ로 해석한 값이다. 과거 epoch의 기호와 그
제약도 유지한다. float 문자열 함수 F는 비트열→문자열 함수로 해석하며,
그 해석들에 실제 변환 함수를 포함한다. 이 정의는 관찰이 같다는 조건을 포함하지 않는다.

**입력.** INTEGER는 bounds 안 정수 n, DOUBLE은 bounds를 10배 한 정수 n과 표현
선택 kind를 사용한다. int 표현이면 `n mod 10=0`, float면 정확한 n/10을 binary64로
반올림하고 n=0에서 sign을 선택한다. nullable이면 별도 kind가 None이다. 따라서 모든
허용 실제 값에 대입이 있다. 같은 `(k,epoch)`는 `world_at`의 같은 Input을 사용하고
캡처된 값은 그 기호를 유지한다. 읽지 않은 축을 늦게 만드는 것은 투영한 제약의 축만
늘린다. `Context.domains`에 다른 경로에서 읽은 기호가 남아도, 각 항은 독립된 nonempty
입력 도메인만 규정한다. 같은 키/epoch면 원래 필요한 제약이고 다른 키/epoch면 현재
실행 대입을 확장할 수 있으므로 실제 경로를 제거하지 않는다. Φ/known은 노드별이다.

**식 해석.** 다음 표는 허용된 기호 연산 전체를 구성하는 경우다. 상수끼리 연산은
원래 실행기의 연산이며, 지원되지 않은 기호 메서드는 `Unsupported`다.

| 연산 | 구체 해석과의 대응 |
| --- | --- |
| int `+,-`, 단항 `-`, abs, 상수 곱 | 수학적 정수 연산 그대로. 구조 귀납으로 피연산자 값과 결과가 대응 |
| float가 포함된 `+,-,*` | int 피연산자를 binary64 RNE로 변환한 뒤 해당 FP 연산. 실제 연산 순서를 유지하며 실수 대수의 재배열을 사용하지 않음 |
| 상수 나눗셈 | int/int는 정확한 유리수 몫을 한 번 FP 반올림, float 포함은 FP 나눗셈. 0 제수는 모델의 0. 음수 정수로 나눈 0의 음의 zero를 별도 보존 |
| 숫자 비교/진릿값 | int/int는 정수 비교, 혼합은 유한 FP의 정확한 실수값과 정수값 비교. 먼저 int를 float로 반올림하지 않음. truth는 0과의 불일치 |
| None 및 bool | None kind를 구체 None으로 실행하므로 기존 None 비교/산술 규칙 적용. 기호 bool은 분기와 같은 bool 비교만 허용하며 숫자와의 미인증 coercion은 거절 |
| int→text | 음수 부호와 절댓값의 십진 정수 문자열을 정확히 연결 |
| float→text | 하나의 공유 F에 64비트 표현을 인자로 전달. 실제 formatter를 F로 해석하면 정확한 결과. signed zero와 서로 다른 표현을 임의로 동일시하지 않음 |
| text 연결/ACTION 동치 | 문자 연결과 관찰의 typed 태그를 보존. numeric ACTION은 수치 equality, bool/number 및 string/number는 태그가 다름. 호출 경계와 target 사슬은 O를 그대로 사용 |

수치 magnitude는 입력 bounds와 상수의 절댓값에서 시작한다. 합/차는 절댓값 상한의 합,
곱은 곱, 상수 나눗셈은 절댓값 몫을 사용하고 매 단계 `nextafter(…, +∞)`로 바깥쪽
반올림한다. 단항 부호/abs는 상한을 유지한다. 이 상한은 각 실제 결과를 포함하며
유한성/`≤1e100` 검사는 FP overflow 가능 영역을 인증에서 제외한다. 값을 이 범위로
**제약해 잘라내는 것**이 아니라 식 전체를 거절하므로 입력 포괄성을 해치지 않는다.
연산은 유한 입력/허용 중간값에서 정의되고 서비스 numeric 인자 범위는 `require`로
전칭 검사한다. text 인자는 unrestricted STRING만 인증한다.

**분기.** 처음 만난 기호 bool b에서 동일 반응 전 상태를 `Φ∧b`, `Φ∧¬b` 두 작업으로
확장한다. 구체 대입은 반드시 그중 하나에 속한다. 이미 알려진 정확히 같은 식의 bool은
동일 대입에서 같은 답을 가져 재사용할 수 있다. 반응 재실행은 복사한 저장소에서
시작하므로 실패한 시도의 부분 대입/ACTION이 다음 시도에 누적되지 않는다. 가능성이
없는 분기까지 검사하는 것은 과대 근사이며 실제 분기를 없애지 않는다.

**인증.** 성공 사건은 `D∧Φ∧¬Eq_O(A_I,A_C)`가 UNSAT(동일 식으로 false가 된 경우 포함)이다.
만약 실제 대입에서 ACTION이 다르다면 실제 formatter 해석까지 포함해 이 식의 모델이
생기므로 모순이다. `require`도 `D∧Φ∧¬Valid`가 UNSAT여야 하므로 정상 호출임을 얻는다.
SAT를 성공으로 바꾸지 않고, unknown/cap/실행 미지원도 성공이 아니다.

동일 signature는 전체 typed 저장소·절대 now·Φ/known을 보존하고 같은 now의 world도
공통이다. ACTION은 중복 확인 전에 검사한다. 최초 방문의 후속이 검사되므로 후속 작업
재사용이 가능하다. 시간은 증가하므로 같은 signature를 시간 순환의 불변식으로 쓰지
않는다. H=None의 비종료 successor 부재는 Incomplete이고 실제 queue 소진 성공은
모든 작업의 종료로 이어진다. 무한 false wait가 남으면 이 완료 조건을 얻을 수 없다.
식 귀납→분기 포함→L3 반응→L4 시간의 순서로 B0–B3를 도출한다.

### L7 — 정수 관계 경로의 귀납적 일반화

이 경로는 정확히 한 top-level named cycle과 같은 양의 completion-relative period,
하나의 선두 INTEGER 초기화, no clock/GV를 검사한다. 외부 입력은 직접 guard에서만
사용하며 공동 대표는 L1–L2를 따른다. 초기 반응은 실제 빈 저장소/실제 초기값에서
실행한다. count가 처음부터 같다는 가정을 넣지 않는다.

`PairInt` 식의 문법은 `z`, 정수 리터럴, 두 식의 `+,-`다. `⟦z⟧ν=ν∈ℤ`로 정의하고
연산을 수학적 정수로 해석한다. `RelText`의 `IntToText`는 해당 정수의 정확한 십진
문자열이다. `γ_R(q)`는 q의 모든 공통 slot에 같은 ν를 대입한 저장소와, 보존된 typed
상수/제어/래치/타이머/입력에 대응하는 구체 쌍이다. 시간 관계와 입력 치환은 L4/L2를
합성한다. ν는 가능한 실제 count 집합보다 넓어도 된다.

식 구조에 귀납하면 같은 정수식과 text식은 모든 ν에서 같은 값이고 정수 연산은
항상 정의된다. `integer_text.value_text`는 절댓값을 10⁹로 나누어 나머지 묶음을
만든다. 몫은 엄격히 감소하므로 각 정수에서 종료하고, divmod 항등식과 9자리
zero-padding으로 원래 정수의 십진 표기를 복원한다. 따라서 count가 커져도 Python의
단일 거대 정수 문자열 변환 제한에 의존하지 않는다. RelText는 unrestricted STRING 인자만 인증한다. 기호 count를 raw
범위 제한 인자로 보내거나 미지원 연산을 하면 거절하므로 미검사 인자 오류가 없다.
정수 비교 b의 `NeedBranch`에서는 두 bool 선택을 모두 실행한다. 구체 ν의 답은 반드시
포함되며, 같은 반응의 같은 비교식은 같은 선택을 공유한다. 서로 다른 비교 사이에
불가능한 조합을 허용하거나 다음 반응에서 과거 선택을 잊는 것은 집합을 넓힌다.
불가능한 분기의 실패가 인증을 막을 수 있어도 실제 실행을 빼고 성공시키지는 않는다.

각 반응에서 O의 동일성 외에 ACTION과 선택 counter 갱신의 **순서 있는 열**도 비교한다.
이는 필요한 ACTION 동치보다 강한 충분조건이다. 반응 후 양쪽 count는 typed 동일
정수/같은 PairInt 식 `f(z)`여야 한다. 이제 실제 ν에서의 공통 값 `m=f(ν)`를 새 slot
해석으로 택하면, `normalize`가 count를 자유로운 z로 바꾼 후의 집합에도 이 후속이
포함된다. f가 전사일 필요는 없다. 새 집합은 모든 정수이므로 도달값의 상위 집합이다.

다른 저장 변수가 같은 f이면 동일 새 slot으로 바꾸어 상관관계를 유지한다. 다른
살아 있는 과거 PairInt/RelText/RelBool이 남으면 이 단일-slot 표현으로 안전하게 바꿀
수 없으므로 거절한다. 예를 들어 `old=z`, `count=z+1`을 둘 다 새 z라고 만들지 않는다.
코드 회차 완료 경계에서만 `entry_live`가 죽었다고 증명한 local을 제거한다. 이 분석은
뒤에서 앞으로 read를 더하고 확실한 대입에서만 kill하며, if의 두 갈래를 합집합하고,
회차 간 live 집합이 닫힐 때까지 반복한다. 따라서 제거된 변수는 다음 읽기 전 모든
경로에서 덮어써진다. `:=`는 후속 회차에서 건너뛰므로 kill이 아니고, pause 중에는
이 제거를 하지 않는다. 제거 전후 미래 관찰이 같다는 것을 다음 최초 읽기까지의
문장 귀납으로 얻는다.

이로써 실제 초기 반응에서 얻은 후속은 최초 일반화 집합 안에 있고(B0), 임의 ν/외부
입력에서 반응·post 관계가 유지되며(B1), 일반화·dead local 제거·L4 시간 키 병합은
그 후속을 포함한다(B2). 모든 새 키와 분기/입력 곱을 검사한 뒤 queue가 비어야 유일한
성공 반환에 도달하므로 B3이다. 임의 회차에서의 유지가 증명되므로 무한히 증가하는
count도 H 없이 인증할 수 있다. 다른 갱신/분기 구조의 동등한 프로그램까지 반드시
인증한다는 뜻은 아니다.

## 통합 정리의 도출

| 실제 성공 경로 | B0 초기 | B1 반응 | B2 압축/병합 | B3 완료 |
| --- | --- | --- | --- | --- |
| 구체 BFS | L1의 전체 초기×입력 곱, L2–L3 첫 반응 | L1–L3과 모든 다음 입력 곱. 관찰 검사 후에만 저장 | L2의 출처 관계 + L4의 정확 키·시간 | 새 키를 한 번씩 queue에 넣고 전 후속 처리. 정상 소진 또는 영구 침묵 |
| 값 흐름 | L1/L5의 모든 σ, 실제 초기화 | L5 식 해석 + L3 | L4, 과거 epoch 보존. 시간 순환 병합 없음 | L5의 유한 명령열 종료 |
| SMT | L6의 D/타입 분기와 모든 실제 초기 반응 | L6 양분기 포함·UNSAT·Valid + L3 | L6 exact signature + L4 | L6의 모든 작업 종료, 비종료 누락은 Incomplete |
| 정수 관계 | L7 실제 초기화 확인·일반화 포함 | L7 모든 ν/분기/입력에서 ACTION/post + L3 | L7 집합 포함·liveness + L4 | L7 관계 그래프의 모든 후속 검사 후 소진 |

**정리 S의 증명.** 계약의 운영상 `Accept∞`를 가정한다. 진입 조건과 정상 반환 분석에
따라 위 네 행 중 하나의 성공이며, 표의 해당 보조정리로 B0–B3가 성립한다. 임의
`g₀∈G₀`, `u∈U_M`를 고정하고 [공통 귀납](#공통-귀납)의 연결
보조정리를 적용한다. 초기 ACTION을 포함하는 모든 유한 반응 prefix가 오류 없이 같고,
L4의 진행성으로 임의 유한 `t₀+T` prefix도 같다. 첫 차이가 있는 무한 trace라면 어떤
유한 시각에 그 차이가 있어 모순이다. 따라서 S가 성립한다. 이 증명은 유한 H까지의
성공을 확장하거나 모든 프로그램의 그래프가 닫힐 것이라고 가정하지 않는다. ∎

**정리 D의 증명.** L3의 구체 식/문장 유일성 귀납에 L4의 유일한 다음 사건과 정수
시간 진행, 종료 후 침묵 확장을 적용한다. 고정 `P,M,g₀,u`에서 정상 timed trace는
유일하다. 이는 solver 탐색/timeout 결과의 재현성과 별개의 명제다. ∎

증명의 수준은 **선언 모델·typed 기본 연산과 준비/실행기 대응을 신뢰하는 인증
알고리즘의 수작업 soundness 증명**이다. 네 경로의 핵심 보조정리를 가정한 조건부
연결에서 더 나아가 그 보조정리를 위에서 도출했다. 실제 배포 런타임과의 대응, Python
전체의 기계 검증, 독립 proof checker의 인증은 이 완료 범위에 포함하지 않는다.

## 논문 주장과 근거의 배치

| 주장 ID | 논문에 둘 내용 | 근거·허용 문구의 경계 |
| --- | --- | --- |
| VETS-D | 같은 모델·초기 상태·입력 이력에서 유일한 실행 관찰 | 이론 주장. 반응 규칙 귀납과 실행 진행 조건이 필요. LLM 생성/timeout 결과의 결정성 주장이 아님 |
| VETS-S | 계약의 H 없는 성공 함의 | 이론 주장. L1–L7·네 경로의 B0–B3·공통 귀납으로 도출한 수작업 정리. 아래 신뢰 기반을 명시 |
| VETS-IMPL | 알고리즘과 구현의 대응 및 오류 방어 | 프런트엔드 대응·독립 kernel의 해당 조각·기존 회귀·반례 재생. 전체 소스의 기계 검증으로 표현하지 않음 |
| VETS-EVAL | 선택한 corpus의 인증·불일치·거절·오류 및 실행 비용 | 경험 주장. [생성된 평가와 연결 감사](../paper/EVALUATION.md)만 수치 기준으로 사용. 개발 재평가이며 정확도 100%·새 held-out·모든 경로의 실증 지원으로 확장하지 않음 |

본문은 **최소 모델 정의 + D/S 두 명제 + 하나의 증명 개요 + 경로별 충분조건 표**로 구성한다.
고정 binding·입력 격자 같은 전제는 모델 설명에 한 번 둔다. 매 문장·초록에 반복할 필요는
없지만, 독자가 물리 센서의 모든 연속 시각을 검증한다고 오해하게 생략하지 않는다.
문장별 규칙·typed 수치·키 병합·네 경로의 상세 귀납은 부록에 둔다. 최종 분량은 원고 편집 때 정한다.

도식은 선택 사항이다. 넣는다면 “구체 실행→입력/상태/시간 축소→공통 관찰 관계” 하나로
O1–O6과 시간/기호 의무의 연결을 설명한다. 테스트 수치를 정리의 증거로 연결하는 화살표는 넣지 않는다.

방법의 배경 인용 후보는 원문으로 확인했다. Clarke, Emerson, Sistla (1986),
[Automatic Verification of Finite-State Concurrent Systems Using Temporal Logic Specifications](https://ix.cs.uoregon.edu/~michal/Classes/04u/fsv/readings/ClarkeEmersonSistla-86.pdf)는
유한 상태 모델의 시간 논리 검증 배경에, Alur와 Dill (1994),
[A Theory of Timed Automata](https://www.cis.upenn.edu/~alur/TCS94.pdf)의 §1.1/§3.1은 시간 관찰과
시간 진행 조건의 배경에 사용한다. Explorer가 이들의 알고리즘/region abstraction을
그대로 구현했다거나 이 인용이 VETS-S의 증명을 대신한다고 쓰지 않는다.

## 별도 검토와 반영

명제 초안·확정 문구·통합 증명에 각각 대화 이력을 전달하지 않은 단일 검토자를
사용했다. 모두 **부분 Methods/증명 검토**이며 전체 원고·평가·관련문헌 재감사가
아니다. 통합 증명 검토는 Critical 0 / Major 0 / Minor 2였고, 선언 모델·고정 인증
알고리즘·명시한 실행/프런트엔드 신뢰 기반에 한정한 수작업 증명 완료가 타당하다고
판단했다. 아래 두 보완을 반영했다. 검토에서 반례를 찾지 못했다는 사실을 증명이나
모든 결함 부재의 근거로 사용하지 않는다.

| 단계·지적 | 반영 |
| --- | --- |
| 명제 초안 Major: 초기 GV/외부 입력/파생 clock의 분류 | 계약에 `W`와 읽기 전용 GV/holiday/파생 clock을 구별. 공통 지원 검사의 소유 충돌 거절과 연결 |
| 확정 문구 Minor 2건: 생략 구간의 정상성, 기호 경로 종료의 범위 | B2에 오류 없는 침묵/재개 관계, B3에 BFS·관계의 그래프 폐쇄와 값 흐름·SMT의 경로 종료를 구별 |
| 통합 증명 Minor: 기호 구체화의 상태 성분 | L5/L6에 제어·종료·정확 timer·절대 now·held 입력의 공동 대입과 과거 epoch를 명시 |
| 통합 증명 Minor: catalog 범위 끝점과 격자 끝점 | L1에 `ceil(s·l)/s`, `floor(s·r)/s`와 `[0.15,0.35]→0.2,0.3` 예를 명시 |

검토자는 파일 수정·실험/테스트 실행·관련문헌 재검색을 하지 않았다. 구현 대응은
정적 검토다. 이번 실행은 증명/계약 연결/상태 문서만 갱신했으며 기존 평가 결과와
테스트 수치를 새 실험으로 재기록하지 않았다. 문서 관리 검사는 구조·링크·동결 자료의
정합성을 확인하며, 의미론 증명의 완료 판정으로 사용하지 않는다.

## 신뢰 기반

- 모델이 사용하는 typed lookup/연산, 정확한 정수·유리 timer, binary64 RNE와 십진 변환을 기본 의미로 둔다. Python의 해당 연산 및 실행기/프런트엔드와 이 규칙의 대응은 소스 수작업 검토를 신뢰한다. 실제 프로세스의 무한 메모리/시간을 보장하는 명제가 아니다.
- Z3의 UNSAT 판정과 정수/FP/문자열 이론 구현을 신뢰한다. **어떤 수식을 인코딩하고 왜 실제 실행을 포함하는지**는 신뢰를 선언해 생략하지 않고 L6에서 논증했다. 독립 proof checker나 solver proof object 재검사는 구현하지 않았다.
- 함수별 코드 검토·회귀/독립 kernel·수작업 증명은 서로 다른 근거다. 전체 Python 소스/파서/컴파일러가 proof assistant로 검증되었다거나 테스트가 모든 버그를 배제한다고 주장하지 않는다.
- 독립 kernel 밖의 모든 언어 구성을 두 번째 구현으로 검증한 것은 아니다. 과거 테스트 수치는 당시 모델/버전으로 한정한다.
