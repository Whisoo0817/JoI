# 격자 타이머 관계 탐색 — timer-zones-v2

2026-09-14. `timer_analysis.py`, `timer_domain.py`, `timer_product.py`의
수작업 논증이다. 전체 구현의 기계 검증은 아니다.

## 적용 조건

기존 입력 포괄·유한성·기능 거절 검사를 먼저 통과한다. 정확히 알려진
IrRunner, PauseRunner, OneShotRunner 및 종료/catalog wrapper만 받는다. 반복 JoI period는
입력 간격 Δ와 같아야 하고 모든 IR period/delay/for/timeout은 Δ의 정수
배수여야 한다. 격자 위 wait/delay와 유한 제어용 이름 카운터는 받는다.
JoI loop, 무한 이름 카운터, GV, IR 질의 및 매개변수 질의와 외부 clock
덮어쓰기는 받지 않는다. Hour 및 제한된 timestamp snapshot은 아래 별도 전제를 따른다.

`x = x + 1`로 증가하는 JoI 변수를 선택한다. 다른 대입은 정수 상수
초기화/리셋뿐이고 사용은 직접적인 정수 상수 비교뿐이어야 한다. 다른 변수나
ACTION/질의 인자로 흘러가면 거절한다. 실제 한 반응에서 여러 번 증가해도
원래 문장을 모두 실행하여 후속 관계에 반영한다. 선택한 기호 값이 예상하지
않은 저장소나 ACTION에 남는 경우도 거절한다.

Minute 등 다른 달력 필드, 격자 밖 마감, 비동기 주기는 기존 정확한 탐색에 남긴다.
비교 상한이 작은 카운터는 실제 정수로 유지한다. 이 선택은 성능 선택일 뿐,
해당 값이 유한하다는 가정으로 상태를 합치지는 않는다.

## 죽은 읽기와 지역값

IR의 plain Clock READ 중 어떤 조건/인자에서도 전혀 참조하지 않는 지역
변수만 제외한다. 예약 이름과 타이머 이름은 제외 대상이 아니다. 원래 READ는
실행하되 그 결과를 후속 관계에서 지운다. 이름 `_noop`에 의존하지 않는다.
프로그램이 내부 타이머 레지스터를 직접 참조하면 새 경로를 거절한다.

JoI 회차 완료 경계에서는 기존 `entry_live` 고정점 분석을 사용한다. 이후
모든 경로에서 읽기 전에 덮어쓰는 일반 지역값만 지운다. 선택한 카운터는
지우지 않는다. 중단된 continuation에 이 규칙을 적용하지 않는다.

## 상태 의미

정확한 제어 위치·일반 저장소·edge/종료 플래그와 정수 DBM을 함께 저장한다.
DBM은 `x_i - x_j <= c` 관계의 교집합이고 `x_0=0`이다. 카운터 좌표는 원래
정수 값, 내부 타이머 좌표는 `(현재 ms - 저장된 시작/기한 ms)/Δ`이다.
미래 기한이면 음수다. 정수 격자 전제에서 모두 정수다. 타이머의 활성 여부는
별도 상태 모양으로 보존한다. 예를 들어 IR timeout 나이 a와 JoI ticks k의
`a-k=0`을 보존하여 두 값을 독립적인 ‘마감 전’ 표식으로 바꾸지 않는다.

일반 저장소는 기존 `freeze_state`로 타입과 값을 보존한다. 후속 반응은
항상 다음 입력 격자라서 모든 최신 입력을 펼치며 held input은 키에 필요하지
않다. 과거 입력 snapshot은 일반 저장소에 남으므로 그것까지 잊지는 않는다.

## 초기 포함과 반응 포괄 — B0, B1

모든 입력 조합에서 빈 저장소의 첫 반응을 실행한다. 시계가 없는 경우
t₀를 0으로 옮겨도 ACTION과 상태 관계가 같다. 시계가 있으면 아래 포괄
규칙으로 별도 처리한다. 구체 반례에는 원래
t₀를 사용한다. 후속에서는 이전 시각을 0으로 옮기고 타이머를 정확한 유리수
`-xΔ/1000`초로 복원한 뒤 원래 실행기를 Δ ms에서 실행한다. 생성/예약은
기존 Fraction 연산을 사용한다. `round(reg*1000)`은 모든 정수 좌표에서
정수임이 확인된 식에서만 허용한다. 임의의 분수 반올림은 거절한다.

기호 연산은 정확한 일차식이다. 비교는 정수 차이 제약으로만 수용한다.
`x-y < c`는 `x-y <= ceil(c)-1`, `x-y <= c`는 `x-y <= floor(c)`이다.
부정과 등호의 부정도 빠짐없이 분기한다. DBM 최단 경로 폐쇄에서 음수
대각이 나오면 그 분기만 비어 있다고 판단한다. 분기 제약을 추가한 뒤
반응을 처음부터 다시 실행하므로 양쪽이 같은 좌표 관계를 공유한다.

각 분기의 원래 ACTION 관찰 정규형을 비교한다. 기호 타이머 값이 ACTION에
유입되면 거절하므로 이 비교는 구체 값의 비교다. 지원하지 않는 식·값·실행
오류를 인증하지 않는다. 후속 좌표가 `x'=y+c` 또는 정수 상수일 때만
투영한다. 폐쇄된 입력 DBM에서 새 bound는 `D[y_i,y_j]+c_i-c_j`이다.
이는 해당 평행 대입과 불필요 좌표 제거의 정확한 DBM image다.

## 확대와 병합 — L4, B2

같은 일반 저장소/제어 상태에서 이전 DBM이 새 DBM을 포함하면 그대로 둔다.
그렇지 않은 bound는 새 bound 이상의 다음 비교 경계로 늘리고, 남은 경계가
없으면 +∞로 늘린다. 경계는 프로그램 상수/타이머 길이와 ±1 인근에서 얻는다.
항상 두 입력 집합을 모두 포함하도록 늘리므로 경계 선택은 정확성 가정이
아니라 성능 선택이다. 불변인 쌍별 차이 관계는 남는다. 확대 행렬 자체는
폐쇄하지 않고 실행 때 복사본을 폐쇄한다. 이는 폐쇄가 불안정한 bound를
반복해서 되살리는 문제를 막는다.

**합친 구체 상태들이 같은 미래를 가진다고 주장하지 않는다.** DBM은 실제
도달 집합보다 넓을 수 있다. 대신 집합의 모든 상태에서 양쪽 ACTION이 같고
모든 후속이 다음 집합에 포함됨을 다시 검사한다. 이 전방 포괄 관계가 기존
L4의 정확한 키 동치 대신 요구되는 의무다. 남은 시간이 다른 상태를 합친 뒤
한 구체 대표만 실행하는 방법에는 이 논증이 적용되지 않는다.

모든 의미 있는 마감과 허용한 시계 경계는 격자에 있으므로 격자
사이에 추가 ACTION이 없다. 입력과 마감이 동시에 오면 원래 실행기가 새
입력을 먼저 읽는다. 성공 조건/timeout의 순서도 기존 IR 실행기의 순서다.

## 완료와 반례 — B3

새 노드 또는 확대된 노드를 큐에 넣어 모든 입력을 재검사한다. 현재 처리
중인 노드가 확대되어도 다시 큐에 넣는다. 큐가 비면 초기 포함, 최종 DBM의
모든 후속 포함, 각 반응의 관찰 일치가 성립한다. 이 귀납 불변식으로 임의
허용 입력 이력과 무제한 시간의 ACTION 동등성을 얻는다. 인증서에 최종
상태/행렬, 확대 횟수, 검사한 반응 수를 기록한다.

상태/전이 한도와 30초 증명 시도 한도는 UNKNOWN이다. 추상 불일치 자체는
DIVERGE가 아니다. 그 입력 순서의 동일 입력 구간을 비교 경계 길이로 늘린
후보를 실제 초기 상태에서 매 격자 실행한다. 차이가 나면 기존
`replay_divergence`로 재확인한다. 이 휴리스틱은 도달 가능성 완전 알고리즘이
아니다. 확인할 수 없으면 UNKNOWN이다. 반례 후보 실행은 전체 전이 예산과
90초 시도 한도를 지킨다. 재생 시간과 호출자의 전체 시간 한도는 별도다.
auto는 새 시도가 미결정이면 기존 구체 탐색을 유지한다. 각 경로의 자원
한도는 별도로 적용되며 E2 호출자의 120초 한도가 전체를 제한한다.
명시 horizon 요청에는 새 무제한 인증을 사용하지 않는다.

## Hour와 timestamp snapshot의 전방 포괄

시계 경로는 `1000 % Δ == 0`, `t₀ % Δ == 0`을 요구한다. 실제 초·시각
경계가 모두 격자 위에 있으므로 양쪽 실행기의 격자 밖 관찰을 생략하지 않는다.
Hour는 매 반응에서 양쪽에 같은 0–23 정수를 제공하고 전량 검사한다.
시간 순서상 불가능한 Hour 변화까지 포함하므로 과근사다. 실제 달력 이력은
그 일부이고, 확대된 모든 이력에서 동등하면 실제 이력에서도 동등하다.
불가능한 달력 이력에서만 차이가 나면 인증하지 못할 수 있다.

timestamp 경로의 JoI는 중단 없는 반복 실행이어야 한다. 별칭을 blocking
continuation 너머로 보관하는 경우는 거절한다. `timestamp_analysis.py`는
timestamp의 모든 사용을 검사한다. 현재 시각의
직접 복사, 매 회차 읽기 전 덮어쓰는 현재 시각 별칭, 현재 시각과 snapshot의
차이를 정수 상수와 비교하는 식, snapshot의 null 여부만 허용한다.
초기 `:=` 정수는 실제 t₀에서 해석한다. 이후 상수로 리셋하거나 가공된
시각을 저장하거나 다른 변수/출력에 사용하는 경우는 거절한다.
IR snapshot 목적지의 모든 대입도 Clock.Timestamp READ여야 한다.

snapshot 좌표는 `floor(현재 ms/1000) - 저장된 timestamp`인 정수 초다.
초기 timestamp는 실제 `floor(t₀/1000)`을 사용한다. 이후 이전 timestamp를
0으로 옮기고 snapshot은 `-age`로 복원한다. 다음 timestamp 증가량은
`floor(Δ/1000)`과 `ceil(Δ/1000)`을 모두 검사한다. 실제 소수 초 위상이
정하는 증가량을 반드시 포함하며, 실제로 불가능한 연속 증가 패턴도 허용하는
과근사다. 두 실행기는 동일한 증가량을 공유한다. snapshot copy는 age=0,
보존된 snapshot은 age'=age+증가량이므로 기존 DBM image와 확대 논증을 쓴다.
null과 정수 snapshot의 차이는 별도 저장소 모양으로 보존한다.

## 나머지 카운터의 정확한 몫 상태

`analysis/modular.py`가 JoI 카운터의 모든 대입과 사용을 검사한다.
정수 상수 초기화/리셋과 `n=n±정수상수`만 허용하고 읽기는 양의 정수 k에
대한 `n%k` 조건으로 제한한다. 원값 비교·복사·ACTION/질의 인자 유출은
제외한다. K를 모든 k의 최소공배수로 놓으면 `n≡m (mod K)`가 모든 허용
조건과 갱신을 보존한다. PauseRunner 반응 후 `n%=K`를 적용해도 다음
반응의 조건·ACTION·종료가 같다. IR은 기존의 나머지 카운터 실행을 쓴다.
이 규칙은 무한 증가를 포화시키는 규칙이 아니며 원값이 출력되는 프로그램에는
적용하지 않는다. 이 정규화는 구체 재생에도 사용하므로 별도의 미정규화
인터프리터와 여러 증가/감소 이력을 비교하는 회귀 테스트를 둔다.

## 반례 후보 생성과 실제 시간 재생

`timer_witness.py`의 경계 탐색은 같은 제어 상태에서 입력을 유지할 때의
일차 갱신과 분기 DBM을 사용해 마지막 유효 반복과 그 직전으로 이동한다.
snapshot 경로는 저장 시각+비교 상수 주변을 후보 시각으로 삼는다.
Hour 경로는 추상 입력 순서를 실제 전진하는 달력에 배치한다.
이 후보 검색의 상태 축약·시간 생략은 EQUIV 증명에 사용하지 않는다.
후보 이력에서 인위적인 clock 덮어쓰기를 제거하고 원래 t₀, 실제 clock,
모든 의무 반응을 수행하는 `replay_divergence`가 차이를 확인해야만 DIVERGE다.
후보가 허위이면 버린다. 후보 검색은 불완전하며 전체 E2 예산은 여전히 120초다.

입력 유지 구간을 압축할 때 **입력이 처음 바뀐 시각과 마지막 시각을 모두
보존**한다. 마지막 항목의 dwell만 늘리면 입력 변경 자체를 뒤로 옮길 수 있다.
이전 후보 생성기의 이 문제는 다단계 리셋 반례 회귀로 검사한다.

## 검증

`explorer.tests.test_timer_zones`는 긴 창, 마감 ±1틱, 리셋, 동시 타이머의
관계, 짧은 모든 입력 이력, ACTION/다른 변수로의 유출, 미지원 시계,
격자 밖 마감, 미지 wrapper, 자원 한도를 검사한다. 정답기 구현을 사용하지
않는다. 새 E2 결과와 미해결 사례는 handoff 폴더에 별도로 기록한다.
`explorer.tests.test_timer_extensions`는 나머지 몫의 미정규화 실행 비교,
실제 Hour 경계 반례, 여러 시작 위상의 timestamp 동등성, 기한 ±1/등호
변이, 상수 snapshot 리셋/출력 유출 거절, 구문 부적합 any ACTION을 검사한다.
