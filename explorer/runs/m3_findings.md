# M3 발견 — 정답 307쌍 IR×JoI 나란히 비교 (2026-08-13/14, 최종)

최종 집계: **EQUIV 281 / DIVERGE 25 / joi_block 없음 1** (Unsupported 0).
cron 47·주기형 blocking 23·one-shot 전부 판정. DIVERGE 25는 전수 해부·
분류 완료 — 모두 v1 게이트(경계 이벤트 합성 + tolerance)를 통과해
"정답"으로 캐시된 쌍들이다 → E2(TCB 충실성)의 실물 사례 목록.

## 판정에 쓴 모델 (엔진 설계 결정)

- **cron 쌍(47)**: IR `start_at cron` 문자열 == joi_block.cron을 검사
  (47/47 일치)한 뒤 **공통 앵커 소거** — 한 번의 발화(창) 안 행동만
  나란히 비교. 창 동치 + 같은 발화 시각 ⇒ 전체 동치.
- **주기형의 영구 종료**: JoI 최상위 break = 블록 영구 종료(플랫폼
  의미). v2 interp는 tick마다 새로 돌므로 DoneLatch 겉옷(runner.py)이
  __fin 래치로 고정. IR 쪽 END의 done 래치와 같은 모양.
- **주기형 blocking(23)**: 멈춘 위치를 경로(__path)로 기억하고 그
  자리부터 이어가는 실행기(pause.py). 멈춘 동안 바깥 if는 재검사하지
  않음(플랫폼 실제 실행과 동일). v1 §6.3(wait=tick 중단 후 처음부터,
  delay=가상시계 전진)과 다른 모델이지만, delay가 period의 배수인
  코퍼스에선 발화 시각이 일치.
- **interp와 의미 정렬** (IR 실행기를 JoI 의미에 맞춤):
  clock.time = hour×100+minute 파생(자유 입력 아님) / 결과를 담는
  호출 = 질의(액션 아님; 다른 명령이 그 변수를 읽을 때만 — 생성기가
  speak에도 var를 붙이는 잔재 때문) / 값 삽입 템플릿("...is $X") =
  str 강제·None→"" / 산술 None→0, 0나눗셈→0 (expr.py 규칙) /
  END_ITER는 tick을 소모하지 않음(같은 tick에 TOP 재검사) /
  all()/any() 한정 비교는 grounding 전 그대로의 비교(1대 세계 정확).
- **집합 바인딩(§9.4 지름길)**: 바인딩 값 = JoI 등장 순서의 태그 그룹
  목록. IR op 수 k, 그룹 수 g에서 k==g면 자리별 1:1, k==1<g면 op
  하나를 그룹 전체로 언롤. → C08_032 EQUIV.
  **한계(명시)**: op 이름이 같은 호출들(예: Switch.On 두 번)의 기기
  구분은 자리 순서로만 잇는다 — JoI가 셀렉터를 뒤바꾼 결함은 이
  지름길로는 원리상 못 본다. 실제 게이트는 확인된 바인딩 표가
  출처이므로 생기지 않는 문제 (§9.4).

## DIVERGE 25 분류

### 레퍼런스 IR 결함 (8) → 382 재감사(§5.2) 수정 대상

- **C13_002/004** — "30분마다 sleep↔auto 토글"인데 IR은 양쪽 다 auto.
- **C09_003** — "auto로 켜고 2시간 뒤 sleep"인데 IR은 delay 뒤에도
  auto (같은 '둘 다 같은 모드' 클래스).
- **C13_003** — cycle(10분){열기; delay 10분; 닫기} — 마감 delay가
  없어 닫기와 다음 여는 호출이 같은 시각에 겹침. JoI(주기 케이던스로
  교대)가 의도에 맞음. C13_006/007은 delay 2개라 정상.
- **C14_004** — "10 올리고 100 도달하면 MaxLevel"인데 IR이 올리는
  call을 무조건 먼저 실행 → 110 발화 + 중복.
- **C17_006** — "≥200이면 high, ≤100이면 low"인데 else가 high.
- **C17_008** — IR 태그 `#Grp2` vs JoI `#Group2` — 표기 불일치로 서로
  다른 센서를 읽음 (태그 정규화 결함).
- **C05_003** — "사이렌이 꺼져 있으면"을 IR이 `Siren.SetSirenMode ==
  false`(명령 속성)로 읽음. JoI는 switch 상태를 읽음 — 상태/명령
  혼동 결함.

### 생성 JoI 결함 = v1 생존자 (4)

- **C14_002** — 밝기 -10, 바닥 0 클램프 의도인데 `if (0 < tmp)
  { tmp = 0 }` — 클램프 방향 반전. v1 '경계 없는 산술' 잔여의 실물.
- **C18_010** — "자정에 문 닫고 6시까지 매시 조명 확인"인데 JoI에
  최초 1회 Door.Close가 아예 없음 (IR에는 있음).
- **C01_006** — 채널 -1에 JoI만 [0,10000] 클램프 추가. lowering 계약
  (joi_common.md: IR에 없는 클램프 금지) 위반 — IR이 범위를 표현할지
  재감사에서 결정.
- **C08_029 (의심)** — "위쪽 조명 켜지면 아래쪽 켜기"인데 JoI가
  #Bottom을 읽고 #Bottom을 켬 (자기 참조). 카탈로그 재감사와 함께.

### lowering 시간 어긋남 — 재무장 한 박자 지연 (6)

C08_012/035/036/041, C10_006/007 (D-3 edge 템플릿, triggered 깃발).
한 바퀴(트리거→delay→동작)가 끝난 tick에 IR은 이미 WAIT로 복귀해
관찰을 시작하는데, JoI 깃발 코드는 다음 tick부터 관찰 — 멈춤 중의
릴리즈/재입력을 한 박자 놓친다. 예: C08_012 버튼을 delay 1초 사이에
뗐다 다시 누르면 IR은 새 눌림으로 발화, JoI는 무시. v1은 tolerance로
통과시킴 — 시간 어긋남 클래스의 실물.

### lowering 시간 어긋남 — 회차 한 주기 밀림 (6)

C12_004/005/007/012/013 (phase 패턴), C18_004 (state 토글 패턴).
IR은 트리거 tick에 cycle 첫 회차(또는 회차 안 후속 동작)를 바로
실행하는데, phase/state 내림 코드는 다음 period tick으로 미룬다.
예: C12_004 누수 감지 tick에 IR은 valve close + 즉시 speak, JoI는
1분 뒤부터 speak. C18_004는 5초 delay가 다음 10분 tick의 else로
내려가 사이렌 끄기가 10분+5초 뒤가 됨.

### 비교 미지원 잔여 (1)

- **C15_002** — IR 인자 {Mode:"repeat"} vs JoI ("repeat", 0) — IR
  args dict는 부분 지정, JoI는 카탈로그 전체 서명. 비교하려면 카탈로그
  서명(순서·기본값) 접착 필요 — 382 재감사에서 인자 정규화와 함께.
