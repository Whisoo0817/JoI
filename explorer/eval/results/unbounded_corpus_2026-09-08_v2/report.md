# H 없는 전체 후보 평가 — 2026-09-08 v2

기존 Gemma4 후보388개를 다시 생성하지 않고 H=None으로 평가했다. 무제한 동등 인증187,
재생 불일치95, 미완료2, 지원 거절43, 기존 생성 실패59, 준비 오류2다.
모든 긍정 결과는 H 없이 새로 검사한 결과다. 이전 bounded 인증을 이름만 바꾸지 않았다.

무제한 인증의 경로는 concrete-event-BFS183건, symbolic-value-flow-v1의 종료 인증4건이다.
기존 카운터 관계 경로와 SMT도 H 없이 연결했지만, 이번 corpus의 신규 인증에는 기여하지 않았다.
개발 예제의 카운터/SMT 인증과 corpus 인증을 합산하지 않는다.

## 미완료2건

C15_005와 C18_003은 clock 조건을 읽는 무한 주기 실행이다. 양쪽의 `clock.time>=2400` /
`clock.hour>=24` 조건은 현재 시계 모델에서 성립하지 않지만, 현재 탐색은 이 사실로
clock 의존성을 지우지 않고 절대 시각을 상태에 유지한다.20초 process 상한에서 끝났다.
동등도 불일치도 인증하지 않았다. 다음 개선 후보는 불가능한 clock 조건의 증명된 상수화,
또는 실제 관찰 clock 필드에 대한 주기적 시간 관계다. 일반적으로 하루만 보면 된다고
가정하거나 clock.timestamp/저장된 과거 시간을 삭제하면 안 된다.

## 보존한 실패와 개발 이력

첫 H 없는 v1 전체 평가도 보존했다: 인증187 / 불일치86 / 미완료11 / 거절43 /
생성 실패59 / 준비 오류2. 이후 검토에서 커스텀 래퍼가 내부 delay 중에도 ACTION을
낼 수 있는 합성 사례에서 허위 bounded 인증을 발견했다. 정확히 아는 래퍼3종만
생략하도록 좁혀 수정했다. 실제 준비된285쌍에는 CatalogRunner/DoneLatch만 있고,
탐색은 TerminalRunner를 추가한다. [수정 전/후 재현](../unbounded_wrapper_guard_2026-09-08.json).

v2는 이 수정과, 초기 고정 입력 이력의 지속/edge/timeout 사건 반례 탐색을 포함한다.
v1 미완료11 중9개에서 실제 반례가 확인됐고, 나머지 판정은 동일하다. v1을 독립 반복
실험으로 세지 않는다. 테스트의 상태 개수/마지막 dwell 기대 수정과 unittest 실행 방식
실패도 validation 기록에 남겼다. 최종 근거로 v2 corpus와 v3 validation을 사용한다.

같은 구현자가 수행한 자체 검토이며, 테스트 통과나 corpus 인증 개수가 전체 검증기
구현의 기계 증명/물리 JoI 런타임 적합성 증명을 뜻하지 않는다.
