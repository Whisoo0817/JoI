# SMT 도입 후 기존388건 판정 비교

전체 재검증 v3는 175.86초(약2분56초)에 완료했다. 후보 재생성·과학적 재시도 없이
동일388개 ID를 포함했고 후보 SHA, reference IR, binding, 연결 기기, 서비스 catalog,
입력 계약과 H=3200ms는 직전 v2와 같다. 기존 탐색/프로세스 자원 제한을 유지했고
새 SMT의 질의1초·총10초·10000질의 한도를 실행 전에 명시했다.

## 결과와 회귀 확인

동등208 / 구체 반례 확인 불일치76 / 거절43 / Explorer 미완료0 /
기존 생성 실패59 / 준비 오류2. 최종 판정 변경은 **0/388**이다.
이는 이 후보 집합에서 판정 회귀가 관찰되지 않았다는 의미이며 전체 구현의 무결점
또는 SMT의 전반적 정확성·지원률 향상을 증명하지 않는다.

양쪽 유한 탐색이 완료한267건은 모두 같은 판정이다. 별도 기호 인증4건
(C01_009, C01_014, C01_017, C01_018)은 기존 value-flow 경로다.
exact만 미완료인13건은 이전과 같고 Explorer는 그중12건 동등/1건 불일치다.
기존 generated-code 불일치76건은 모두 ACTION 반례 재생이 확인됐다.

## C01_006: 거절 이유와 단계만 바뀜

IR과 코드 모두 현재 TV 채널에서1을 빼 SetChannel에 전달한다.
현재 채널의 서비스 명세 범위는0..10000이며 SetChannel 인자도0..10000이다.
입력0이면 두 프로그램 모두 SetChannel(-1)을 호출하므로 인자 계약을 위반한다.

- 이전: 준비 단계에서 산술식/지원 조각 검사로 REFUSED.
- 현재: 준비를 통과해 `smt-linear-trace-v1`로 들어가지만,
  `SMT ACTION domain is not universally valid: SetChannel`로 REFUSED.
- 두 프로그램의 trace가 다르다는 DIVERGE 판정이 아니다. 현재 입력 계약 전체에서
  서비스에 유효한 인자를 전달한다는 지원 조건이 충족되지 않는다.

이1건 때문에 manifest READY는284→285, 준비 REFUSED는43→42로 변했다.
실행 REFUSED1건을 더하면 최종 거절43건은 같다. harness NOT_COMPARABLE14건은
exact 미완료13건 + 이 SMT 거절1건이며 Explorer 미완료14건이라는 뜻이 아니다.
exact NOT_APPLICABLE5건도 기호 인증4건 + SMT 거절1건으로 구분한다.

## SMT의 효과와 근거 범위

이번 corpus에서 새 SMT 경로에 진입한 것은 C01_006 하나이며 신규 인증은0건이다.
나머지 산술 관련 거절 사례는 periodic/cycle 등 v1 지원 조건 밖에 남는다.
SMT가 평균·합 조건을 처리한다는 근거는 별도 개발20케이스(인증5/재생 불일치8/
예상 거절7)와 최종223개 회귀 검사다. 이들을388건에 더하거나 held-out으로 부르지 않는다.
최종 회귀 기록과 동결 평가의 교집합 코드/requirements64개 SHA는 모두 같다.
회귀·E1을 이번에 다시 실행한 것은 아니다.

새 결과의 소스/후보 실행 전후 SHA와 ZIP 바이트를 확인했고 자체 감사 구조 검증이
통과했다. 저장소 로컬 연속성이지 실행기 격리·독립 검증은 아니다. 약176초와 이전
약171초의 차이는 단일 실행의 기술적 기록이며 SMT 비용이나 인과적 속도 변화의
추정치로 쓰지 않는다. 초기 SMT 개발의 false-EQUIV2건과 명시적 거절 교정 이력은
최종 v2 개발 근거에 남아 있으며 corpus 판정 일치로 그 이력을 숨기지 않는다.

다음 작업은 정확한 bounded 보장 명제, BFS/상태 병합/입력 이산화/기호 비교/SMT의
증명 근거, 이 평가 결과와 지원 제한을 논문 설명으로 연결하는 것이다.
